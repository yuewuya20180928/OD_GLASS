## ★ 为什么 Rev B 的自检 **不用 "在 STL 上量尺寸"**

Rev A 的 `verify_pack.py` 是在 STL 上量尺寸。本轮实测踩了 **4 个坑** (都记在 `verify_pack_revb.py` 头部):

1. 网格三角形 **绕向不一致** (实测 50/50) ⇒ 用法线符号判进出 ⇒ 全错;
2. 条带法切孔 ⇒ 同一块被切成几十个小盒, **相邻盒共面** ⇒ 奇偶配对 **错位一格**;
3. 射线 **从实体内部出发** ⇒ 命中数奇偶翻转;
4. 探针位置用绝对坐标 vs 射线参数 t **混用** ⇒ 差一个原点偏移。

⇒ Rev B 改成 **两段式**: ① **解析模型精确求尺寸** (生成器同步记录图元表, 不采样不近似)
② **STL 逐点互验** (射线奇偶只判内外, 绕向无关) ⇒ 两边职责分开, 各自都不再有上述坑。

## ⚠️ 口径 (别把模型自检当成实测)

`verify_pack_revb.py` 量的是 **模型/规格层**: 它证明 "Rev B 的数字被正确实体化成几何了, 且 STL 与规格逐点一致"。
它 **不能** 替代 **M-PRINT (实物打印件实测尺寸)** —— 实物还有 FDM 工艺偏差
(孔径收缩 +0.1~0.2 / 层纹 / 收缩率 / PA-CF 吸湿 24h 后尺寸变化)。
⇒ `state/measurements.yaml` 的 **M-PRINT 仍是 [推算]/未测**, 阶段门 G2 不认 (**这是设计意图, 不是 bug**)。
