## B1 结论摘要 (先说结论)

1. ★ **hw-lead 的指摘成立, 旧表整表作废**。旧算法 `半对角 50° − 俯角 − 余量 10° → 可接受最大偏置 ≤40°` 混了**三个**错误:
   - **错误① (主错)**: 拿**对角半角**判**垂直俯角**。垂直俯角只能由**垂直半视场**决定 —— 16:9 理想靶面、对角 100°、直行口径下垂直半视场只有 **30.30°** (本脚本复现, 与 hw-lead 的 30.3° 一致) ⇒ 旧结论 40° **高估 9.70°**。
   - **错误②**: 把**垂直俯角**和**水平偏置**放同一列比。垂直俯角 → 垂直半视场; 水平偏置 → 水平半视场。**两个物理量不可互换**。
   - **错误③**: 「对角 FOV」**没带投影模型**。同一「对角 120°」, 直行 (`r=f·tanθ`) 垂直半视场 40.45°, 等距/鱼眼 (`r=f·θ`) 只有 29.53° —— **差 10.9°**。不带模型引用 FOV = 无效引用。
2. ★★ **基线已变, 旧表必须整表重算**: 老板 **2026-11-02 09:41 拍板「使用D」** ⇒ sensor = **onsemi AR0234CS 1920×1200@60 整幅不裁剪** (`PROJECT_TRACKER.md` §(1.56)); 老板 10-25「禁止 ROI/crop」⇒ **不做 1080p 裁切**。
   ⇒ **现行定案: AR0234CS 整幅 + 等距(鱼眼) + 对角 120° ⇒ 垂直半视场 31.80°, 水平半视场 50.88°** (f=3.2432mm, 与 SW `fov_scale_check.py` 及 hw-lead 分片 `sensor_lens_focal_equidistant` 三方一致)。
3. ★★ **结构侧结论 (本单真正的价值)**: 现行定案下 **俯角 25° 基线站得住, 而且比旧基线宽裕**:
   - 垂直半视场 31.80° (旧 OV04C10 基线 29.53°) ⇒ **+2.27°**;
   - 俯角 25° 名义余量 **+6.80°** (旧基线 +4.53°) ⇒ **多 2.27°**;
   - 扣掉边框遮挡 1.91° 后**有效余量 +4.89°** ⇒ **≥ 判据 4° ✅**;
   - ⇒ **`h_max` (摄像头光轴中心高于用户视线) = 13.99 / 14.92 / 16.32 mm (d=30/32/35)** —— 与 10-29 那版一致, 但**现在有了新的、更硬的理由** (不是"OV04C10 恰好卡在 25°", 而是"AR0234CS 给了 2.27° 富余, 25° 是有余量的设计点不是临界点")。
4. ★ **旧「俯角 20-32° 不可回避」彻底作废**: 现行定案俯角 **32° 时名义余量 −0.20° ⇒ 正前方掉出画面**。且 **30° 也不安全**: 名义 +1.80° 但扣边框遮挡后 **−0.11° ⇒ 正前方被镜框上沿遮掉** (旧表根本没算遮挡这一项)。
5. ★★ **新发现 (旧表没有)**: **边框遮挡吃的是"正前方那一侧"**。摄像头装镜框上沿、光轴朝下俯, 正前方对应画面**上半部**, 而镜框上沿正好挡住上半部 ⇒ 前顶点凹进量直接吃掉"正前方在画面内"的余量。**凹进 1.0mm = 1.91°**。所以判据必须用**有效余量** (名义余量 − 遮挡角), 不能只看名义余量。
6. ★★ **零余量位置镜框上沿做不到**: 硬上限 (有效余量 = 0) 29.89° ⇒ `h_max(d=35) = 20.12mm`, **比 MECH 原上界 20mm 还高 0.12mm** ⇒ 任何设计点都必须留余量, 判据 B' (有效余量 ≥ 4°) 给出 16.99mm 是能做到的。
7. ⚠️ **口径选择仍未决 (PM 一句话)**: 俯角上限取**名义余量 ≥ 4°** (⇒ ≤27.80°) 还是**有效余量 ≥ 4°** (⇒ ≤25.89°)? 差 1.91° ⇒ 差 `h_max` 1.47mm (d=35: 18.45 vs 16.99mm)。**我的建议: 取有效余量 ≥ 4° (B')**, 理由 = 遮挡是实物必然 (凹进 0 也要占窗口座沉孔 0.35mm), 名义余量留不住。
8. ✅ **可以不等镜头定档就开模** —— 三档 (100/110/120°) 的镜筒/窗口/高度需求只差 ≤0.9mm (ISS-052 结论不变), 结构侧按 `MECH/CAMERA_WINDOW_SPEC.md` §B2/§B4 的预留值开孔即可。

## B2 ★ 复核: hw-lead 的指摘逐条核对

### B2.1 核心数复现 (16:9 对角 100° → 垂直半视场 30.30°)

推导 (直行口径, 16:9 理想比例, 靶面长边归一化 16、短边 9):
```
对角 d = √(16² + 9²) = 18.3576
f = (d/2) / tan(50°) = 9.1788 / 1.19175 = 7.7019
垂直半视场 = atan( (9/2) / f ) = atan( 4.5 / 7.7019 ) = atan(0.58426) = 30.30°  ✅
水平半视场 = atan( (16/2) / f ) = atan( 8 / 7.7019 ) = 46.09°
```
⇒ **hw-lead 的 30.3° 完全正确** `[推算]`。旧表的 50° (半对角) 与真实的 30.30° (垂直半视场) 差 **19.70°**。

### B2.2 旧表错在哪 —— 三个错, 不是一个

| # | 旧表做法 | 为什么错 | 正确做法 |
|---|---|---|---|
| **①** | `半对角 50° − 俯角 − 余量 10°` ⇒ 可接受最大偏置 ≤40° | **垂直俯角由垂直半视场决定, 与对角半角无关**。垂直半视场只是对角半视场的 ~60% (16:9) | `俯角上限 = 垂直半视场 − 判据余量` |
| **②** | 垂直俯角与水平偏置同列 | 两者由**不同的量**决定: 垂直俯角 → 垂直半视场; 水平偏置 → 水平半视场 | 分成两列, 各自独立判 |
| **③** | 「对角 120°」不带投影模型 | 直行 vs 等距同一对角 FOV, 垂直半视场差 10.9° | FOV 数必须写成 `投影模型 + 读出窗口 + 对角 FOV` 三元组 |

### B2.3 旧表真值对照 (改表前 / 改表后)

| 项 | 旧表 (MECH §1.5 原表) | 复核后 (本文件) |
|---|---|---|
| 判据式 | `半对角 50° − 俯角 − 10°` | `垂直半视场 − 判据余量` |
| 可接受最大偏置 | **≤40°** (16:9 对角 100°) | **≤30.30°** (判据 A, 零余量) / **≤26.30°** (判据 B, 4° 余量) —— 16:9 对角 100° 直行口径 |
| 俯角 20-32° | 「不可回避」 | **32° 掉出画面 / 30° 被边框遮掉** ⇒ 收窄到 **≤25°** (现行定案 + 有效余量判据) |
| 投影模型 | 未标 | **必须标** (直行 / 等距) |
| 边框遮挡 | 未算 | **1.91° (凹进 1.0mm @ d=30), 吃正前方那一侧** |

> - 读出窗口决定靶面尺寸; **镜头按该窗口的对角线**设计到目标对角 FOV;

|---|---|---|---|
| 垂直半视场 | 29.53° | **31.80°** | **+2.27°** |
| 俯角 25° 名义余量 | +4.53° | **+6.80°** | **+2.27°** |
| 俯角 25° 有效余量 (扣 1.91° 遮挡) | +2.62° ⚠️临界 | **+4.89°** ✅ | **+2.27°** |
| 判据 B' 允许的俯角上限 | ≤23.62° | **≤25.89°** | **+2.27°** |
| `h_max` @25° (d=35) | 16.32 | **16.32** | 0 (基线不变) |
| 硬上限 (零余量) 时 `h_max` (d=35) | 18.31 | **20.12** | +1.81 |

⇒ ★ **结论: 换 sensor 不改结构基线 (h_max 仍是 16.32mm @d=35), 但把「25° 是临界点」变成「25° 是有余量的设计点」** ⇒ 镜框上沿的造型自由度变大 (可以谈更矮的上沿/更好的外观), 判据口径之争 (B vs C) 也不再卡结构。
