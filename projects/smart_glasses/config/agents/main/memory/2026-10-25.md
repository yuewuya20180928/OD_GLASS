### ⭐ 通信拓扑: 星型 (老板 10-25 明确要求)
> "2.硬件总工、3.软件总工、4.结构总工之间**不做直接沟通**, 由总工对接我的需求和命令拆分给各个模块"

**技术落地**:
| 通道 | 允许 | 实现 |
|---|---|---|
| 项目总工 → 三总工 | ✅ | `sessions_spawn(agentId=...)` |
| 三总工 → 项目总工 | ✅ | 交接单落盘 + spawn 完成回执自动推回 |
| **三总工 ↔ 三总工** | ❌ **禁止** | per-agent `tools.deny: ["sessions_send"]` → **配置层硬性禁掉, 发不出去** |
| 三总工 spawn 别的总工 (借道) | ❌ | per-agent `subagents.allowAgents = [自己]` |
| 三总工 **读** 别人产出区 | ✅ | 共享项目库互相可读 |

**⚠️ 关键区分 (落地时必须守住)**: 堵死的是**"对话"**不是**"信息"**。如果连"读"也堵死 → 硬件画完 PCB 尺寸结构总工看不到, 结构画完外形硬件总工看不到, 三总工各写各的, 项目总工变成人肉路由器, 传话必然失真。→ **横向信息流走文件 (共享产出区), 不走会话**。

**配套 (必须有, 否则框架空转)**:
1. `INTERFACES.md` 跨模块接口契约表 (硬件↔软件↔结构) —— 提前书面固化, 不能靠对话拉齐
2. 同一份需求文档同时下发三方 (`REQ/REQUIREMENTS.md`) —— 避免口头转述失真
3. 跨模块评审由项目总工组织: 收集 → 转交 → 收意见 → 裁决 → 落盘
4. 收口时必须做**跨模块接口一致性检查** —— 否则会出现"三总工各写各的, 没人发现接口对不上"

**可行性判断**: ✅ 可行, 且与项目当前阶段 (P0 拿资料 / P1 选型, 跨模块实时联调还没开始) 匹配 —— 串行中转的延迟现在不痛。
**代价**: ① 项目总工成瓶颈 (注意力单线程, 建议分批收口而不是三线齐推) ② 跨模块确认多一跳 (缓解: 项目总工**同时**把同一份需求发给两方, 而不是串行转述) ③ 单点故障 (缓解: 跟踪表/决策日志/交接单全落盘, 三总工角色文件独立完整, 可随时恢复) ④ 冲突裁决全压项目总工 → 必须有技术判断力, 不能只会传话。

### 关键配置 (踩过的坑)
1. `openclaw agents add <id> --workspace <dir> --model <id> --non-interactive` → 自动建 workspace + agentDir + sessions 目录, 写进 openclaw.json
2. **`tools.agentToAgent` 是 strict schema, 只有 `enabled` + `allow` 两个键** —— 我第一次加了 `maxPingPongTurns` → `Config is invalid: tools.agentToAgent: Invalid input`。那个键在 `session.agentToAgent` 下, 不是 tools 下
3. **`sessions_spawn` 跨 agent 要显式开 allowlist**: 默认只允许 spawn 自己 → 报 `agentId is not allowed for sessions_spawn (allowed: main)`。修法:
   - `agents.defaults.subagents.allowAgents = ["main","hw-lead","sw-lead","mech-lead"]`
   - `agents.list[].subagents.allowAgents` 同样 (per-agent 覆盖)
4. `tools.sessions.visibility = "all"` → 让 agent 能 sessions_list/send 到别的 agent 的 session
5. `tools.agentToAgent.allow = ["main","hw-lead","sw-lead","mech-lead"]` → 跨 agent 消息放行

### 结论: 通信通道干净, 但共享状态源会"说谎"
- ✅ **零串味** (canary 归属 100% 正确, 双向)  ✅ **零误闭合** (600+ 条压力需求, 0 条被错标 answered, 第三方代答全进 foreign_answers)  ✅ 冲突检测 0 误报 0 漏报
- 🔴 **绝对路径绕守卫 → 消息真投递** (sw-lead→hw-lead / mech-lead→sw-lead, 对方会话里能看到原文, 对方 assistant 都开始回应了) → **守卫下沉到 CLI 入口封掉**
- 🔴 **分片非原子写 → 整个 agent 域从快照里静默蒸发** (12%~38% 的合并发生, 快照还打 ✅) → 别的 agent 会据此误判"某总工没待办"
- 🔴 并发 merge 互踩固定名 tmp → 7.5% 概率 rc=1 崩溃, 快照静默过期
- 🟠 已闭合需求会因对方分片被跳过**翻回 pending** → 重复催办
