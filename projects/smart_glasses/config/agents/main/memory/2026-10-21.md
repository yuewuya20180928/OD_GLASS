## 这 7 条决策的连带影响 (我推算, 未实测, 需原厂/实测确认)

### 1. DDR 512MB 定稿 → 老文档的 1GB 硬指标作废
- `PROJECT_REQUIREMENTS.md` 里"1GB (硬规格)" **已过期**
- `CHIP_SELECTION.md` 里"ARS45 + 外挂 512MB LPDDR4x 凑 1GB" **10-20 已证伪** (FCCSP 无 DDR 引脚, 不能外挂), 现在又确认 512MB 就够 → 该条彻底废
- 512MB 内存规划必须一开始定死 (Linux + ISP buffer + NPU io + 显示双缓冲)

### 2. DP→MIPI-DSI 桥 = 新增硬件模块 (之前完全没考虑)
- 之前数据流 (老板 19:37) 写的是 "MIPI-DSI", 但 `CHIP_SELECTION.md` 公开资料写 ARS45 显示是 **DP1.4 RX 独立 Scaler**
- 老板决定: 光机只能吃 DSI → **中间必须加桥接芯片**
- **新增风险**: 桥接芯片 (Analogix ANX7625 / Parade TC358870 / ITE IT6505 之类) 的体积/功耗/延迟/国内可得性全是未知
- **bridge 延迟会吃掉 60ms 预算的一部分**, 必须列入 latency budget

### 3. 续航 1h → 整机功耗预算硬约束
- 公开的 ARS45 "1080p@30fps 录像 < 300mW" 是**空载 SoC 且 30fps**
- 本项目是 **1080p@60 + ISP + OD 持续跑 + DP 桥 + 双目光机** → 整机功耗必然远高于 300mW
- **我推算** (未实测, 不做决策依据): 整机大概率 1-1.5W 档, 1h 续航对应电池 400-500mAh 起
- **必须确认**: 老板能接受多大的电池塞进镜脚? 续航 1h 是在 "OD 持续跑" 状态还是 "OD 按需触发" 状态?

### 4. 只出 1 台样机 → 不是量产打板, 是单板验证
- 不需要走"多轮改板 + 认证"流程, 可以 **一次投板 + 软件迭代**
- 打板成本可以压 (单面/少层/嘉立创)
- 但也意味着 **没有第二轮硬件修改机会**, 原理图一次过

### 5. 不上无线 → 简化一大块
- 省掉: WiFi/BT 芯片、射频天线、SRRC 认证、天线净空、结构避让
- **但要确认**: 完全不联网的话, 模型/配置怎么更新? 只能靠 Type-C ADB 手动 push? 这对后续维护是不是问题?

### 6. < 60ms 硬指标 → latency budget 必须逐段拆
- 上一项目从未验证过端到端 latency (只验证过 fps)
- 眼镜场景对延迟敏感, 60ms 是硬指标意味着每个环节都要有数
- **待确认**: 60ms 从哪算到哪? 摄像头曝光 → 光机出光? 还是 ISP 输出 → DSI 输出?

### 7. 建整体跟踪表 + 删过期 → 文档重构

## 我今天算的 latency budget (粗算, **未实测, 仅供讨论, 不作为决策依据**)

假设 "sensor 曝光完成 → 光机出光" 口径:

| 环节 | 粗估 |
|---|---|
| sensor 出图 | ~20-30ms (1080p@60 一帧曝光周期内) |
| ISP (AE/AWB/降噪) | ~10-20ms (pipeline 深度不确定) |
| 缩放 1080p→640x480 | ~2-5ms |
| OD 推理 (yolov5s INT8) | ~8-14ms (**推算, 完全没实测数据**) |
| 后处理 (decode+NMS) | ~2-5ms |
| DP→DSI 桥转发 | ~5-15ms (**未知, 取决于桥芯片**) |
| 光机 scanout + 衍射波导 | ~5-15ms (**未知, 取决于光机**) |
| **合计** | **~52-109ms** |

**结论 (我的粗算)**: **60ms 硬指标在这个配置下大概率达不到, 中位数都到 52ms 了, 悲观值超一倍**
- 但这个估算本身粗糙 (每段都是拍的), **不能当结论**
- **第一个必须从酷芯微拿的硬数据: OD 推理 latency + ISP pipeline 各级 latency + DP TX latency**
- 如果实测 OD 只要 5ms, ISP 做浅 pipeline (关 3A/关降噪), 可能压回 60ms

### ⚠️ 我要修正的两个自己错误
1. **错**: 以为 ARS45 只有 DP 输出 → **对**: DP1.4 RX 和 DSI TX 是**并存的独立接口**。我只看到"DP1.4 RX"就以为没 DSI
2. **错**: yolov5s 延迟估 8-14ms → **修正为 15-20ms** (RK3588/RK3576 官方 model_zoo 都是 15ms 级别, 我之前估乐观了)

### 📊 NPU 横向数据 (Rockchip 官方 model_zoo, yolov5s INT8 @640×640)
```
RK3588 (6 TOPS, 单核)  66.1 fps = 15.1ms
RK3576 (6 TOPS, 单核)  65.0 fps = 15.4ms
RK3566 (1 TOPS)         25.5 fps = 39.2ms
RV1126 (~3 TOPS)        29.2 fps = 34.2ms
```
独立验证: PhotonVision 在 RK3588 实测 15.03ms, 与 model_zoo 15.1ms 几乎一致

**关键规律**: 三家 6 TOPS 芯片跑 YOLO 实际利用率只有 **15-20%** (标称 6 TOPS → 实际约 1.1 TOPS)
**别用标称 TOPS 推延迟**

| 参数 | AR9481 (备选) | ARS45 (首选) |
|---|---|---|
