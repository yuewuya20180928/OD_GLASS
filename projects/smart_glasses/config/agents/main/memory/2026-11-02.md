## ★★ 本夜抓到的 4 个缺陷 (都不是想出来的, 是跑出来的)

1. **真缺陷 · 网表**: P1 页 `TS_BAT` 那行把 RT1 的 TS 端写成 **`U_CHG pin22` (=REGN)** 而不是 pin11 (=TS) ⇒ **REGN 被短到电池 NTC 节点 ⇒ 充电链失效**。★**逃过全部 36 条门禁** —— 因为 `.net` 生成器会按连通性重排引脚, **.net 一直是对的, 错的只有 CSV** (而 CSV 正是 PCB 工程师照着接线的那份)。⇒ 修复 + 收紧 `check_bq25896_pinout.py` 的 REGN 允许网集合。
2. **结构缺陷 · CSV**: **274/470 行的引脚号是"隐式"的** (只写裸位号, 靠出现顺序推), 只有 96 行写了显式 pin ⇒ **隐式 + 手写显式混用 ⇒ 笔误能长期潜伏** ⇒ 新增 `state/gen_netlist_pins.py` ⇒ **真 pin-centric 表 `HW/netlist_v1_pins.csv` (550 行 = 每引脚一行, 220 器件)** + 5 类交叉校验 + 复用 pinout 真源当别名白名单 (**ISS-094 收口**)。
3. **门禁缺陷**: `HW/check_bq25896_pinout.py` **一直 exit 1 (⑤⑥⑦ FAIL) 却不在 `gate_check.py` 链里 ⇒ 没人发现** ⇒ ⑤⑥ 的规则**与它自己的 PINMAP 自相矛盾** (设计意图就是双名节点) ⇒ ⑦ 的规格快照过期 (V1.8 把 TS_BAT 从 pin5 挪到 pin8) ⇒ 三条判据修好 ⇒ **24/24 全绿** (新开 ISS-136 接门禁链)。
4. **★自己引入的回归**: 改占位名时 `gen_kicad_net.py` 里**硬编码的正则没跟着改** ⇒ **SoC 的 56 个引脚整条从 .net 消失** (550→494 行) ⇒ **所有原有门禁都没报** (只查"冲突", 查不到"整条不见了") ⇒ 修法: 正则泛化 + ★**加结构回归门禁** (`.net` 必须有 SoC 占位器件且引脚 ≥50) ⇒ **已做反向验证** (故意改坏 ⇒ 立刻抓到)。⇒ ★**方法论: "全局字符串改名"必须配一条结构回归检查**。
