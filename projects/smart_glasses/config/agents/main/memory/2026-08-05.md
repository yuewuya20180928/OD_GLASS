- ✅ nbinfo 验证 INT8 output (8.5MB → 2.1MB, 4x 省)
- ✅ 推到板端 /etc/npu/yolov5/model/yolov5.nb

### 失败根因
- ACUITY 6.30.22 (2025-01) 生成的 .nb 用 v2.0.10.x NPU driver ABI
- 板端 NPU driver 是 VIPLite 2.0.3.2-AW-2024-08-30 (老)
- vpm_run + awnn_create 报 `nbglk_valid_nbg_check[946], fail core0 vip sram size=0x8c8a82ac, actually size=0x80000`
  - 0x8c8a82ac 是 NBG 内部期望的 vip sram 字节数 (解析出乱码)
  - hardware 只有 0x80000 = 512KB
- 试 --optimize v2 没改变 (v2/v3 只是 pipeline 优化级别, 不改 target 字节)
- hexedit 改 NBG 头 byte 8 target 0x20 -> 0x3B (0x10000020 -> 0x1000003B), 进一步报 SRAM size

### 推断
- **ACUITY 6.30.22 toolchain output 跟 driver 2.0.3.2 ABI 不匹配**
- 需要换 board NPU driver 到 v2.0.10.x 配套 (这条路 7-10 踩过 kernel ABI 不一致)
- 或: 用 Allwinner awnpu_model_zoo 旧版 ACUITY 6.18.x toolchain 重新生成 (但 8-03 调研的 tarball 404)
