## 23:36-23:50 — v25 dual_ctx 实测 ❌ DEAD-END

### 现象
- 启动正常: 4 thread ready, npu-0/npu-1 都拿到 dual_handle
- 前 6 帧 inference OK (npu_ms 94-133ms 单次, 比 v24 单 ctx 27ms 慢 4x)
- **第 7 帧起 stall**: npu-0/npu-1 卡在 `awnn_run_dual_npu` 不返回
- 4 thread 全活 (etime 1:33) 但 throughput=0
- dmesg 无 NPU driver panic/err → 不是 driver 异常退出

### 根因 (铁律: 看数据)
- **VIPLite NPU 硬件是 single task queue** (vip_run_network 同一时刻只能跑 1 个 task)
- user-space mutex 拆开只解表层, **driver 内核模块内部还有锁**
- 双 ctx 第 7 次起 driver 内部 mutex 排队死锁
- 单 ctx npu_ms=27ms; 双 ctx 单次=94-133ms (driver 内串行 + ctx 切换开销)

### 结论
- **v25 dual_ctx 不可行**, VIPLite 硬件层不支持
- **不要再去试双 ctx** — 7 次连续 stall 是确定结论
- 把 v25 + dual .so 都封存进 memory/2026-08-05 + libod_helper.so.v_with_dualctx_20260805_154100.bak
