## 23:36 — 真根因 (Radxa 官方论坛验证)

forum `https://forum.radxa.com/t/a7a-radxaos-boot-failed/30486.json`:

> 用户 ChiiAya 报告 A7A 烧 R2 (512) **boot log 一模一样** (我们 R6 512 同款)
>
> 5/7 jack_young 回复: 命令 `part list mmc 0; ext4ls mmc 0:3 /boot; sysboot mmc 0:3 any ${scriptaddr} /boot/extlinux/extlinux.conf`
>
> 5/17 ChiiAya accepted answer: **编 U-Boot 删 `CONFIG_UFS=y`, 重烧** 解决了 (用 FEL mode + LiveSuit/PhoenixSuit)
>
> 真根因: A7A 默认 U-Boot 编了 `CONFIG_UFS=y`，板子没 UFS module → UFS probe 反复 fail (`err:link startup failed -6` ×7) → bootcmd 进异常 → `expected 8 cells got 4`

**R6 镜像本身 OK** (rootfs/extlinux.conf/vmlinuz/dtb 全在), 是 **板子 SPI U-Boot 的 bootcmd 在 UFS probe 卡死**, 没空间跑到默认 bootcmd 完整路径 (sysboot/extlinux.conf auto-detect)。

## 23:58 — 老板准备重刷固件

老板问: 是否能用 A7A R6 (KDE/CLI) 镜像?
**答**: 不行。所有 A7A/A7S/A7Z R 系列 (R2/R6 × CLI/KDE × SD/UFS) 都有同一 CONFIG_UFS bug。换镜像不解决问题。

### 我推荐的修法顺序

#### B1 (一劳永逸) - FEL mode 重编 SPI U-Boot 烧 SPI NOR
- git clone `https://github.com/radxa-pkg/u-boot-aw2501.git`
- vim src/configs/radxa-cubie-a7s_defconfig → 注释掉 `CONFIG_UFS=y`
- aarch64-linux-gnu- toolchain 编译
- 用 sunxi-fel 烧到 SPI NOR
- 然后 SD 卡 boot auto-work

#### C (中) - 烧 R6 4096 (.img 输出_4096) 用 balena etcher (densify sparse)
- R6 4096 设计有 bootloader/boot-resource/env/rootfs 4 partition (跟 SPI U-Boot 命名匹配)
- balena etcher 处理 sparse image 不会损坏
- 7/11 R2 烧失败是因为 dd 没 densify, balena etcher 会
- ⚠️ 风险: bootloader/boot-resource 内容未知 (R6 512 知道 boot-resource 全 0)

#### B0 (最简单) - 把 SD 卡镜像加 boot-resource partition
- 改 R6 512 .img 的 GPT, 末尾加一个 32MB boot-resource partition
- 把现有 boot.scr 写进 (or 用 mkimage)
- dd 烧 SD 卡后 boot-resource 能找到 → sysboot 启 → kernel
- 但 U-Boot bootcmd 因为 CONFIG_UFS=y 仍然死循环 → 不work 同样的路

#### D (回退) - 烧回 R6 512 + 进 SPI console (需要先 fix 板子 boot)
- 让板子上电 + 串口能看到 SPL/BL31 log
- 在 U-Boot console 执行 `setenv bootcmd 'sysboot mmc 0:3 ...'` + `saveenv`
- 但 ChiiAya 报告 saveenv `Failed (-19)` — SPI env area 可能损坏

## 教训

- **不要凭 log 字面意思推断根因** — "boot-resource not found" 不等于镜像布局错; U-Boot bootcmd 才真错
- **遇到坑先搜官方论坛** — forum.radxa.com 7/9 就有 A7A 用户报告同问题
- **看到 "Model: A7A" 不立刻判断镜像错** — 可能是 SPL 里 dtb 错的 cosmetic 问题
- **SD card reader 状态要 daily confirm** — `/dev/sda` 没出现 = 烧录操作没准备好
- **空间紧张时大镜像先 push 到别处** — trixie 6GB 现在没了
