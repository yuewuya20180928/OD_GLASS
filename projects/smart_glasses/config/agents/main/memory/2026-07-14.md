## Vivante SDK 文档重点
- A733 = Vivante **VIP9000** 系列 NPU
- 两个 driver 栈:
  - **Unified Driver** (OpenVX/OpenCL, tens of MB, Android/Linux, 支持 JIT)
  - **VIPLite Driver** (轻量, tens of KB, 也支持 RTOS, **不支持 JIT**, **只支持 NBG 预编译**)
- 我们用的是 VIPLite driver (在 /dev/vipcore, NBG 格式)
- ACUITY Toolkit = 离线转换 (ONNX/TF/PyTorch → NBG) + 量化 (UINT8/INT16/BF16/PCQ)
- TIM-VX = VeriSilicon 开源 runtime 接口 (https://github.com/VeriSilicon/TIM-VX)

## 7/14 分析后修正铁律
- **【修正铁律】vpm_run binary 也要替换,不能只换 .so**
  - apt 装的 vpm_run 跟 apt 装的 libVIPhal.so 配套
  - awnpu_model_zoo 提供的 libVIPhal.so 要配 awnpu_model_zoo 源码编译的 vpm_run
  - 7/12 hang 的真正原因可能就是 vpm_run binary 没换
  - 修法: 板端用 apt 装 cmake + gcc + aarch64 工具链,跑 awnpu_model_zoo 的 build_linux.sh
  - 或者 PC 端 cross-compile,产物 scp 到板端

  - https://dl.radxa.com/cubie/allwinner-model-zoo.tar.gz
  - 我们硬盘上 208MB 那个就是
- **【新认知】cubie-image 仓库提供 5.15 kernel**
  - sun60iw2p1 仓库有 6 个 5.15 版本
  - 跟 a733-bullseye 仓库的 -21 是不同包

## 23:45 — 重大实测进展

### SSH 恢复 + 板子状态确认 (实测)
- 192.168.71.15:22 通,密码 radxa/radxa (sshpass)
- kernel 6.6.98-1-aw2511 (Oct 2025 build,无变化)
- uptime 1 min (老板刚 reboot 完)
- /dev/vipcore 存在 (199,0)
- 当前 /usr/lib/libVIPhal.so md5 = `749bde6f...` (跟 backup.apt-may2025 一致 = May 2025 apt 版)
- vpm_run 是 **Sep 26 2025 build** (npu-runtime 2.0.3 包内,86000 bytes)
- vpm_run RPATH 写死到 /lib (LD_LIBRARY_PATH 不生效)
- awnpu_model_zoo 没 scp 到板子,只有散落的 .so + .nb + sample.txt + 输入文件
- cmake / g++ / linux-libc-dev 没装

### 路径 B 实测 (compile vpm_run + replace .so)
1. scp awnpu_model_zoo functions/vpm_run + common/npuruntime + cmake_toolchain → OK
2. 装 cmake 3.31.6 + g++ 14.2.0 → OK
3. 编译 vpm_run:
   - 缺 kernel headers,做 `/usr/include/asm,asm-generic,linux` 软链接到 /usr/src/linux-headers-6.6.98-1-aw2511/include/uapi/
   - arm64 缺 asm/types.h,symlink 到 asm-generic/types.h
   - CMakeLists.txt 默认 SYS_ARCH=linux_armhf (因为 CMAKE_C_COMPILER=/usr/bin/cc 不含 "aarch64")
   - 强制走 aarch64 分支:`-DCMAKE_C_COMPILER=/usr/bin/aarch64-linux-gnu-gcc`
4. 编译成功,vpm_run 78KB,RPATH 正确指 awnpu_model_zoo A733 .so
5. 替换 /usr/lib/libVIPhal.so + libNBGlinker.so 为 awnpu Aug 2024 版本 (md5 `a432e0ec...` + `dd63994b...`)

### 测试结果
**测试 A: 跑 mobilenet_v2_t527.nb**:
- ✅ driver load: `VIPLite driver software version 2.0.3.2-AW-2024-08-30`
- ✅ .nb 文件找到
- ❌ 但 NPU reject: `binary target=0x10000016 T527, actually target=0x1000003B A733` — **这是 chip ID 校验正常工作的证据!说明 ABI 配套!**

**测试 B: 跑 yolov5s_rt_uint8_a733.nb**:
- ✅ driver load
- ✅ nbg 加载成功 (`size: 5120576`)
- ✅ create network 13.9 ms
- ✅ prepare network 1.3 ms
- ✅ tensor shape 正确 (3 个 80x80/40x40/20x20 detection heads)
- ❌ **inference 阶段 hang**: `VIPDRV_WAIT_TASK status=-1`

### 修正后的根因
- **不是 vpm_run binary 问题** (修了之后 driver load 成功)
- **kernel driver (Oct 2025) 跟 awnpu Aug 2024 .so 仍然 ABI 不完全配套**
- hang 位置从 7/12 的 driver load 阶段 → 现在推进到 inference 阶段
- 需要的不是换 userspace,需要换 **kernel driver**
