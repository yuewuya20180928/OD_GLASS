## 0 · 一句话设计主张

> ★**MECH 版不是「再造一道弱版闸」, 而是【把 SW 那道闸的判据口径原样搬过来, 只换扫描面与注册表冻结范围】** ★

## 1 · 扫描面 (★不许只扫顶层★)

| 项 | SW 侧现状 | ★**MECH 版要求** ★ | 实测 |
|---|---|---|---|
| 文档 | `SW/*.md` (**单层**) | ★**`MECH/**/*.md` 递归** ★ | **48** 份 md |
| 脚本 | **不扫** (SW 闸只扫 md) | ★**`MECH/**/*.py` 递归 (★MECH 的位号风险主要在判据脚本里★)** ★ | **65** 份 py |
| 合计 | — | — | ★**113 份 (顶层 == 递归 ⇒ 无漏网)** ★ |
| 唯一 token | — | — | **230** 个 |

★**为什么必须扫 `.py`**: MECH 侧 1,934 命中行里 **543 行在 `.py`** (其中 **508 行是代码**、35 行是注释), 而 1,356 行在 `.md` ⇒ ★**只看 md 的闸会漏掉 543 行「判据脚本里的位号字面量」** ⇒ ★**那正是假绿最容易藏身的地方** ★。

★**为什么必须递归**: `MECH/` 下有子目录 (`MECH/print/` 等) ⇒ 单层 glob 会漏。

★**为什么必须补前缀 (★照抄 SW 的「只许加不许减」原则★)**: SW 闸的 `TOKEN_PREFIXES` 共 16 个 (`R_ C_ U_ J_ D_ L_ Q_ TP_ LED_ SW_ VBUS_ PWR_ FB_ BT_ CONN_ CHG_`) ⇒ ★**它扫不到「裸编号」位号 `Q1` / `Q2` / `X1`** ★ ⇒ 这 3 个在 218 真集里 ⇒ ★**MECH 版必须补一条 C16 规则: `^Q\d+$` / `^X\d+$` 裸编号位号** ★ (实测: 命中表 76 个 distinct 真集引用中, SW 前缀只覆盖 73 个, 漏的正好是这 3 个)。

## 2 · 分类口径 (★照抄 SW 那道闸的 C1/C2/C14 三类 + 冻结注册表机制★)

### 2-1 · 抄过来的部分 (★口径零漂移的做法★)

| SW 侧机制 | SW 侧实现 | ★**MECH 版做法** ★ |
|---|---|---|
| ★**C1 live 解析** ★ | token 现在能在【板文件】或【网表】里找到 ⇒ 真位号·存在 | ★**完全同源**: 板 `HW/PCB/demo_mainboard.kicad_pcb` + 3 件网表 CSV (`HW/netlist_v1.csv` / `netlist_v1_pins.csv` / `BOM_v1.csv`) ★ |
| ★**C2 冻结注册表** ★ | token 在建闸日是位号, 现在找不到了 ⇒ 真位号·【改名漂移】 | ★**同机制, 但冻结范围换成 MECH 域**: 冻结「★**MECH 域引用到 且 建闸日能解析得到**★」的位号集合 ⇒ 命中注册表却解析不到 ⇒ 改名漂移 ★ |
| ★**C14 兜底** ★ | 形状像位号, 板/网表里从来没有过 ⇒ 【真隐患】 | ★**同规则, 但 MECH 侧数字大得多 (60 vs 3)** ⇒ 见 §5 |
| ★**冻结注册表机制** ★ | `DESIGNATOR_REGISTRY` 常量 + `--freeze-registry` 一条命令重建 | ★**同机制**: `MECH_DESIGNATOR_REGISTRY` + `--freeze-registry` (★建闸日跑一次, 之后只读★) ★ |
| ★**建闸日基线机制** ★ | `BASELINE_COUNT = 3` = 建闸日实测 `DESIGNATOR_MISSING` 条数 = 允许上限, ★**不许为了让闸绿而放宽** ★ | ★**同机制, 数字必须 MECH 侧自己 fresh 测 (见 §5), 不许抄 3** ★ |
| ★**基线逐条理由** ★ | `BASELINE_TOKENS` 逐条写「为什么本来就该对不上」 | ★**同机制** ★ |
| ★**新真隐患判定** ★ | `baseline_ok = (missing_total <= BASELINE_COUNT) and (not new_missing)` | ★**原样照抄** ★ |
| ★**fail-closed 三条** ★ | 板读不到 / 网表读不到 / 文档列表拿不到 ⇒ 判红 | ★**原样照抄 + 扩一条** (见 §3) ★ |
| ★**反向用例** ★ | `--selftest` ≥5 条 | ★**≥5 条 (见 §4) + 加 MECH 特有 2 条** ★ |

### 2-2 · MECH 侧必须新增的两条 (★因为 MECH 域与 SW 域形状不同★)

| 规则 | 为什么需要 | 实测依据 |
|---|---|---|
| ★**C15 · 判据脚本的常量/变量名命名空间** ★ | MECH 判据脚本里大量用「形状像位号」的变量名 (`R_ILIM_VALUES` / `LED_REF` / `R_DCR` / `C_CASES` …) ⇒ **它们不是位号, 是代码标识符** ⇒ 若不摘出去, 闸一建就红 40 条 | ★**实测: C14 共 60 条, 其中 40 条【只出现在 .py 里】= 判据脚本变量名** ★ |
| ★**C16 · 裸编号位号** ★ | `Q1` / `Q2` / `X1` 不带下划线前缀 ⇒ SW 的 16 前缀扫不到 ⇒ 218 真集里漏 3 个 | ★**实测: 命中表 76 个 distinct 真集引用, SW 前缀覆盖 73 个, 漏 Q1/Q2/X1** ★ |

★**规则口径的实现纪律 (★防口径漂移★)**: ★**MECH 版不许把 SW 那道闸的分类逻辑抄一份改改** ⇒ 建议 **`importlib` 只读 import `SW/tools/check_sw_ref_reachability.py`, 直接复用它的 `TOKEN_PREFIXES` / `read_board_refs` / `read_netlist_refs` / `read_net_names` / `classify`** ★ ⇒ 本设计稿的原型就是这么干的 (`logs/iss326/gate_design/mech_gate_proto.py` §"只读 import SW 侧那道闸") ⇒ ★**两个闸对同一盘面永远给同一个答案** ★。

## 3 · fail-closed 三条 (★取不准必须判红, 不许放宽成「取最近一条」★)

| # | 条件 | SW 侧行为 | ★**MECH 版行为** ★ |
|---|---|---|---|
| ★**F1** ★ | ★**板文件读不到** ★ | 抛 `InputError` ⇒ 判红 | ★**原样照抄** (板 md5 = `611b869e13518c3c023fb178f91a0075`, 不匹配时判红) ★ |
| ★**F2** ★ | ★**网表 3 件读不到 / 没有 `ref` 列** ★ | 抛 `InputError` ⇒ 判红 | ★**原样照抄** ★ |
| ★**F3** ★ | ★**扫描面拿不到** ★ (SW: glob 空) | 抛 `InputError` ⇒ 判红 | ★**原样照抄 + 扩一条: `MECH/**/*.py` 与 `MECH/**/*.md` 【各自】非空, 且 token 总数 > 0 ⇒ 否则判红** ★ (★防「只扫到 md」或「只扫到 py」的半残口径★) |

★**三条补充纪律 (★「取不准」的三个具体落点★)**:
1. ★**取位号不许「取最近一条」**: 同一个 token 在多处出现, ★**必须按【全部出现位置】判**, 不许只取第一处或最后一处 ⇒ SW 侧的 `classify(token, idx, occ)` 收的是 `occ` 列表, ★**MECH 版照抄这个接口** ★。
2. ★**基线上限不许为了让闸绿而放宽**: `BASELINE_COUNT` 一旦定下, ★**只许在【基线里的条目真隐患被修掉】时下调, 不许上调** ★ ⇒ SW 侧 `baseline_ok` 的 `(not new_missing)` 分支就是这条的实现。
3. ★**注册表只读**: 建闸日冻结后, ★**`--freeze-registry` 不许在日常 CI 里跑** ⇒ 否则每次跑都在重写基线 ⇒ 闸失效。

### 5-3 · 建议 (交 main 拍板, ★本单不替老板拍板★)

> ★**建议基线 = 16 条** (文档级真隐患, 已剔除本单自污染与判据脚本变量名)
> ★**前提**: C15 (判据脚本常量/变量名命名空间) 先落地 ⇒ ★**否则闸一建就红 56 条, 等于没建** ★
> ★**若 main 决定先不落 C15** ⇒ 那基线只能取 **56** (剔除自污染后), ★**但这个基线里混着 40 条代码标识符 ⇒ 基线的解释力很差, 不建议** ★
> ★**基线里的每一条都要写理由** (照抄 SW 的 `BASELINE_TOKENS` 口径) ⇒ ★**不许只给一个数字** ★
> ★**16 这个数不许抄 SW 的 3, 也不许抄本设计稿以外的数** ★ —— 它是 ★**MECH 侧 fresh 实测** ★

### 5-4 · ★★为什么必须「改名之前」建闸 (本设计最硬的一条论据) ★★

| 读数 | 值 | 含义 |
|---|---:|---|
| 218 真集里被 MECH 域引用到的 **改名位号** | ★**68** ★ | 186 个要改名的位号中, MECH 域真的引用了 68 个 |
| 这 68 个今天的状态 | ★**68/68 都能 live 解析 (C1)** ★ | 今天的引用是通的 |
| ★**改名当天这 68 个的分类** ★ | ★**全部变 C2 改名漂移** ★ | ★**闸的 C2 计数会从 0 跳到 68** ★ |
| 218 真集里被 MECH 域引用到的 **不动位号** | ★**7** ★ | ★**改这些 = 误伤 ⇒ 沙盒用例 ③ 的探针 (`J_SOM_P1` 就在其中)** ★ |

> ★**结论**: ★**先改名后建闸 ⇒ C2 一次跳出 68 条 ⇒ 闸分不清「老漂移」和「新漂移」⇒ 闸失去鉴别力** ★
> ★**⇒ 闸必须先建好、注册表先冻结, 改名之后闸才认得出「哪一条是我这次改漏的」** ★
