## §0 一句话结论 + 三问回答

**一句话结论**: `J_UART` 现位**放不下**官方 1×2 P1.27 THT land (★**不是孔的问题, 是铜的问题**★ —— 三个朝向的**孔净距全部通过** `1.0773` 以上, 但 pad1 铜箔**压在 `I2C_B_SDA` 的 F.Cu 长走线上**, 铜箔净距余量 `-0.3500`); **挪得下** —— 本机穷举 **282,663** 个候选落位 (3 朝向 × 94,221) 实测出可行域, **最小位移 = 0.8010 mm** (rot 0 / rot 90 同点, 落点 `(20.7000, 70.8000)`, 余量 `0.0262`; ★**余量太薄 ⇒ 要余量 ≥ `0.1` 就得挪 `0.9009` mm**★), **一个既有过孔都不用挪**; 但**挪完那一趟还剩 3 件没解决** (① `UART_TX` 5 段走线端点脱网必须重接 + `UART_RX` **一寸铜都没有** ② `UART_TX`/`UART_RX` 的 **pin 顺序在 rot 0/270 下翻转** ③ 落位横移会不会挤掉 UART 罩开口待 mech-lead 答)。

| 三问 | 答案 | 判据出处 |
|---|---|---|
| (a) 现位能不能放下? | **不能**。rot 0/90/270 三个朝向的**孔净距全部通过** (最差 `1.0773` ≥ `0.25`), 但 **pad1 铜箔与 `I2C_B_SDA` 的 F.Cu 走线重叠** ⇒ 铜箔净距余量 `-0.3500` / `-0.3500` / `-0.8035` (rot 0/90/270) | §3 · C2/C4/C7 |
| (b) 挪得下吗? | **能**, 代价是**至少挪 `0.8010` mm** (余量 ≥ `0.1` 的口径下是 `0.9009` mm)。rot 270 另有一条**只挪 `0.0400` mm** 的路 (pad1 锚点口径, 余量 `0.2750`) | §4 · C1~C5 |
| (c) 挪完那一趟还剩几件没解决? | **3 件** (走线重接 + `UART_RX` 零铜 / pin 顺序翻转 / 机械开口)。**过孔一个都不用挪** | §5 · §6 · §7 |

★**★本单挖出三条与姊妹件 `J_DEBUG` (ISS-376) 完全不同的结构性事实, 是「同一趟做完」的关键输入 ★** ★
★**① `J_UART` 的封装原点【不在焊盘上】**: 现位封装 origin `(20.7400, 70.0000)`, 但两个焊盘在局部 `(-2.10, -1.40)` / `(-1.60, -1.40)` ⇒ 绝对 `(18.6400, 68.6000)` / `(19.1400, 68.6000)` ⇒ ★**官方 land 的 pad1 (局部 `(0,0)`) 装上去必然和旧 pad1 错位 `2.5239` mm**★ ⇒ 「现位放不下」这一条**不能照抄 `J_DEBUG` 的孔净距结论** ★
★**② 卡点是【铜】不是【孔】**: 三个朝向**孔净距全部通过** (最差 `1.0773`), 真正卡住的是 pad1 铜箔压在 `I2C_B_SDA` 那条 F.Cu 长走线上 (走线从 `(13.2450, 71.1500)` 直拉到 `(27.6400, 68.6000)`, **从现位正中间横穿过去**) ★
★**③ `UART_RX` 这个网在板上【一寸铜都没有】**: 板读 `UART_RX` (netcode 130) 全网只有 2 个 pad (`J_UART.2` + `J_SOM_P2.9`), **0 段走线、0 个过孔** ⇒ `UART_RX` 从来没接过 ⇒ ★**挪 pad2 的代价 = 0 段脱网 (但也说明这条网本来就是空的, 换 land 后仍然要有人去接)**★ ★

## §4 pin 顺序契约 (★只管 `J_UART` 这半边 ★)

### §4.1 三个朝向的 pin 顺序表

| 朝向 | pad1 绝对位置 (落点 L) | pad2 绝对位置 (落点 L) | 沿板 X 递增方向的 net 顺序 | 与现位 (TX 在左, RX 在右) 相比 |
|---|---|---|---|---|
| rot 0 | (L.x, L.y) | (L.x, L.y+1.2700) | ★**X 向无序** (两个 pad 同 X 列, 只有 Y 向 TX→RX)★ | ★**Y 向同序** (TX 在下, RX 在上) ★ |
| rot 90 | (L.x, L.y) | (L.x+1.2700, L.y) | ★**`UART_TX` → `UART_RX`** ★ | ★**同序** ★ |
| rot 270 | (L.x, L.y) | (L.x−1.2700, L.y) | ★**`UART_RX` → `UART_TX`** ★ | ★★**翻转**★★ |

### §4.2 ★**会不会翻转? —— 会, 且只在 rot 270 下翻转 ★**

- ★**现位 (板读)**: pad1 `UART_TX` @ X=`18.6400`, pad2 `UART_RX` @ X=`19.1400` ⇒ **沿 X 递增: TX → RX** ★
- ★**rot 90**: pad1 @ L.x, pad2 @ L.x+`1.2700` ⇒ **沿 X 递增: TX → RX** ⇒ ★**与现位同序** ★
- ★**rot 270**: pad1 @ L.x, pad2 @ L.x−`1.2700` ⇒ **沿 X 递增: RX → TX** ⇒ ★★**与现位【镜像】**★★ ★
- ★**rot 0**: 两个 pad 同 X 列 ⇒ **沿 X 无法定序**; 沿 Y 递增: TX → RX (rot 0 的 pad2 在 +Y) ⇒ 排针本体相对现位是【转 90°】而不是【镜像】 ★

> ★**★关键矛盾点 (★只登记, 不代拍★) ★**
> ★**§2.3 算出来「几乎原地不动」的那条最优解是 rot 270 (pad1 只挪 `0.0400` mm, 余量 `0.2750`) —— 而 rot 270 恰好是三个朝向里【唯一会把 pin 顺序翻转】的那个** ★
> ★⇒ ★**「落位代价最小」和「pin 顺序不变」这两件事在 `J_UART` 上【互斥】**: 想要顺序不变就得走 rot 90 (pad1 挪 `0.2441`~`0.3124` mm, 余量 `0.0447`~`0.1155`); 想要落位代价最小就得走 rot 270 (pin 顺序翻转) ★
> ★⇒ ★**这个取舍归 main 裁 (换不换 land / 挪不挪 / 挪到哪 / pin 顺序要不要改), 本单只给事实与代价 (§7 未决项第 ② 条)** ★
> ★★**不许替 sw-lead 回答 `J_DEBUG` 那半边 (★那是 ISS-378 的地界★) —— 本单只管 `J_UART` 一个 ref 的 2 个脚**★★

### §4.3 ★`UART_RX` 零铜这个事实对 pin 顺序的影响 ★

★因为 `UART_RX` 在板上没有任何铜, 所以 ★**「pad2 挪到哪」在电气上没有任何既有约束** ⇒ 唯一约束来自铜箔净距 (C2) 和机械开口 (§5) ⇒ ★**若 main 决定改 `UART_RX` 的 net 映射 (pad1↔pad2 对调), 板侧代价 = 0 段走线重接** ★ (★但那条网本来就要新接, 所以是「本来就要做的活」不是「额外多出来的活」★)
