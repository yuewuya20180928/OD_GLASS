# HW/CHIP_SCORING_RUBRIC.md —— 换芯片选型打分标准 v1 (9 项 × 0-10)

> **触发**: 老板 2026-10-29 09:59 指令 —— "直接更换酷芯微的解决方案, 不用酷芯微的芯片, 直接采用其他芯片:
> ①先筛选国内 TOP10 的嵌入式芯片厂商 ②各厂家筛出 TOP1~5 的芯片 ③每款芯片打分 (每项最高 10 分最低 0 分),
> 按总分做芯片选型"。
> **本文 = 把老板的 9 条标准翻译成可机械判定的给分条件** —— 没有这一步, "打分"就是拍脑袋, 子总工之间的分数不可比、老板复核不了。

**打分上限**: 9 项 × 10 = **90 分**
**一票否决 (不参与打分, 直接淘汰)**: 见 §2
**用法**: 情报方 (hw-lead) 只交**逐项证据 + URL**, **不打分**; 打分由项目总工按本文机械执行 ⇒ 分数可复算、可审计。

---

## §1 九项评分细则 (每项 0-10)

### 3.1 sensor 接入及 ISP 处理能力 (≤1080P@60 的一票否决)
| 分 | 判据 (择一, 取最高) |
|---|---|
| 10 | ≥4-lane MIPI-CSI @ **≥1080P@60** + 硬件 ISP + 硬件缩放 + EIS/多帧降噪 (或厂商明确支持) |
| 8 | ≥4-lane MIPI-CSI @ ≥1080P@60 + 硬件 ISP + 硬件缩放 (无 EIS) |
| 6 | ≥2-lane MIPI-CSI @ ≥1080P@60 + 硬件 ISP |
| 4 | ≥4-lane @ 1080P@30 (仅在"淘汰线已由 §2 放宽"时用, 默认不出现) |
| 0 | 无 MIPI-CSI / ISP 全软 |
> **证据要求**: 官方 datasheet / 产品页的 MIPI lane 数 + 分辨率@帧率 + ISP 模块名 (如 RKISP / ISP350 / VVIP)。

### 3.2 智能算法处理能力 (不支持 YOLO 的一票否决)
| 分 | 判据 |
|---|---|
| 10 | NPU ≥6 TOPS + **官方/主流 YOLOv5/v8 转换工具链 + Model Zoo 公开模型** + 端侧 INT8 跑通 |
| 8 | NPU 4~6 TOPS + 官方工具链 + Model Zoo |
| 6 | NPU 2~4 TOPS + 官方工具链 |
| 4 | NPU 1~2 TOPS + 官方工具链 (仅轻量模型) |
| 2 | 有 NPU 但无公开 YOLO 转换链 / 只支持自家模型格式 |
| 0 | 无 NPU 或仅 CPU (MCU 级) |
> **证据要求**: TOPS 数值 + 工具链 pip 包名/版本 + Model Zoo 链接 + 是否有 YOLOv5/v8 样例。

### 3.3 CPU 核心数及主频
| 分 | 判据 |
|---|---|
| 10 | ≥4× 大核 (A75/A78/X1/S系列) @ ≥2.0GHz |
| 8 | 4× A55/A64 @ ≥1.8GHz, 或 2× A78 @ ≥2.0GHz |
| 6 | 4× A55 @ ≥1.5GHz |
| 4 | 2× A55 @ ≥1.5GHz |
| 2 | 单核 A55 / 双核 A53 |
| 0 | MCU 级 (Cortex-M / RISC-V 小核) |
> **证据要求**: 官方 CPU 核数/架构/主频; 强调 **大核** (小核多不算)。

### 3.4 DDR 带宽能力 (位宽 ≥32 为硬门槛, 64 最好)
| 分 | 判据 |
|---|---|
| 10 | **64-bit** + DDR4/LPDDR4X ≥2666MT/s (或 32-bit + ≥3733MT/s 等效带宽) |
| 8 | 64-bit + DDR4/LPDDR4 ≥1600MT/s |
| 6 | **32-bit** + DDR4/LPDDR4 ≥1600MT/s |
| 3 | 32-bit + LPDDR3/DDR3 |
| 0 | 位宽 <32-bit 或无外部 DDR (含仅 LPDDR 封装内 <32bit) |
> **证据要求**: 官方支持的 memory 接口位宽 + 最高速率 + 最大容量。
> ⚠️ **本项目真实需求**: 1080p60 通路 + YOLOv5s INT8 + 显示合成 ⇒ ≥32-bit 是**能跑得起来的门槛**, 不是偏好项。

### 3.5 端到端演示 (≤60ms, 允许 10ms 误差 ⇒ ≤70ms)
| 分 | 判据 (端到端 = 曝光→出光, 口径 A, 与项目锁死口径一致) |
|---|---|
| 10 | 有**官方或第三方实测**端到端 ≤50ms (或纯 NPU ≤10.67ms 推得 age=1) |
| 8 | 实测 ≤60ms |
| 6 | 实测 ≤70ms (容差内) |
| 3 | 实测 70~100ms |
| 0 | 无任何端到端实测值, 且无公开模型可换算 |
> **证据要求**: 实测来源 + 链接 + 口径说明 (是不是纯 NPU 时间冒充端到端)。⚠️ **只给"NPU 推理 X ms"的一律标 [推算]**, 不得当端到端。

### 3.6 芯片制程及功耗 (★功耗越高得分越低 —— **不是否决项**, 老板 10-29 18:55 明确)
| 分 | 判据 (制程 + SoC 域功耗, 取两者综合) |
|---|---|
| 10 | 制程 ≤12nm **且** SoC 域功耗 ≤250mW (官方值或实测) |
| 8 | ≤12nm 且 ≤350mW |
| 6 | ≤12nm 且 ≤500mW |
| 4 | 16nm 且 ≤600mW |
| **5** | ★**功耗不明确 / 无法推算 → 中间分 5** (老板 10-29 18:55 原话: "功耗不明确或者无法推算, 打中间的分") —— **不许因为查不到功耗就淘汰候选** |
| 2 | 28nm |
| 0 | 未量产 (这一档由 §2 V5 兜住) |
> ★**功耗不是淘汰线, 只是分数**。即便 >400mW (皮肤 43°C 红线), **该芯片照样进候选表、照样按总分参选** ⇒ 可行性问题**登记成后继风险项**, 由项目总工在选型结论里列"需要用什么手段化解" (放宽镜腿宽度 / 加散热 / 分体主板 / 换协处理器)。
> **证据要求**: 制程 (官方) + 功耗 (官方/媒体/实测, 标等级); 查不到就写 [0数据], 由打分按中间分处理。

### 3.7 图像缩放能力 (类似 VPP 模块, 一处多)
| 分 | 判据 |
|---|---|
| 10 | 独立硬件缩放器 (VPP / ISP scaler / VIP scaler) + **多路并行** (缩放 + 旋转 + 抠图可同时) |
| 8 | 硬件缩放器 + 单路多分辨率输出 |
| 6 | 硬件缩放器 (单一 scaler, ISP 内) |
| 3 | 仅软件缩放 (CPU) |
| 0 | 无缩放能力 |
> **项目语境**: 一处多 = **1080p60 输入 → 640×480 OD + 800×600 显示 + 缩略图** 三路并发 ⇒ 纯软件缩放会吃掉 CPU 和带宽。

### 3.8 VO 显示能力及接口 (**DP 优先于 MIPI-DSI**)
| 分 | 判据 |
|---|---|
| 10 | **DP 1.4 TX** (可直接驱动 DP sink / 转 DSI 桥) |
| 8 | DP TX + MIPI-DSI 双出口 |
| 6 | MIPI-DSI 多通道 (≥2) |
| 4 | MIPI-DSI 单通道 (DSI TX 1 lane 级别) |
| 0 | 无 VO 输出 |
> ★**换芯片的战略收益**: 项目卡了两周的 ISS-003/ISS-005 (ARS45 是否原生带 DSI TX 未确认, 桥接芯片是 fallback) —— **DP 是几乎所有 SoC 的原生出口**, 按老板"DP 优先"的口径, **换芯片很可能直接消掉桥接芯片这条采购路径 (4-8 周周期)**。
> **证据要求**: 官方 VO 接口类型 + 最高分辨率@帧率 + 是否支持双出口。

### 3.9 其他外设接口 (I2C / SPI / eMMC / USB / IO)
| 分 | 判据 (逐项累加, 上限 10) |
|---|---|
| +1.5 | I2C (≥2 路) |
| +1.5 | SPI (≥2 路) |
| +2 | eMMC (≥4.5) |
| +2 | USB (host/device, ≥2.0) |
| +1 | USB 3.0 / Type-C PD / PCIe 任一 |
| +1 | GPIO 数 ≥100 或可复用 IO 富余 |
| +1 | 额外能力 (多路 UART / SDIO / 以太网 MAC / 音频 DSP) |
| 上限 | **10 分** |
> **项目语境**: 跨铰链 USB (ISS-085) + I2C_A 挂 4 个从设备 (TMP117 / 充电状态 / 光机) + eMMC 存模型权重 + J_CHG SPI/I2C ⇒ 外设不足会直接卡结构与 SW。

## §3 物理可行性 —— **不作为选型前置条件, 登记为后继风险项** (老板 2026-10-29 18:55 明确)

> ★**老板原话**: "芯片没有的话, 项目起都起不来, **先定芯片功耗作为后继风险项**, 是在不行**镜腿做成宽的**"。
> ⇒ **口径**: ①**先按 9 项总分选芯片** (分数是唯一排序依据); ②镜腿/板宽/皮肤温度这些**不参与否决**, 一律**登记成后继风险项** (每条写: 缺什么 / 需要用什么手段化解 / 代价 / 谁来解 / 何时解)。
> ⇒ **结构尺寸不再是死约束**: 老板已明确**允许把镜腿/镜框做宽**来换面积 ⇒ 凡是"装不下"的问题, **优先走"放宽结构宽度"这条化解路径**, 而不是删件/双面贴/改板框。

每款候选仍要登记这些数 (供项目总工排风险项):

| 核查项 | 项目锁死值 | 来源 |
|---|---|---|
| SoC 域功耗 | ≤300mW 级 | §0 锁死变量 / 43°C 皮肤红线 |
| 封装尺寸 | 必须能进镜腿腔体 (镜腿 7.3mm) | §0 |
| PCB 板宽 | ≤60×**30**mm | ★§0 (10-29 19:16 老板放宽: 15mm → **30mm 以内**, 参考宽镜腿成品 ≥30mm) |
| 整机皮肤侧温度 | ≤43°C (设计目标 38-40°C) | MEMORY.md 铁律 (ISO 13732-1) |
| 电池/续航 | 1 小时以上 | §0 |
| 端到端 | <60ms (口径 A) | §0 |
| 工具链可得性 | 能转 YOLOv5 INT8 + 有 Model Zoo | 老板"资料充足"判据 |

**结论输出格式 (A6)**: ①**总分排序表 (90 分制)** —— 唯一排序依据; ②**后继风险项表** (功耗/封装/镜腿宽度/皮肤温度 ⇒ 每条: 缺什么 + 靠什么手段化解 + 代价 + 责任人); ③**对现方案的改动成本** (网表/原理图要重做多少)。
⇒ **风险项不参与打分、不否决候选**; 但**必须在结论里显式列出**, 不能装作没这回事。

## §4 情报方交付要求 (hw-lead 用的, 不打分)

对每款候选芯片, 逐项给**证据 + URL**, 证据分级标 [官方]/[实测]/[媒体]/[推算]/[0数据]:

```
芯片型号 | 制程 | CPU | NPU(TOPS)+工具链 | MIPI-CSI lane/分辨率@帧率 | ISP/缩放器 | DDR 位宽/速率 | VO 接口/分辨率 | 功耗 | 外设 | 量产状态 | 证据 URL
```
★**不许打总分** (打分是项目总工按本文做, 避免多家子总工各自一套口径); ★**不许把 [推算] 写成 [实测]**; ★**0 数据就写 0 数据, 不许编**。
