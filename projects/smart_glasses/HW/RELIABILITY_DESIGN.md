## B1 结论摘要 (每条带数字)

1. **降额表覆盖 15 个器件 / 电源 / 电池, 每个给温度·电压·电流三档** —— 工作值 / 额定上限 / 绝对最大 / 建议设计上限四列。**绝对最大 (abs max) 列大量为 `[0数据]`**: 本轮只核了各器件的**工作范围与额定值**, 没有逐份核 datasheet 的 Absolute Maximum Ratings 表 → **降额表目前只能用作"设计约束", 不能用作"器件符合性声明"**。
2. **最紧的温度降额项不是主控, 是 BQ2970 和 Type-C 母座** —— BQ2970 额定 `-40~85°C` → 建议设计上限 **72°C** (85×0.85), 而贴皮肤镜脚的组件环境上限 **55°C** → **占用率 76%**, 全板只剩 **17°C** 余量; Type-C 母座同类通用值 `-25~85°C` → 同样 72°C 上限 → **同样 76%**。→ **结构上必须把充电域 (BQ2970 + Type-C + 充电 IC) 挪到远离皮肤的镜框上沿**, 这条与 `MECH §2.3.1` 的结论**同向**, 是独立佐证。
3. **★ 降额评审查出 1 个电源拓扑硬伤 (R-F1)**: `TPS7A20` 压差 **110mV typ** `[官方]` → **3.3V 轨 (LIGHT_3V3 150mA + VDD_3V3_IO 200mA) 在 `SYS = VBAT` 低于 3.41V 时失效**。`SYS` 下限 3.0V `[推算, 1S 锂电]` → 失效区间覆盖放电末段约 **12-15% 电量** `[推算]` → 现场表现 = **"用到快没电突然黑屏"**。2.8V 轨需 VIN ≥2.91V → **✅ 不受影响**; 1.2V 轨 ✅。→ 处置见 §3.4, 裁决权给项目总工。
4. **★ 降额评审查出 1 个充电倍率风险 (R-F2)**: 充电电流设计 **1.0A** `[推算, POWER_IC_SELECTION §3.1.3]` 对 **575mAh** 电芯 = **1.74C**; 消费级 LiPo 典型允许充电倍率 **0.5C-1C** `[0数据-同类通用, 需电芯规格书]` → **1.0A 对 575mAh 电芯可能超规格**。→ 三个候选: ① 充电降 0.575A (1C, 充满 1.5h) ② 选支持 2C 快充电芯 ③ 改 340mAh 档 (1.0A = 2.9C, 更糟 → **淘汰**)。→ **必须先拿电芯规格书再定充电电流**。
5. **应力: 跌落工况下的板本体可靠性, 决定因素不是板厚而是支架是"面接触"还是"点接触"** —— 算得 (1m 跌落 / 吸能行程 2mm / 500g / PCB+器件 6g): **点接触 (2 螺钉柱 + 1 定位销, 跨距 20mm) + 4 层 0.8mm → σ ≈ 115 MPa > 板材弯曲许用 100-140 MPa ❌**; **面接触 (托架贴合, 有效跨距 3mm) → σ ≈ 17-11 MPa ✅**。→ 落成一条**可执行约束**: PCB 托架接触面 **≥40×8mm 且为面接触**, 只靠 2 个螺钉点承力不可接受 (R-F3)。
6. **MTBF: 元件级累加 MTBF ≈ 236,700 h (≈27.0 年)** (ΣFIT = 4,224 FIT, 263 件器件) `[推算]`; **系统级 MTBF: 按需触发基准工况 ≈ 522,500 h (≈59.6 年)**, 最恶劣工况 (夏季密闭 55°C) ≈ **317,900 h (≈36.3 年)**, 满载最恶劣 ≈ **93,400 h (≈10.7 年)** `[推算]`。
7. **★ MTBF 的主导项是光学子系统, 不是 SoC** —— 光机 + 衍射光波导×2 + 一拖二分光件 = **1,650 FIT = 全模型 39.1%** `[推算]`; SoC (120 FIT) 只占 **2.8%**。→ **结论: 提高整机 MTBF 的杠杆在"光机/波导的供应质量与清洁度管理", 不在 PCB 设计**; 反过来说, 硬件降额/应力做得再好, 也只能动那 61% 里的一部分。
8. **★ 本评审不改变 MECH §2.3 的散热结论** —— 降额规则与应力约束都是**约束条件**, 不改变热模型输入 (P / R_skin_path / R_conv)。`0.23W → 46.5°C` (超 ISO 13732-1 红线 43°C 3.5°C) 与 `1.22W → 96.1°C` 的数字**一字不改**。唯一能改变皮肤温度的机制是**降功耗 (降频/降亮度)**, 而它的代价是**端到端延迟** → 必须记进 sw-lead 的延迟账。详见 §B6。
9. **未验项 14 条** —— 其中 **6 条必须等样机** (跌落/振动/弯折/热/焊点/连接器寿命), **8 条必须等 datasheet 或规格书** (abs max / FIT / 电芯倍率 / 镜头刚度等)。

## B2 评审基准: 统一降额规则 + 应力工况假设

### 2.1 降额规则 (本文统一采用, 全文所有"建议设计上限"都按这三条推)

> **规则出处**: IPC-9701 (焊点/板级应力) 与 GJB/Z 35A (元器件降额准则) 的通用降额档位, 电源/模拟器件按 TI 通用实践取更保守的一档。**本文未逐份核对上述标准的原文条款号 → 规则本身标 `[推算]`**。

| 轴 | 规则 | 说明 |
|---|---|---|
| **温度** | 设计工作温度上限 ≤ **器件额定温度上限 × 0.85**; 且结温 Tj 在最恶劣工况 ≤ **105°C** | 0.85 档 = 通用降额准则中间档。SoC 自身 Tj 上限待 datasheet |
| **电压** | 设计工作电压 ≤ **器件输入电压上限(额定) × 0.80**; **且必须另做 dropout/headroom 校核** (额定输入范围不等于可用范围) | 0.80 档 = 通用档; 生产容差/工艺漂移留 20% |
| **电流** | 设计工作电流 ≤ **器件额定电流 × 0.80**; 机械/光学部件 (无降额数据) ≤ **× 0.70** | 0.80 档 = 通用档 |

**"占用率"定义** = 设计工作值 ÷ 建议设计上限。**≥100% ❌ / 80-100% ⚠️ / <80% ✅**。

**三个工况环境温度 (本文统一)**:

| 工况 | 组件环境温度 T | 来源 |
|---|---|---|
| 低温良好 | **35°C** | `MECH §2.3` 体温基准 35°C |
| 基准 / 按需触发 | **40°C** | 壳体温升后的中值 `[推算]` |
| 热恶劣 (夏季密闭 / 满载) | **55°C** | 满载工况壳内空气上限 `[推算]`; 满载下 MECH 推算皮肤侧 96.1°C 已判"物理不成立" → 55°C 取的是**组件自身周围**温度上限, 不是皮肤侧温度 |

### 3.2 ★ 降额评审发现 (两条, 都要进 needs_from)

#### R-F1 🔴 高 —— 3.3V 轨在电池放电末段失效 (SYS 低压 + LDO dropout 冲突)

```
事实链:
  SYS = VBAT = 3.0 ~ 4.2 V                     [推算] 1S 锂电 (POWER_IC_SELECTION §5.2)
  TPS7A20 压差 (dropout) = 110 mV typ           [官方] POWER_IC_SELECTION §B5
  → 3.3V 输出要求 VIN >= 3.41 V
  → 失效区间: VBAT < 3.41 V
  → 1S 锂电 3.41V→3.0V 区间约占总容量 12-15%     [推算] (典型放电曲线)
现场表现: 光机掉电 (LIGHT_3V3 150mA) + SoC IO 轨失效 → "用到快没电突然黑屏"
影响轨: LIGHT_3V3 + VDD_3V3_IO (共 350 mA)
不受影响: SENSOR_AVDD 2.8V (需 ≥2.91V, SYS 下限 3.0V ✅) / SENSOR_CORE 1.2V ✅ / TPS62130A 核心轨 ✅
```

**三个候选处置 (裁决权在项目总工/老板, 我只给工程代价)**:

| 方案 | 做法 | 代价 | 可靠性副作用 |
|---|---|---|---|
| **A (我推荐)** | 把 BQ2970 的 **UVP 阈值从 ~3.0V 抬到 3.5V**, 3.3V 轨改由 **TPS62130A** 供 (3.5-4.2V → 3.3V, buck 压差 ~0.15V ✅) | **牺牲 12-15% 可用容量** → 续航口径要重算 (Q4) | 容量减少 → 电池档位可能要从 340mAh 抬档 |
| B | 3.3V 轨换 **buck-boost** | +1 颗 IC + 面积 + 成本 | 新增 IC = 新增 FIT 项 (§B5 光学占 39% 的背景下, 这条成本可接受) |
| C | 保持现状, **接受末段黑屏** | 0 | ❌ 典型的"能用但会骂人"故障, 客服成本高 |

#### R-F2 🟡 中 —— 1.0A 充电 vs 575mAh 电芯 = 1.74C 超典型倍率

```
充电电流设计 1.0 A                [推算] POWER_IC_SELECTION §3.1.3
575 mAh 电芯 @1.0A = 1.74C        [推算]
消费 LiPo 允许充电倍率 0.5C-1C    [0数据-同类通用] 必须以电芯规格书为准
340 mAh @1.0A = 2.94C             [推算] → 更糟, 该档位直接排除 1.0A
```

**处置**: ① 先拿电芯规格书 (允许充电倍率 + 循环寿命) ② 若电芯只支持 1C → 充电电流改 **0.575A**, 充满时间 **1.08h → 1.5h** (影响"1h 充满"的口径) ③ 或选支持 2C 的电芯 (牺牲容量/成本) → **needs_from `rel_battery_cell_spec`**。

> ⚠️ 这条**不影响** MECH 的散热结论: 充电耗散在 1.0A→0.575A 时从 0.5W 降到 **0.29W** `[推算, §3.1.2 算式]`, 对**充电时**的皮肤温度有帮助, 但对**工作态 46.5°C 毫无影响**。

### 4.3 跌落工况

**工况**: **1.0 m 自由跌落**, 硬质面, **6 面各 1 次 + 4 角各 1 次 = 10 次/台**, 每台样机 10 次 × 3 台 = 30 次; 吸能行程 2.0mm → **a = 500g**。

**先算板本体应力 (这是全部跌落风险的总闸)**:

```
冲击速度      v = sqrt(2gh) = sqrt(2×9.80665×1.0) = 4.43 m/s
冲击加速度    a = v²/(2δ) = 4.43²/(2×0.002) = 4905 m/s² = 500 g
等效惯性力    P = m_eff × a = 0.006 kg × 4905 = 29.4 N
   (m_eff = PCB 0.9g + 器件 ≈5g = 6g; 电池与光机由骨架直接承力, 不计入)
截面模量      Z = b·h²/6 = 12×0.8²/6 = 1.28 mm³  (4 层 0.8mm)
              Z = 12×1.0²/6 = 2.00 mm³  (6 层 1.0mm)
简支梁跨中集中载荷  σ = P·L/(4Z)
```

| 支架形式 | 有效跨距 L | 4 层 0.8mm | 6 层 1.0mm | 判定 (板材弯曲许用 100-140 MPa, 焊接前最弱 `[0数据-通用]`) |
|---|---|---|---|---|
| **点接触** (仅 2×M1.2 螺钉柱 + ⌀2.0 定位销, 跨距 20mm) | 20mm | **σ = 115 MPa** | **σ = 74 MPa** | 4 层 ❌ **超许用** / 6 层 ⚠️ 贴边 |
| **面接触** (金属骨架托架全面贴合, 有效跨距 3mm) | 3mm | **σ = 17 MPa** | **σ = 11 MPa** | ✅ 两种层数都大量余量 |

> 🔴 **R-F3 (本文可执行约束)**: **跌落可靠性由"支架是面接触还是点接触"决定, 不由板厚决定** —— 点接触 + 4 层 0.8mm 会算出 σ=115 MPa 超板材弯曲许用; 换成 6 层 1.0mm 只是把问题推到贴边, 而**加厚板会挤占镜脚厚度 (MECH 已算镜腿 7.3-8.7mm, 没有余量)**。
> → **落成约束: PCB 托架接触面 ≥ 40×8mm 且必须是面接触; ⌀2.0 定位销只负责防转, 不承担弯矩; 2 个 M1.2 螺钉只做防翘压紧。** → 写进接口请求给 mech-lead (`needs_from` `rel_mount_stiffness`)。

### 5.4 MTBF 的三条解读 (结论比数字重要)

1. **🔴 光学子系统主导: 光机 + 波导×2 + 分光件 = 1,650 FIT = 全模型 39.1%**; SoC 只占 120 FIT = **2.8%**。→ **提高整机 MTBF 的杠杆在光机/波导的供应质量与光学腔清洁度管理, 不在 PCB 设计**。反过来说, 本文做的降额与应力加固, 最多只能动剩下 61% 里的一部分。
2. **⚠️ 数字的"漂亮"来自模型的乐观**: 系统级 59.6 年 **不是可信承诺**, 因为 ① 全部 FIT 是通用代表值而非器件数据 (A1) ② 焊点在模型里被低估 (A11) ③ 电池按 MTBF 刻画是弱的 (A8) ④ 汗液/盐雾/化妆品/UV 老化完全没进模型 (A12)。→ **本 MTBF 的正确用法: 做"相对比较"和"找主导项", 不做"对外承诺"**。
3. **✅ 对本文的交叉验证**: 按需触发工况 (D=0.19) 的 MTBF 比满载高 **5.6 倍** (522,510 vs 93,396 h)。这与 `MECH §2.3` 的热学结论**方向一致**: **按需触发同时是散热解和可靠性解**, 但两者是**同一个决定的两面** —— 用按需触发换来的 MTBF 提升, 代价是端到端延迟变差 (触发到出框的时间)。

## B6 ★ 与 MECH §2.3 皮肤温度模型 (46.5°C) 的关系

> 本节是 ISS-023 的强制项。结论先行:

### 6.1 结论

**降额收紧与应力收紧, 都不会改变 MECH §2.3 的散热结论。**

| 项 | 数值 | 是否被本文改变 |
|---|---|---|
| 按需触发 0.23W → 皮肤侧 | **46.5°C** (超 ISO 13732-1 红线 43°C **3.5°C**) | ❌ **不变** |
| 持续满载 1.22W → 皮肤侧 | **96.1°C** (保守模型) / 82.0°C (剥离壳壁) | ❌ **不变** |
| 43°C 红线对应的持续功耗上限 | 0.16W (保守) / 0.21W (剥离壳壁) | ❌ **不变** |
| 贴皮肤可持续功率上限 | 0.15-0.2W | ❌ **不变** |

**为什么不变 (机制层面)**: MECH §2.3 的模型是
`皮肤侧温升 = P × R_skin_path × [R_conv/(R_skin_path+R_conv)]`, 输入只有三项 —— **发热功率 P**、**结构热阻**、**对流面积**。
本文所有的降额规则 (电压/电流/温度上限) 与应力约束 (弯折/振动/跌落) 都是**约束条件**, 它们**不进入 P 的表达式, 也不改变 R_skin_path 与 R_conv**。

### 6.2 唯一的两条耦合路径 (都不是本文的手段)

| 路径 | 机制 | 对 46.5°C 的影响 | 代价 |
|---|---|---|---|
| **① 降频 / 限流 → 降功耗** | 若因降额 (电流上限/温度门限) 触发 SoC 降频 → P 从 0.23W 进一步下降 → 皮肤侧温度下降 | **会下降** (每降 0.01W ≈ 降 0.5°C, 按 §2.3 主模型 50 K/W) | **端到端延迟增加** → 必须记进 sw-lead 的 `<60ms` 预算; 降频与"框龄 age"台阶 (16.67ms) 直接冲突 |
| **② 充电域挪离皮肤侧** | 把 BQ25896 (0.5W 耗散) + BQ2970 + Type-C 母座从镜脚末端挪到镜框上沿 | **只改变"充电时"的皮肤温度 (MECH 算得 75.1°C)**, **不改变工作态 46.5°C** | 跨铰链要加大电流通道 (MECH M9 缺 USB 链路, `SCHEMATIC_L1 §5.4` 已按"加 CONN_USB"预留) |

> ⚠️ **必须点明的一条**: 路径 ② 与本文 §3.2 的温度降额结论**互相强化** —— BQ2970 (额定 85°C) 与 Type-C 母座 (同类 85°C) 的建议设计上限只有 **72°C**, 而镜脚末端组件环境上限 **55°C** → **只剩 17°C 余量**。所以"充电域挪到镜框上沿"这件事, **既是为散热 (MECH §2.3.1), 也是为器件温度降额 (本文 §3.2)** —— 两条独立路径指向同一个结构决定, 这是本文对 MECH 结论的**独立佐证, 不是重复**。

### 6.3 本评审与散热的关系, 一句话

> **降额与应力是"不许坏"的约束, 不是"不许热"的手段。**
> 想解决 46.5°C, 只有两条路: **降功耗** (降频/降亮度, 代价在延迟账) 或 **把热源挪出接触区** (代价在空间与跨铰链电流)。
> **本文不提供第三条路, 也不为 MECH 的结论背书或改写。**
