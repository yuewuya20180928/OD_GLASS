## 0. 判定口径

**老板给的替换标准 (11 条)**: ①满足眼镜场景需求 ②已量产 ③芯片手册 ④调试工具链 ⑤SDK开源 ⑥社区易查(CSDN等) ⑦sensor接入1080P60FPS ⑧YOLO达640×480@60FPS ⑨算力≥6T ⑩端到端延时≤60ms ⑪最好内置DDR

**我加的 3 条否决项**:
| # | 否决项 | 依据 |
|---|---|---|
| **V1** | **皮肤 ≤43°C (ISO 13732-1)** ⇒ SoC 域 ≤300mW 级 | 贴皮肤镜腿可持续承受上限仅 **0.15-0.2W** (MECH 模型) |
| **V2** | **封装 ≤10mm 级 + 塞得进 60×15mm 板框** (镜腿 7.3mm 不变) | §0 锁死表板宽 15mm / 板长 60mm |
| **V3** | **MIPI-DSI 显示输出** (或能配桥接芯片) | 我们的光机是 MIPI-DSI 输入 (走鹃Ⅱ) |

> ★**一句话结论**: **15 个候选里, 没有一个能同时满足 ①~⑪ + V1~V3**。
> 满足「≥6T + 资料全 + 已量产」的 (**RK3576 / RK3588**) 功耗封装是**手机级**, 直接违 43°C 红线;
> 真正眼镜级形态的 (**全志 V881 / 恒玄 BES2800·BES6100 / 展锐 W517 / 炬芯 ATS 系列**) NPU 只有 **1-4T**, 差老板要的 6T 一到六倍。
> ⇒ **必须降一项** (详见 §5 三条路径)。

## 4. 按"眼镜场景适配度"重排 (不是按算力排)

## 5. ★三条决策路径 (必须降一项) + 我的建议

| 方案 | 芯片 | 含义 | 代价 | 风险 |
|---|---|---|---|---|
| **A 保算力+资料** | **RK3576** | ⑨⑩⑧ 全保, 产品定义不变 | V1 功耗 ⇒ SoC 挪镜框 + 主板分体; V2 封装 ⇒ 板框重排 | ★功耗 [推算] 未实测 ⇒ **可能直接违 43°C** |
| **B 保眼镜形态** | **V881 + 外挂 NPU** | 形态/功耗/DDR 全对 | 本地实时 YOLO 靠外挂 ⇒ **BOM+面积+两套 SDK**; 或改产品定义(只拍照+云端) | 外挂 NPU 的通信延迟吃掉 60ms 预算 |
| **C 保眼镜形态 + 双芯片** | **RK3576 (镜框主控) + V821/V881 (镜脚协处理器)** | ★**业内主流架构** (高通AR1+恒玄BES2700 / BES2800+外挂视觉芯片) | 两颗芯片两套 SDK + 跨铰链通信 | 跨铰链延迟风险 + 功耗账复杂 |

★**我的建议 (仍是 A, 但补一个前提动作)**: 理由不变 —— 老板锁死的核心是"端到端 <60ms 的本地实时 YOLO", B/C 都要么改产品定义要么加芯片;
