## 2. 三个必须现在就有答案的硬件卡点

### 卡点 A — ARS45 显示输出接口未确认 → 原理图必须能兼容两种接法

**事实**: "ARS45 原生带 MIPI-DSI TX" = **媒体二手报道**, 官网产品页只字未提显示接口, 且两家媒体转述口径不一致 (一家写 DSI, 一家不写), EET China 明确写的是 **DP1.4 RX (输入)**。证据等级 = **方案级媒体转述**, 非 datasheet 级。→ tracker §5.8 已降级为"未确认"。

**关键推论 (比 tracker 写的更狠一层)**: 如果 ARS45 **既没有 DSI TX, 也没有 DP TX**, 那它就没有任何视频输出口 → **不是"加颗桥芯片"的问题, 是显示链整体不成立**, 必须换 SoC 或换显示方案。**当前没有任何公开信息能区分这两种情况。**

#### 我的原理图对策 (不锁死任何一条路)

**设计原则: 光机侧连接器是固定接口, 驱动路径可换。**

```
                    ┌──────────── 方案 A (原生 DSI TX) ────────────┐
   SoC DSI_TX ─────┤                                              ├─→ [固定光机连接器]
   (若存在)        └──────────────────────────────────────────────┘   MIPI-DSI + I2C
                                                                            │
                    ┌──────────── 方案 B (DP TX + 桥接) ──────────┐      │
   SoC DP_TX ───────┤ [0Ω/DNP] ─→ [桥接芯片] ─→ DSI TX ──────────┼──────┘
   (若存在)        └──────────────────────────────────────────────┘
```

**具体落到 PCB 上的动作**:

1. **光机连接器先定死**: 定义一个板对板/FPC 座, 包含: DSI CLK lane + DSI Data lane(2/4 lane 待定) + I2C(SDA/SCL) + 光机所需各电源轨 + RESET + GND。**光机侧不动** → 波导/光机选型不被卡。
2. **SoC 侧留双出口**: 原理图上同时画出 SoC 的 DSI_TX 组和 DP_TX 组, 各自接到**不同的连接器或不同的 0Ω/DNP 器件**; 由 BOM 上的"装/不装"决定走哪条。**不可在原理图阶段把其中一条画成 NC。**
3. **桥接芯片落位策略 (两个方案, 待结构空间确认后二选一)**:
   - **方案 B1 (推荐, 若镜脚空间允许)**: 桥接芯片直接放主 PCB → 走线短, 无额外连接器, 少一个故障点。
   - **方案 B2 (若空间不够)**: 桥接芯片做在**独立小板 (显示转接板)**, 主 PCB 出 DP TX + I2C, 小板出 DSI → 用**同一组连接器**与主板/光机对接。好处: 主 PCB 面积小, 换 SoC 时只换小板。
   - ⚠️ **B1/B2 都需要 mech-lead 的镜脚面积预算才能定** → 已列入我的信息需求清单。
4. **DP 侧的隐藏坑 (现在就要预留)**: DP 链路除主 link (4 lane × 差分) 外还需要 **AUX 通道 (2 pin) + HPD (1 pin)**, 且多数 DP-to-DSI 芯片需要 **DP 侧重驱动/均衡 (redriver/retimer)** 才能过 SI/眼图。**这些 pin 和器件现在就得在 PCB 上占位**, 否则将来加桥接芯片要改板。
5. **时间上的取舍**: 桥接芯片采购周期 4-8 周 (tracker R4/R8), **不能等原厂回复** → 桥接芯片询价必须**并行启动**, 不能等 Q16 落地。

**降级判据 (给项目总工一个决策规则)**:
- Q16 答"有 DSI TX, ≥800×600@60" → **方案 A 为主线**, 桥接芯片仅作备份 (但仍需选定一颗候选以防万一)。
- Q16 答"只有 DP TX (无 DSI TX)" → **方案 B 为唯一主线**, 立即锁定桥接芯片并进 BOM。
- Q16 答"只有 DP RX, 无任何 TX" → **架构级阻塞**, 立即上报项目总工 + 老板 (不是硬件能解的题)。

### 卡点 B — FCCSP 8×10mm 逃线可行性 (一票否决项)

**当前数据**: 只有封装尺寸这一个数字 —— "8×10mm FCCSP" (tracker §2)。**球间距 (ball pitch) 未确认, 引脚图未确认 → 现在无法给"可行/不可行"结论。**

#### 评估框架 (拿到 pitch 和 pinout 就能判)

**判据 1 — 逃线工艺门槛 (行业通用规则, 非 ARS45 数据)**:

| 球间距 (pitch) | 常规 4-6 层板可行? | 所需工艺 | 结论 |
|---|---|---|---|
| **≥ 0.40 mm** | ✅ 可行 | 4 mil (0.1mm) 线宽 + 0.1mm 钻孔通孔, dog-bone 逃线 | 常规工艺, 无异议 |
| **0.35 mm** | ⚠️ 极限 | 需 3 mil 线宽 + 0.075-0.1mm 钻孔, 良率与加工费上升 | **需要 PCB 厂书面确认工艺能力** |
| **≤ 0.30 mm** | ❌ 不可行 (与 4-6 层锁死冲突) | 需 HDI 激光微孔 + 叠层增层 | **一票否决** — 违反 §0/§2.2 层数锁死 |

> 关键含义: **"4-6 层" 这个锁死值, 实际上是通过"pitch ≥ 0.4mm" 来决定 PCB 能否做出来的。** pitch 是 SoC 选型的一票否决项, 不是工艺细节。

**判据 2 — 引脚预算 (需要逃出的信号)**:

| 组别 | 需要的 pin 数 (估) | 说明 |

| MIPI-CSI 输入 | 1 lane=4 / 2 lane=6 / 4 lane=10 | lane 数取决于 datasheet |

| USB 2.0 | 4 | |
| I2C | 2 (+上拉) | sensor + 光机共用或分路 |
| JTAG | 4-8 | |
| RESET / BOOT / GPIO | 6-10 | |
| 音频 | 0 (未确认) | tracker 未提 |
| **合计 (不含电源/地)** | **≈ 35-55** | 逃线难度主要看这个数 |

**判据 3 — 逃线层数需求**:
4 层板 → 只有 2 层信号层, 35-55 根高速/信号 + 电源逃线会**极度紧张**;
6 层板 → 3 层信号层 (L1/L3/L5) + L2/L4/L6 参考地/电源, **这是我的目标叠层**, 需要 PCB 厂确认 6 层的阻抗控制能力 (MIPI 100Ω 差分 + 单端 50Ω)。

**判据 4 — 电源逃线 (容易被忽略)**: FCCSP 的电源/地球数通常占 30-50%, 必须用 **大面积过孔阵列 + 平面层直供**, 而不是逐球走线。**散热焊盘 (若有) 还要分割成多块供不同电源轨** → 需要 datasheet 才知道焊盘是整块还是分块。

**我现在能做的 (不靠猜的部分)**:
1. **把 pitch 写成 SoC 选型的一票否决条款**, 列入给原厂的追加问题。
2. **提前锁定 PCB 工艺能力 (在拿到 pitch 之前)**: 与 PCB 厂确认 "6 层 / 3 mil 线宽 / 0.1mm 钻孔 / 阻抗控制 ±10%" 的报价与良率 → 等 pitch 出来当天就能判定。
3. **准备 6 层叠层草案** (L1 信号 / L2 GND / L3 信号 / L4 电源 / L5 信号 / L6 GND), 供拿到 pitch 后立即代入核算。

**我现在不能做的**: 没 pitch 就给"逃线可行/不可行"结论 —— 那是拿经验值冒充实测, 不做。

### 卡点 C — 电源树峰值电流

**当前数据**: tracker §3.4 给的整机功耗区间 **0.95~2.0W 是推算** (基于 ARS45 "<300mW @1080p30 录像" 公开口径外推), **没有任何实测**。而 **SoC 各电压域的电压/电流上限完全未知 (无 datasheet)**。

#### 我先把能算的算清楚 (全部为推算, 标注来源)

**Step 1 — 整机功率区间 (引用 tracker §3.4, 推算)**

| 模块 | tracker 推算 | 证据等级 |
|---|---|---|
| SoC (1080p@60 + ISP + OD 持续) | 500-900 mW | 推算 |
| DP→DSI 桥 (若需要) | 100-300 mW | 推算, 芯片差异极大 |
| 光机 (走鹃Ⅱ 自身) | **98 mW** | ✅ 官方 (JBD 官网) |
| 光机 + 一拖二 + 波导 系统端实际 | tracker 记 200-500 mW | 推算 (含分光/波导损耗) |
| sensor + 存储 + 电源转换 | 150-300 mW | 推算 |
| **整机合计** | **0.95 ~ 2.0 W** | 推算 |

**Step 2 — 折算成电池电流 (1S 3.7V 标称)**

| 场景 | 整机功耗 | 电池电流 | 1h 续航所需电池容量 (100% 可用) | 加 20% 余量后 |
|---|---|---|---|---|
| **无桥接** (原生 DSI), 低功耗端 | 1.0 W | 270 mA | 270 mAh | ~340 mAh |
| **无桥接**, 高功耗端 | 1.7 W | 460 mA | 460 mAh | ~575 mAh |
| **有桥接**, 高功耗端 | **2.0 W** | **540 mA** | 540 mAh | **~675 mAh** |

**Step 3 — 结论 (硬件层面的硬约束)**

🔴 **结论 C-1: "要不要桥接芯片"不只是 BOM 问题, 是电池体积档位问题。**
- 无桥接 → 电池 **~340-575 mAh**
- 有桥接 → 电池 **~575-675 mAh** (直接顶到镜脚空间上限)
→ **这条必须立刻交给 mech-lead 做空间验证**, 否则 Q16 迟迟不回, 结构那边也没法开工。

🔴 **结论 C-2: 峰值电流不能只按均值算。** NPU 推理是突发负载 (640×640 INT8 推理 ~15ms/帧, 60fps), 每帧都有一个电流台阶。DC-DC 必须按**峰值**选型, 并用输出电容吸收台阶造成的电压跌落。
- **给 PCB 厂的约束**: 核心轨 DC-DC **额定电流 ≥ 均值 ×1.5**, 且**负载跃变响应**指标必须在选型时被写入 (这一项常被忽略, 表现为"静态功耗达标, 一跑 OD 就掉电重启")。
- **给软件的约束**: 需要 sw-lead 给出 OD 的**帧间负载曲线** (是否连续推理 / 是否双缓冲交替), 这直接决定电容数量。

🔴 **结论 C-3: 电压域清单现在写不出来, 原理图不能开工。**
需要 datasheet 给出: 各电源轨名称 / 电压 / 典型电流 / 峰值电流 / 上电顺序 / 电压容差 / 负载开关需求。
→ **在拿到之前, 我能做的极限工作是**: 定下顶层骨架 (电池 → 保护 → 充电 → DC-DC → 各轨分配) 和接口层的**去耦策略 / 大电流铜箔策略 / 测试点策略**, 标成占位。

🔴 **结论 C-4: 充电时间与电池容量是联立约束。**
460 mAh 电池若要 1h 充满 → 充电电流 ≥ 460mA + 充电损耗 (约 ×1.2) → **约 550mA**, **必须超过 USB 2.0 默认 500mA**。所以:
- 要么走 **Type-C PD (5V/2A)** → 需 PD sink 芯片, 1h 充满没问题;
- 要么接受 **5V/900mA (Rp 默认) → 1.2-1.5h 充满**;
- 电池若到 675 mAh (有桥接), 5V/900mA 需 **1.1h**, 5V/2A 需 0.5h。
→ **建议: 上 Type-C PD sink (5V only, 2A), 成本几块钱, 一次性解决充电时间 + 兼容性 + "电脑 USB 口供电能力差异"三个问题。** 但采购走 main (红线: 不单独对外)。

🔴 **结论 C-5: 系统端没有电源监测 = 调试期会浪费大量时间。**
建议预留: **电源开关 (load switch 或 P-FET 软关断) + 电流采样 (分流电阻 + 放大或直接测脉冲) + 电量计 (可选)**。理由:
- 眼镜整机装在镜脚里, **没有物理开关** → 调试时必须能硬断电 (挂死/漏电时唯一手段);
- Q4 (续航 1h 是持续跑还是按需触发) 未答 → 电流采样能让你们在板上直接测出真实功耗曲线, 不用拆眼镜;
- 1 台样机, 加这几十块钱完全值得, 省的是**拆机时间**。
