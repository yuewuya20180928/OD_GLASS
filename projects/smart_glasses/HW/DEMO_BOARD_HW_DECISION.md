## 0. 一句话定案

★**demo 分两步走, 但硬件方案一次定死**:
- ★**Step1 (立刻能跑, 零 PCB)**: ★**用公开 SBC 当载体** (Forlinx OK3572-C 这类 RK3572 单板, 公开规格/原理图齐全) + **IMX415 camera 模组** (公开 MIPI-CSI) + **视涯 0.49" 屏模组** (公开 MIPI-DSI) ⇒ ★**软件链路本周就能开始跑**
- ★**Step2 (产品形态, 硬件自研)**: ★**一块主板** = **RK3572 核心板 (SOM) + 两个 FPC 座** ⇒ sensor 模组与屏幕模组各用 **FPC 软排**连到主板 ⇒ ★**主板不碰 SoC 球位号 (TBD-01 由此解除阻塞)**

## 1. ★★ 问题一: sensor 和主板之间怎么连

| 项 | **决定** | 依据 |
|---|---|---|
| **器件** | ★**IMX415** (3840×2160@60 可裁 1080p60) | 19:29 判据: 规格 ✔ + 数据来源 10/10 (主线驱动 + RK BSP 驱动 + rkaiq isp3x 现成 IQ) |
| **封装形态** | ★**camera 模组** (sensor + 镜头 + 支架 + FPC 出线), **不带 LDO** | 老板 19:25「sensor 画成模组」; ★**电源集中在主板** (统一噪声/接地/可测) |
| **连接器** | ★**主板端 FPC 座, 0.5mm 间距 24p** (翻盖式, 贴板) | 公开同类: 31p/0.3mm (4-lane CSI) 与 15p/1.0mm (2-lane CSI); ★**demo 只需 2-lane ⇒ 24p 够** |
| **FPC 长度** | ★**≤ 60mm** (主板内走线, **不跨铰链**) | 老板 19:25 不做结构 ⇒ 取消跨铰链 |
| **信号分配 (24p)** | ★**MIPI-CSI 2-lane (4p: D0P/D0N/D1P/D1N) + CLK (1p) + MCLK (1p) + SCCB SCL/SDA (2p) + RESET (1p) + 电源 3 轨 (3p) + GND (≥8p 兼作回流/屏蔽)** | 2-lane 带宽够: 1080p60 RAW10 = 1.244 Gbps ⇒ 2 lane @ ~700Mbps/lane (RK3572 CSI D-PHY 2.5Gbps/lane) |
| **AC 耦合电容** | ★**放模组侧 (紧贴 sensor)**, 主板不装 | 主板只走可控阻抗差分; ★**写进采购硬判据** |
| **供电** | ★**主板供**: 数字 (VDD) / IO (VDD_IO) / 模拟 (VAA+VAA_PIX) ⇒ ★**具体电压以公开 datasheet 为准** (IMX415 公开口径约 1.0~1.2V 数字 + 1.8V IO + 2.8V 模拟) ⇒ **ISS-148 的 facts 落定后改网表三条轨** | 现有网表三条轨 (SENSOR_CORE 1.2V / SENSOR_VDD_IO 2.8V / SENSOR_AVDD 2.8V) 是**按 AR0234CS 写的, 必须重核** (ISS-150) |
| **I2C 总线** | ★**camera 用 I2C_A, display 用 I2C_B ⇒ 分开** | 避免地址冲突/互相拖累 (SCCB 0x1a vs 面板 DDC) |
| **模式** | ★**sensor 侧窗口化出 1920×1080@60** (不是 ISP 裁) ⇒ 124 MP/s, ISP 余量充足 | 8.4MP@60 = 505 MP/s 会超 250 口径; ★**不违反 10-25「禁 ROI」** (降分辨率不改 FOV) |

**★ 采购硬判据 (camera 模组, 随货必须给)**:
① IMX415 + 镜头 + 支架, ★**0.5mm 24p FPC 出线** ② **1080p60 模式的寄存器表/配置序列** (随货给! 不需要问厂家) ③ **AC 耦合是否内置** ④ 供电电压/电流清单与上电时序 ⑤ SCCB 地址 ⑥ 是否含 IR filter ⑦ FPC 弯折寿命与插拔次数.

## 2. ★★ 问题二: 主控芯片在主板上怎么放

| 项 | **决定** | 依据 |
|---|---|---|
| **形态** | ★**主板不焊 SoC, 用 RK3572 核心板 (SOM) 焊在主板上** (或插座, 视模组厂提供) | ★**RK3572 球位图官方未到 (TBD-01) ⇒ 焊裸芯片主板画不出来**; ★**SOM 路线让主板完全绕开球位图** ⇒ **TBD-01 对 demo 板不再是阻塞** |
| **公开可行性** | ★**有货且公开**: Forlinx **OK3572-C** (RK3572 SBC: 4×MIPI CSI / 1×MIPI DSI 4-lane / HDMI 2.1) · ArmSoM RK3576 SBC · DFRobot RK3576 核心板 ⇒ ★**Step1 直接用 SBC 当载体, 零 PCB** | 公开规格页 + 公开原理图 (开源渠道 ✔, 不违反不发邮件) |
| **主板上的位置** | ★**SOM 放在板中部偏一侧**: ①**散热面朝下**贴导热垫/铜箔 (demo 阶段用外壳导热即可, 不做结构) ②**camera FPC 座与 display FPC 座放在 SOM 的同侧或相邻侧** ⇒ ★**MIPI 差分走线短、直 (≤60mm)、不跨分割** ③ CSI/DSI 差分对各走一边, 中间用地/电源隔开, 100Ω 差分阻抗 ④ **FPC 座朝板外缘**, 便于模组侧插拔与走线 | 高速差分走线规则 (公开可查的 RK 参考设计通则) |
| **主板供电** | ★**USB-C 5V 输入 → 3.3V (SOM 核心) + LDO 组 (1.0/1.2V 数字 · 1.8V IO · 2.8V 模拟/面板驱动板)** ⇒ ★**demo 不装电池、不上充电电路** (充电 IC 位置留 DNP 占位) | 老板: demo 不考虑功耗 / 不做结构; 目标是**跑通链路** |
| **主板最小集 (BOM)** | ★SOM + USB-C 5V 输入 + 3.3V LDO + 3 个 sensor/panel 相关 LDO (1.0/1.2V · 1.8V · 2.8V) + **camera FPC 座 (0.5mm 24p)** + **display FPC 座 (0.5mm 20p)** + I2C_A/I2C_B + 调试 (USB-UART + JTAG) + BOOT/RESET 按键 + 状态 LED + (DNP) 充电 IC 位 | demo 只需跑通链路 |

★**一条必须说清的取舍**: ★**"一块主板 + 两模组"是 Step2 的产品形态; Step1 用公开 SBC** ⇒ ★**Step1 不画板也能跑, Step2 的板子等 Step1 验证过再画** ⇒ ★**这样"敲定硬件方案"与"尽快出画面"不冲突**。

## 3. ★★ 问题三: 屏幕模组和主板之间怎么连

| 项 | **决定** | 依据 |
|---|---|---|
| **器件** | ★**视涯 0.49" 1920×1080 SiOLED 面板 + 驱动板 = 一个"屏幕模组"** (FPC 出线) | 老板 19:25「屏幕驱动板也画成模组」 |
| **连接器** | ★**主板端 FPC 座, 0.5mm 间距 20p** (翻盖式) | 4-lane DSI 8p + DDC 2p + 电源 + EN + GND ⇒ 20p 够 |
| **信号分配 (20p)** | ★**MIPI-DSI 4-lane (8p) + DDC SCL/SDA (2p) + 3.3V (1~2p) + RESET/EN (1p) + GND (≥6p)** | 公开 DSI 4-lane 配法 |
| **带宽** | ★**1920×1080@60 RGB888 ≈ 373 Mbps payload ⇒ 4-lane 绰绰有余 ⇒ demo 不需要 DSC** | RK3572 DSI 1.2 4-lane ✔; ★**面板支不支持 DSC 随模组给说明, 但 demo 不依赖它** |
| **init code / 时序** | ★**不外发问询 ⇒ 写进采购硬判据**: 模组必须随货给 **init code (寄存器序列) + DSI 时序参数 + DDC 地址 + 供电/电流清单** ⇒ 主板侧只需在 Rockchip panel 框架里加一个 panel 节点 (公开框架, 无需厂家) | 老板 19:25③ + 规则④ (厂家专属信息 → 采购硬判据) |
| **供电** | ★**3.3V 由主板供**; 若驱动板另需 5V ⇒ ★**从 USB-C 5V 直接引一路** (demo 无电池) | 公开的面板驱动板供电口径 (3.3V 逻辑 + 可选 5V 面板轨) |
| **单色/全彩** | ★**demo 一律按单色/灰阶处理** (画框走 Y 平面、双色描边) ⇒ **不阻塞** | 单色/全彩未定 (原 ISS-132) ⇒ 规格侧已写"彩色框等面板答复后启用"; ★**不外发 ⇒ 就按最保守做** |

**★ 采购硬判据 (屏幕模组, 随货必须给)**: ①0.49" 1920×1080 面板 + 驱动板一体, ★**0.5mm 20p FPC 出线** ② **init code + DSI 时序 + DDC 地址** ③ 供电电压/电流/上电时序 ④ 单色 or 全彩、亮度/色度口径 ⑤ 有效显示区尺寸 ⑥ 是否需要 TE 同步脚。

## 5. ★ 网表要改什么 (ISS-149 / ISS-150 照此执行)

| # | 改动 | 落点 |
|---|---|---|
| N1 | ★**camera/display 改成板内 FPC 座** (不再跨铰链) ⇒ `CONN_CAM` / `CONN_LIGHT` 去掉 HINGE 板级归属 | `state/gen_netlist.py` (板级归属列) |
| N2 | ★**CSI 走 2-lane** (只画 D0/D1 + CLK) ⇒ 原来 4-lane 的位号要减 | `gen_netlist.py` P5 页 |
| N3 | ★**三条 sensor 轨按 IMX415 重核** (数字/IO/模拟) ⇒ `HW/SCHEMATIC_V1_SPEC.json` 的 power_rails 是真源 | ISS-150 (等 facts) |
| N4 | ★**I2C 分离**: camera = I2C_A, display = I2C_B (现网表已是两条, 只需确认上拉电压按各自 IO 轨) | ISS-150 |
| N5 | ★**充电板并板 / demo 直接 USB 供电** ⇒ `J_CHG` 不再跨铰链, 充电 IC 与电池位改 DNP 占位 | ISS-149 |
| N6 | ★**新增两个 FPC 座位号** (0.5mm 24p / 20p) + 对应 net 与测试点 | ISS-149 |
| N7 | ★**去掉跨铰链相关的铰链区堆叠/净空判据** (结构不做 ⇒ 24mm 铰链区约束不适用) | `check_netlist.py` 里那条判据要改成"板内 FPC 走线长度 ≤60mm" |

## 6. ★ 20:3x 两条采购口径更正 (来自 ISS-151 替代料清单, 实测公开现货)**:
- ★**C3: "0.5mm/24p" 在公开现货里基本不存在** —— 公开在售 camera 模组的 FPC 实际是 **31p/0.3mm (4-lane CSI)** / **RPi 15p/1.0mm (2-lane CSI)** / 22p/0.5mm ⇒ ★**本文件 §4 的两块 FPC 针位表是「自研目标规格 (Step2)」**; ★**demo 阶段 (Step1) 直接用公开现货规格的模组**, 两边对不上就以现货为准, 别硬凑。
- ★**C4: 公开现货的 MIPI-DSI 一体屏最高只到 1200×1920 (Radxa 10 FHD)** ⇒ ★**"1920×1080 视涯 SiOLED" 没有公开对标品** ⇒ ★**demo 阶段用 8HD / 10FHD 这类公开现货屏验链路即可, 视涯屏单列为风险项** (等 init code / 采购)。
- ★**init sequence 现成范例**: `rk3576-evb.dtsi` 里有 **1080×1920 / 4-lane / RGB888 的完整 panel-init-sequence** (与视崖屏分辨率最贴) ⇒ ★**面板这条路的起点不是"问厂家", 是"抄内核里的现成 dts"**。
