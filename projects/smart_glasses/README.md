### 通信规则 (硬规则)
- **三个总工之间不做直接沟通** —— 技术上已用 per-agent `tools.deny: ["sessions_send"]` 禁止, 不是靠自觉
- **三个总工只与项目总工通信**: 下达用 `sessions_spawn(agentId=...)`, 回收用交接单 + 完成回执
- **需要横向沟通时**: 写"接口请求"交接单给项目总工, 由项目总工组织三方评审 —— 控制权始终在项目总工
- **但产出区互相可读** —— 硬件的 PCB 尺寸结构总工能直接读到, 不用传话。**堵死的是"对话", 不是"信息"**

## 铁律 (全员)
1. **不做任何假设** — 疑问点/风险点必须主动提出, 不脑补不推演
2. **进度问题必做 sync** — 不扫文件就给答案 = 错情报
3. **不推断** — 区分"我观察到了" vs "我推测是"
4. **对外不单独行动** — 邮件/供应商/采购全部经项目总工
5. **证据分级** — 官网 brief < datasheet < 原厂书面答复 < 方案级媒体转述
6. **一次错误结论 = 一个凭空模块 + 一个采购周期 + 一条延迟项**

## 📊 共享状态源: STATE.yaml (老板 2026-25 指示)

```bash
python3 state/merge.py                # 刷新共享快照 (纯函数, 无锁, 谁都能跑)
python3 state/merge.py --for hw-lead  # 你的切片: 谁在等我 / 我欠谁 / 冲突
python3 state/test_merge.py           # 合并器自测
```

| 文件 | 谁写 | 是什么 |
|---|---|---|
| `STATE.yaml` | 合并器生成 | **当前状态快照** (机器可读): 做到哪/卡在哪/在等谁/接口值/冲突 |
| `state/fragments/<id>.yaml` | **每个总工只写自己那一个** | 你的状态分片 (进度/产出/阻塞/needs_from/answers/interface_claims) |
| `state/merge.py` | 项目总工 | 合并器: 原子写 + needs×answers 配对 + 冲突检测 + lint |
| `PROJECT_TRACKER.md` | **只有项目总工** | **决策与理由真源**: 锁死变量/决策记录/证据链 |
| `INTERFACES.md` | 项目总工 | 跨模块接口契约 (星型拓扑的配套) |
