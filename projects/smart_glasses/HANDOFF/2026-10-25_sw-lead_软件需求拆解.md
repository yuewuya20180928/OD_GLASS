## B1 结论摘要

> 口径: 端到端 = **口径A (sensor 曝光开始 → 光机出光)**, 即 AGENTS.md 写的最严口径。Q1 未拍板前, 三口径对照见 §10.4。

1. **8 个软件模块 / 52 条验收标准**, 每条都是可测判据 (M1-R1..R8 / M2-R1..R6 / M3-R1..R6 / M4-R1..R6 / M5-R1..R8 / M6-R1..R6 / M7-R1..R6 / M8-R1..R6)。
   ⚠️ **[v2 自证更正] 首轮我写的是 "48 条", 实际 52 条 (少计 4 条) —— 复现命令见 B6-5。**
2. **端到端 (口径A, 60fps 异步模式) = 67.0ms, 超 60ms 硬指标 7.0ms → 不达标**。同一套硬件在 "显示等 OD" 模式是 55.7ms, 但**代价是显示帧率掉到 25.6fps** (§3.3 的 "42-45ms 达标" 没写这个代价)。
3. **漏算项是框龄 (age), 不是加法算错**: `age = ceil(T_od / 16.67ms)`, 是**台阶函数** —— 纯 NPU 从 10ms 涨到 11ms, 端到端从 **50.3ms 跳到 67.0ms (+16.7ms)**。"INT8 输出能否直通" 这一件事就值 16.67ms 预算。
4. **512MB 内存不是瓶颈**: §12.1 表行逐行相加 = **175.1MB (乐观) / 187.9MB (悲观)**, 占 512MB 的 34-37%, 余量 ~324-337MB。
   ⚠️ **[v2 自证更正] 我原先写 178/191MB (交接单里还写过 "~180-190MB"), 与表行相加差 2.9-3.1MB (疑似显示帧 buffer 行 2.9MB 被重复计入) —— 复现见 B6-4。结论不变, 但精确数字以逐行相加为准。**
5. **A7S 复用 32 项**: 直接搬 10 / 逻辑复用 4 / 完全不带 11 / 方法论复用 7。其中 **`cyl_iou_nms` + cylindrical 0.40 阈值明确不带** —— 那是 A7S 的场景定制, 与锁定变量 #2「80 类通用模型」冲突, 用通用逐类阈值回归解决。

## B3 证据分级

> 四档全项目通用: **[实测]** = 我自己跑出来的 · **[官方]** = 原厂/官网书面口径 · **[推算]** = 由前两档推导 (**写清推算过程**) · **[0数据]** = 拿不到, 标出来, 不装作有数。
> ⚠️ 前提: **本项目一个 ARS45 板端实测数都没有** (还没投板)。下面标 [实测] 的全部来自 A7S / A733 两个**不同平台**, 只作方法论与量级参照。

| 关键结论 | 等级 | 依据 / 推算过程 |
|---|---|---|
| 端到端 **67.0ms** (口径A, 模式B 60fps) | [推算] | 推算链: 帧周期 P=16.67 (锁定 #6 1080p@60) → T_od = S4+S5+S6+S7 = 1+16+2+3 = 22ms → age = ceil(22/16.67) = 2 → 端到端 = (2+1)×16.67 + S3(8) + S8(1) + S9(3) + S10(5) = **67.01ms**。其中 S5=16 取自 RK3588 15.1ms 横评 (乐观值), S6=2 是"INT8 直通"目标值, S10=5 是占位 |
| 端到端 **83.7ms** (悲观 age=3) | [推算] | 同上: T_od = 1+20+9.3+5 = 35.3 → age=3 → (3+1)×16.67+17 = **83.7**。S6=9.3 由 A733 实测反量化外推 |
| 端到端 **55.7ms** (口径A, 模式A 显示等 OD) | [推算] | 16.67+8+22+1+3+5 = 55.67; 显示帧率 = 1/(S3+T_od+S8+S9+S10) = 1/39 = **25.6fps** —— 这是"达标"的代价, §3.3 没写 |
| 端到端 **42.3ms** (口径C, 模式B) | [推算] | 67.0 − 24.67 (曝光 8.3 + 读出 8.3 + ISP 8.0) = 42.34。**口径本身还没拍板 (Q1)** |
| **NPU 纯硬件耗时 (S5)** | **[0数据]** | 原厂**从没公开跑过 YOLO** (讯飞 2026-05-28 那台 ARS45 眼镜跑的是语音/翻译/唇语/降噪, 不是检测)。公开只有 "6 TOPS" 标称值 —— **标称 TOPS 不能用来推延迟**。唯一参照: RK3588 15.1ms / RK3576 15.4ms [官方·Rockchip model_zoo 公开横评, **口径未标明**] + A733 27.19ms [实测·他平台] → 推算区间 15-20ms, **投板前任何"能跑 60fps"的结论都没有依据** |
| **光机逐帧延迟 (S10)** | **[0数据]** | JBD 走鹃Ⅱ 官网只有 480Hz 刷新率, **没有任何逐帧延迟数值**; 我表里的 5ms 是**占位, 不是数据**。光机出光无法软件打点 → 必须高速摄影 (≥240fps) 或示波器 (§11.4 M-1/M-2) |
| 显示 TX 3ms (S9) | [官方] | 原厂公开口径, 但属**方案级宣传语** (松山湖演讲), 非 datasheet 规格; **若走外挂桥接芯片此值作废** |
| ISP 段合计 <10ms (S3+S9+S11) | [官方] | 原厂 "Sensor 输出→显示屏出图 <10ms"; 拆成单段 8ms 是我的拆分 → 该拆分属 [推算] |
| 内存 175.1 / 187.9MB | [推算] | §12.1 共 12 行逐行相加 (B6-4 可复现); 其中 SDK workspace 20MB、堆余量 30MB **是估的, 无数据**; NPU workspace 若膨胀到 50-100MB 结论会变 (§12.4) |
| A733 纯 NPU 27.19ms / SDK 总 36.51ms / 反量化 9.29ms (占 25%) | [实测] | 我方 A733 板端, **不同平台**; 直接套到 ARS45 属外推 → 由此派生的结论按 [推算] 记 |
| A7S: 线程模型 19.83→29.78fps / ring buffer 反向拖累 29.66→24.5fps / `bgr.clone()` 0.5ms | [实测] | 我方 A7S (A733) 板端; **方法论可复用, 数值不可直接套 ARS45** |
| A7S 复用清单 32 项 | [实测] (清单本身) | §13.1-§13.4, 每项标了 v31 源码行号, 可逐条对照 |

## 3. ⚠️ 需要 PM 优先处理的三件事

### 3.1 【最高优先】延迟口径 (Q1) —— 不答就给不出达标结论

同一套硬件, 三种口径差 24.67ms:

| 口径 | 模式 A (显示等 OD, ~25.6fps) | 模式 B (异步 60fps, 乐观 age=2) | 模式 B (异步 60fps, 悲观 age=3) |
|---|---|---|---|
| A. **曝光开始 → 光机出光** | 55.7ms ✅ / 悲观 69.0 ❌ | **67.0ms ❌** | **83.7ms ❌❌** |

**AGENTS.md 的硬指标写的是 "sensor 曝光 → 光机出光"**, 即口径 A。在这个口径下:
