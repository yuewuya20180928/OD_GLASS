## B1 结论摘要

1. **台账落地**: 登记模型资产 **10 条** (3 条 ARS45 候选 + 7 条 A733 参考), 每条带 `sha256[:16]` / 字节数 / 许可 / 输入输出 shape / 算子类型 / NBG 头字段 / 状态机 (candidate·active·reference·quarantined)。复核脚本 `SW/tools/model_asset_check.py` 一次跑完 **60 项判定, rc=0**。**证据 [实测]**

2. **★ 查出 3 个"名字骗人"的资产 (同名不同内容)**: 三份都叫 `yolov5s-sim` 的 ONNX 体积完全相同 (29,337,706 B) 但 sha256 **三者互不相同**, 输入分辨率分别是 **320 / 320 / 640**; 其中 `_clean` 与 `_v2` **逐字节完全相同** (sha256 `340978ec59391f69`) → 文件名里的 "v2" 不代表版本差异。**由此立了 2 条硬规则: 模型唯一 ID + 版本只认 sha256 (路径/文件名一律不作数)**。**证据 [实测]**

3. **★ 许可栏是空的 → 2 个量产阻断项**: 3 条 yolov5s-sim 系 ONNX 的 `metadata_props` **一个字段都没有** (无 license/author/version) → 许可 **[0数据]** (阻断项 **L1**); 唯一带许可的 `yolov8s.onnx` = **AGPL-3.0** → 商用须向 Ultralytics 采购商业许可 (阻断项 **L4**)。工具输出 **放行阻断项 L=2**。**不解决 → 量产评审不许过**。**证据 [实测]**

4. **★ 2 条 .nb 资产是死的**: `yolov8s_coco80.nb` 与 `acuity_pipeline/network_binary.nb` 的 NBG 头 byte 8-11 = **0x10000020**, 而 A733 真实 chip ID 是 **0x1000003B** → 板端加载后报 SRAM size 错。已标 `quarantined` 隔离; 本地**可用**的 .nb 只有 3 条 (7.5 / 12.0 MiB, 全部 ≤ 板端 15 MiB 槽位)。**证据 [实测]**

5. **★ 交付边界说清楚**: 本单交付的是**台账 + 量化流程 + 精度评估方法 + 回归门禁**; **ARS45 板端 INT8 模型 = 0 个, 转换 0 次, 板端实测 0 次**。A733 侧完整可复现的 5 步量化流程 (P1 import → P2 quantize → P3 export nbg → P4 算子核对 → P5 deploy) 本机**全部可用** (ACUITY 6.30.22 + VivanteIDE 5.11.0 + 100 张校准集), 已作为 ARS45 的方法论模板登记; **P3/P4 两个脚本本机缺失** → 需从 A733 工程找回。**证据 [实测] + [0数据]**
