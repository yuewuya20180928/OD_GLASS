## B1 结论摘要 (6 条, 每条带数字)

1. ★★**PIN-SET-2 孔位 Y 两套互斥口径 ⇒ 仲裁成一套: 套 A** (Y 按中心线平移, 旧中心 7.50 → 新中心 15.00, **S 孔 ±5.00 不变**) = **P1(8.00,15.00) / P2(52.00,15.00) ⌀2.0 H7 + S1(8.00,10.00) / S2(52.00,20.00) ⌀1.4**; **套 B (S1 Y=2.50 / S2 Y=27.50) 否决**。两套**各差 7.50mm**, 不可能同时对。依据 (全部可复现, 见 §2 与权威表 §4):
   - ★**[实测] 打印包已经是套 A**: 纯 Python 解析 `MECH/print/temple_cage_revb.stl` (笼的 B 段 PCB 定位板, 板基线 Y=60) ⇒ **⌀2.4 让过孔 @(8.00,75.00)/(52.00,75.00) ⇒ 板坐标 (8,15)/(52,15); ⌀1.6 让过孔 @(8.00,70.00)/(52.00,80.00) ⇒ 板坐标 (8,10)/(52,20) = 套 A**; 同法解析 `fit_coupon_revb.stl` 的 L 段 PCB 样板 (基线 4/84) ⇒ **⌀2.4 @(12,99)/(56,99) ⇒ (8,15)/(52,15); ⌀1.6 @(12,94)/(56,104) ⇒ (8,10)/(52,20) = 套 A** ⇒ **若 PCB 按套 B 钻, M1.2 螺钉与笼的 ⌀1.6 让过孔差 7.50mm ⇒ 螺钉穿实心板 ⇒ 板装不进骨架/笼**;
   - ★**[实测] hw-lead 自己的三个产物已写套 A** (`hw.yaml` claim `pcb_mount_holes_xy` / `HW/hw_week_20261101_check.py:55` 的 `exp` / 他给结构侧的 needs_from `iss118_pcb_holes_30mm_y` **明写**「S 孔 ±5.00 不变」) ⇒ 套 B 是 `HW/pcb60x30_check.py` 一张 `HOLES` 表里的**单点孤例**;
   - ★**[推算] 套 B 的边距不可接受**: S 孔壁距板边 **1.80mm** (套 A **7.30mm**), 再叠加 ISS-049 §5 强制的「隔热垫 2 处螺钉位开 ⌀3.0 让位孔」⇒ 孔缘距板边只剩 **1.00mm** ⇒ 破边;
   - ★**[推算] 套 B 推翻骨架接口**: X=8/52 处骨架特征组从 **5.00mm 拉到 12.50mm** ⇒ 非 SoC 段须 ≥**17.50mm** (ISS-049 §4 写的是 ≥10.00mm) ⇒ 骨架加宽/增重/重出图;
   - 套 B 唯一优势 (压紧力矩对角力臂 12.50 vs 5.00mm) **可用「骨架端段加宽 + M1.2 加大预紧」单独取得, 不值得动已冻结的钻孔口径**。
   ⇒ **影响面**: 要改的只有 `HW/pcb60x30_check.py:113-117` + 重生成 `HW/pcb60x30_check.json` 的 `sec4_holes` (RK3588 + RK3576 **两段**); 打印包与量测清单 **不用改**。已登记 needs_from → hw-lead (key `iss192_pcb60x30_holes_set_b_to_set_a`)。
2. ★**假绿已修掉**: 旧 `pinset2_mech_check.py` 输出「复算项 31 | FAIL 0 | WARN 3」rc=0, 那是**一块 15mm 板 + RK3588 8×10 封装**上的绿灯。迁到 **60×30 + RK3576 17.20×16.10 + 套 A** 后: **复算项 38 | FAIL 0 | WARN 2 | rc=0**, 且 **4 孔 × SoC 逃线带 2D 重叠 = 0.0000 mm² (4/4)**、× 封装体 = 0.0000、× J_CHG keep-out = 0.0000、孔心到板边最小 **8.00mm**、孔壁距边最小 **7.00mm**、孔间中心距最小 **5.00mm** / 孔壁间距 **3.30mm**。
3. ★**判据不是只改常量, 是重推**: 原判据写「老口径 **3/3** 孔压逃线带 ⇒ 成立」, 而 60×30/RK3576 下实测只压 **2/3** (SoC 在 Y 向长高 8.00→16.10, 逃线带从 Y[2.70,12.30] 上移到 Y[6.15,23.85], 老孔 M1@Y2.50 掉出带外) ⇒ **计数随板宽变, 结论不变** ⇒ 判据改成**板宽无关**的「**≥1/3 压带 ⇒ 不可用**」, 并**另加两条板宽无关的独立判据** (① 单销定位链不足: 1 个 ⌀2.0 H7 无法同时约束 X 与 θz、无副销消过定位 ⇒ 必须双销; ② 边距余量偏紧, WARN 级留痕)。⇒ 判据不再依赖那个会变的计数。
4. ★**打印包契约三条 WARN 的现行值** (真源 = Rev B 生成器实际常量, 不再硬编码 Rev A 老值): `pcb_len=60.00` (= 板长 60 ✅)、`pcb_wid=30.00` (= 板宽 30 ✅)、销孔让过孔 ⌀2.4 **2 个**/板 (双销 ✅, 老口径单销是 1 个)、螺钉让过孔 ⌀1.6 **2 个**/板 (✅)。★旧判据的「孔距 40.00 (X=6/46)」是 **15mm 单排口径**的产物 ⇒ 改写成**逐坐标比对**: 打印包 `pinset2_p_y/s1_y/s2_y` vs PCB 四孔 Y ⇒ **差 0.00 / 0.00 / 0.00mm** (X 向间距 44.00 vs 44.00, 差 0.00) ⇒ **这条判据就是「两套口径并存」的根因防线**: 打印包与 PCB 差多少 mm, 脚本就报多少 mm (已在 `--self-test` 用例 5 验证: 把打印包改成套 B ⇒ 该判据立刻 FAIL)。
5. ★★**30mm 板宽带出一条新的结构账: 金属骨架重量全线超预算** (骨架段复算, 60×30/RK3576): SoC 沿板宽占 **16.10mm** ⇒ 横向热扩散通道 3.50 → **6.95mm/边 (×1.99, 这是板宽翻倍的结构收益)**, 但 SoC 段满宽 **30.00mm** 且满宽段长 **17.20mm** ⇒ 4 个候选**全部**超 `MECH_BUDGET` §2.4 B 的「+1~3g/对」预算: 满宽 **9.72g/对** (判死) / 台阶 t=1.0 **5.10** / 台阶 t=0.8 **4.08 (超 +1.08g)** / 铜 t=0.8 **13.53**; **石墨片也翻倍**: 60×30×0.30 = **1.08g/片 = 2.16g/对 > W11 上限 2g**。⇒ **骨架截面必须重做** (满宽段只到 SoC 投影 / 横向扩散交给石墨 / 材料分段) —— 属**预算裁**, 已登记 needs_from → main (key `iss192_mech_scripts_dead_constants_disposition`)。
6. ★**孤儿红治理 + demo 板零安装孔** (只报不改): `MECH/cross_review_check.py` **明确「不是闸」** (全项目调用方 = 0; 16 项里只有 7 项属结构侧) ⇒ 退出码改成**只反映 MECH-OWNED 判据** (本次 **rc=0**), 且 16 项**逐项标归属 + needs_from 键** ⇒ 每盏红项都有主人 (C-1/C-2/C-4/C-9/C-10/C-11/C-12 → HW-OWNED; C-8/C-14 → CROSS-OWNED, 已登记 `iss092_jdebug_cortex10_netlist_fix` / `iss089_typec_opening_and_print_pack` + `iss092_print_pack_rev`)。★demo 板 (`HW/PCB/demo_mainboard.kicad_pcb`, 160×100mm) **[实测] MountingHole footprint = 0 个**, 全板只有 **2 个 np_thru_hole** (都属 USB-C 座自身壳体柱); `params.json` 声明的 4 个 `[[3,3],[57,3],[3,42],[57,42]]` ⌀2.2 只跨 54/160 × 39/100mm 且 **(57,3) 距 `J_SOM_P1` 仅 6.8mm** ⇒ **60×45 时代遗留**; 网表 **0 行**含固定孔/keepout ⇒ 已登记 needs_from → main (key `iss192_demo_board_zero_mounting_holes_keepout`, 含结构侧建议: 产品板用 PIN-SET-2 四孔 + SoC 投影区 keepout X[13.70,33.50]×Y[5.65,24.35]; demo 板**推荐 (a) 删掉**那几个遗留坐标)。
