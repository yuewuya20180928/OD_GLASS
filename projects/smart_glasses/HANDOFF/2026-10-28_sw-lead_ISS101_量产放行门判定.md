## B1 结论摘要

1. **★ Apache-2.0 候选 TF→ONNX 实测跑通 (rc=0)**: `tf2onnx 1.16.1 + TF 2.20.0 --saved-model --opset 13 --signature_def serving_default` → 产物 12,259,298 B / opset 13 / **3304 节点 / 33 算子** / sha256[:16]=`8709cc23432340f6`。**转换链第 1 段不再是纸面问题**。证据 [实测]

2. **★ 发现并解决 NPU 致命问题: 74.7% 的图是 NMS 后处理**: 全图 **2465/3304 节点 (74.7%)** 属 `Postprocessor` 段, 含 `NonMaxSuppression(90)` / `TopK(2)` / `Range(2)` / `NonZero(1)` —— NPU 编译器**一律不支持**。自写 `SW/tools/cut_postprocessor.py` 裁到 `raw_detection_boxes`+`raw_detection_scores` → **299 节点 / 18 算子, 高风险算子归零**, 与全图输出 **max_abs_diff = 0.000e+00 (逐位相同)**。做法与本机 `awnpu_model_zoo/examples/yolox` 官方配方同构 (`onnx.utils.extract_model` 只留 3 路 head, 后处理外置 CPU)。证据 [实测]

3. **★ 动态 shape 是第二个拦路虎, 已修**: tf2onnx 输出 `[1,'unk__5514','unk__5515',3]` → NPU 编译器拒收。`SW/tools/fix_static_shape.py` 固化 → `[1,320,320,3]`, 与裁图版输出仍逐位相同 (0.000e+00)。证据 [实测]

4. **★ 第一组真实精度数字 (之前是 0 数据)**: COCO val2017 前 299 张, score≥0.3 / IoU=0.5 → **TP=907 FP=1099 FN=1261, P=0.4521 R=0.4184 F1=0.4346**; person 类 P=0.549 R=0.532。⚠️ 自写逐类匹配, **非官方 mAP**, 只用于同口径门限自比。证据 [实测]

5. **★ 修掉复核器自己的一个高危 bug (会误杀好模型 → 会导致错误架构决策)**: `model_asset_check.py` 的 C9 冒烟**硬编码 float32 造输入**, 而本模型输入 dtype 是 **uint8** → `INVALID_ARGUMENT` → **好模型被判成坏模型** (实测复现: FAIL=1 / L=1, 会让"Apache-2.0 路线不可用"这个结论凭空成立)。已改为按模型自己声明的 dtype 造输入, 修复后 FAIL=0 / L=0。证据 [实测]

6. **★ 放行门判据已写死进复核器 (可机械判)**: 新增 **C10/C11/C12/C13** + **L6/L7/L8** 三条阻断项; 五组判据 G1(许可) / G2(转换链产出物) / G3(实测精度) / G4(PC 侧推理) / G5(板端产物)。实跑 **资产 13 条 · FAIL 0 · rc=0 · L=0**; 并做了**反例验证**(注入缺陷 → 复核器立刻变红)。⚠️ **L=0 只覆盖 G1~G4; G5 (板端产物 + 板端实测) 仍 [0数据] 不满足**。
