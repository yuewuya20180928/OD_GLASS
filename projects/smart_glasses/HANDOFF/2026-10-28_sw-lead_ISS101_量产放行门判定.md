## B1 结论摘要

1. **两个清单必须分开看**: ①**交付集** (台账 `candidate`/`active`, 现在 **1 条**) 的门禁 = **L=0 (实测 rc=0)**;
   ②**量产可用模型清单** (真能上板出框的 OD 模型) = **0 个** ❌。工具输出原来写"✅ 可进量产评审"**过强**, 本单已改成
   "✅ 放行阻断项已清零 (★不等于有可用模型)" 并加显式提示。**证据 [实测]**
2. **量产可用 = 4 条同时成立**: ①许可闭环 ②有板端产物 (≤15 MiB + chip ID 匹配) ③板端实测通过 ④回归 R-01~R-14 全过。
   现在: 条件 1 只有交付集那条 Apache-2.0 满足; 条件 2/3/4 **一环没走完** (板端产物 0 个 / 无板 / 回归不可跑)。**证据 [实测]**
3. **★ 交集为空**: 唯一许可干净候选 `MOD-SSDMBV2-FPNLITE-320-COCO90-TFODAPI` (TF OD API SSD-MobileNetV2-FPNLite 320×320,
   `num_classes: 90` → 可用 80 类) 卡在 **TF SavedModel → ONNX → Art.Galaxy 三段都没跑过** = [0数据];
   唯一实测可推理的 `MOD-YOLOV5S-640-ARS45-SRC` (onnxruntime 冒烟 OK) 卡在 **AGPL-3.0 未采购 → 禁入交付物**。**证据 [实测]**
4. **★ 新增一条量产评审门禁**: 从本单起, 量产评审必须**同时**看 "L=0" **和** "量产可用模型清单非空", 缺一不可
   (L 只管交付集的**静态属性**: 许可/容量/chip/模型完整性; 不管**动态属性**: 能不能上板出框)。**证据 [推算]**
5. **补齐路径只有三条, 且共享同一个公共前置**: A 采购 Enterprise (条件 1, 10⁴–10⁵ USD [推算], 4–12 周 [推算]) ·
   B 换 Apache-2.0 栈 (条件 1+2, 许可成本 0 + 3–8 人日 [推算]; 首选 YOLOX-s: 80 类 + Rockchip 官方 model zoo 已有同族 NPU 转换配方) ·
   C 等原厂提供"许可由原厂承担"的预编译模型 (条件 1)。**三条路都还缺 Art.Galaxy 工具链 + ARS45 chip ID (条件 2/3)**。**证据 [实测]+[推算]**
