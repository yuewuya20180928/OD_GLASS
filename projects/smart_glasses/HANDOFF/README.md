# HANDOFF — 交接区

## 协议 (老板 10-25 定: 三个总工之间不做直接沟通, 全部经项目总工)
**所有交接单只写给项目总工 (`main`)。不写给其他总工。**

需要跟别的模块对齐的事, 写"接口请求"给项目总工, 由项目总工决定:
- 直接转达给对方
- 组织三方评审 (在 `INTERFACES.md` 里落一条)
- 或者由项目总工自己裁决

文件名: `HANDOFF/YYYY-MM-DD_<发起方>_<主题>.md`

## 模板 (v2 · 2026-10-25 项目总工质量门升级)

> **v2 变化**: 加了 **6 个必填验收块**。项目总工用 `python3 state/gate_check.py` 机械校验;
> **缺块 = 不通过 = 退回重写**。目的: 让交付质量**可判定**, 不靠"我看过觉得还行"。

```markdown
# [<发起方>→PM] 主题
- 发起方: hw-lead | sw-lead | mech-lead
- 日期: 2026-XX-XX
- 结论: 一句话
- 依据: 文件绝对路径 / 数据 / 链接

## B1 结论摘要        ← 必填 (3-5 条, 每条带数字)
## B2 验收标准自评     ← 必填 (逐条: ✅通过 / ❌不通过 / ⚠️未验 + 依据章节号)
## B3 证据分级        ← 必填 (每条关键结论标 [实测] / [官方] / [推算] / [0数据])
## B4 接口取值声明     ← 必填 (跨模块接口取值; 同时登记进自己分片的 interface_claims)
## B5 未决项与卡点     ← 必填 (需要谁回答什么 + 期望时限; 外部对象写明走谁)
## B6 自证复现命令     ← 必填 (别人能一条命令复现你的关键数字)

## 接口请求 (需要跟别的模块对齐时写这里, 不要自己联系)
- 对方: hw-lead / sw-lead | mech-lead
- 我的需求: ...
- 我的假设 (如果对方不回应, 我会按这个做): ...

## 待办: 需要项目总工做什么
## 阻塞: 缺什么信息 (明确写"需要老板/原厂回答 X")
```

### B2 验收标准自评 (示例)
| 验收标准 | 自评 | 依据 |
|---|---|---|
| 26 个硬件模块拆解齐全 | ✅ 通过 | HARDWARE_BREAKDOWN.md §1 表 26 行 |
| 5 项排除项有理由 | ✅ 通过 | 同上 §2 |
| FCCSP 球间距可判 | ❌ 不通过 | 原厂未给 (见 B5) → 已升级为选型一票否决项 |
| 电源域电压/电流上限 | ⚠️ 未验 | datasheet 未到 |

### B3 证据分级 (四档, 全项目通用)
| 等级 | 含义 |
|---|---|
| [实测] | 我自己跑出来的数 (板子/脚本/仿真) |
| [官方] | 原厂 datasheet / 官网规格 / 官方书面答复 |
| [推算] | 由 [实测]/[官方] 推导, **写清推算过程** |
| [0数据] | 拿不到, 标出来 (不装作有数) |

## 落盘 = 事实
- 产出区互相可读, 跨模块信息靠读文件, 不靠对话
- 硬规则: 三个总工的 `sessions_send` 已被配置层禁用, 互相发不出去
- 项目总工 → 总工: `sessions_spawn(agentId=...)`
- 总工 → 项目总工: 交接单 + 任务收尾摘要 (spawn 完成回执会自动回到项目总工)

## 写分片 (别用 open(w)!)
- **必须用 `python3 state/frag_write.py --agent <你的id> ...`** (原子写)
- 直接 `open(path,"w")` 覆盖 → 并发下合并器读到半截 → **整个域从快照里静默消失** (10-25 压测实测 99.6% 概率)
- 登记闭环: 回答了别人 → 写进自己分片的 `answers` (用对方的 key); 否则需求永远"未闭合"
- 声明接口取值 → 写进 `interface_claims` (value 写短规范值) → 冲突自动暴露

## 红线
- 不改 `PROJECT_TRACKER.md` 里"已锁死的变量"表 —— 那是项目总工的权限, 改之前必须先沟通
- 不发对外邮件 / 不联系供应商 —— 全部走项目总工
- 不直接联系其他两个总工 —— 要对齐就写接口请求给项目总工
- **一个 agent 同时只开一个写会话** —— 两个会话会互相覆盖分片 (10-25 压测实测丢失更新)
