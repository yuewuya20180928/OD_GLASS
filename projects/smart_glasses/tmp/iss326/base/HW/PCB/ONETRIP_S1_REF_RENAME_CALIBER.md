### ★3-1 · 反查加在哪一段 (★三处选一处★) ★

### ★3-2 · 映射表的权威来源 (★必须是【真源】, 不能是又一份副本★) ★

★★**答: ★**项目里已经有一个「口径单一真源」—— `state/gen_kicad_sch.py::kicad_ref()` (★L276-287★) 与它的一对 `kicad_ref_to_table()` (★L290-297★)★。而 ★**同一口径的精确反查层, `state/check_chain_content_anchor.py` 已经实现并已在生产跑着** (★`_kicad_ref_to_table()` L160-177 ★ + 调用点 L285-291★) ⇒ ★**本补丁必须【复用同一个口径单源 + 同一份兜底副本的写法】, 绝不许再写第三份** ★★

★**★具体口径 (★实测确认, `logs/iss314/12` 场景矩阵即按此跑★)** ★:

```python
# ★口径单源 (★state/gen_kicad_sch.py::kicad_ref()★)
def kicad_ref(ref):
    r = (ref or "").strip()
    if r and r[-1].isdigit():
        return r          # ★末字符是数字 ⇒ 原名不动 (含原生 R_BAT_DET_1 / X1 / J_SOM_P1)★
    return r + "_1"       # ★否则加 _1 (含 J_USB_C → J_USB_C_1)★
```

★**★关键性质 (★实测, `logs/iss314/sb09` 的单射校验★)** ★:
- ★**对末字符是数字的 ref 是【幂等】的** ⇒ ★**`R_BAT_DET_1` 映射到 `R_BAT_DET_1` (不是 `R_BAT_DET`) ⇒ 原生 `_1` 的件不会被误反查** ★
- ★**映射表 = `{kicad_ref(t): t for t in 表侧 ref 全集}` ⇒ 【图上位号 → 表侧 ref】精确映射, 不是模糊匹配** ★
- ★**★必须校验【单射】(★实测: 现行 218 个表侧 ref 映射后无碰撞★) ⇒ 若表侧同时存在 `R_BAT_DET` 与 `R_BAT_DET_1`, 两者都映到 `R_BAT_DET_1` ⇒ ★**字典推导会静默丢掉一个器件 ⇒ 必须显式判红** ★
