## 1 判据来源: 上限 25% 与名义 8.26% 是哪来的 (只读引用)

### 1.1 上限 25% (保守) —— 一字不改地引用

| 项 | 值 | 证据 | 出处 |
|---|---|---|---|
| ★**面板蓝光通道辐亮度占白场辐亮度上限** ★ | **25%** (保守上限) | `[推算]` | `MECH/DISPLAY_BIOSAFETY_CRITERIA_V2.md` §3 ② 判据 ②-b ★**(need 记作 §3.2)** ★ |
| 25% 的定位 | **保守**口径: 覆盖"驱动蓝光到满码 / 高色温白场"等最坏工况的余量 | `[推算]` | 同上 |
| 25% 之外还有的两档 | 绝对上限 ≤ **4000 cd/m²** (仍落在 RG1 内) · 保守辐亮度口径 ≤ **500 cd/m²** | `[推算]` | 同上 §3 ① |
| 结构侧真正的杠杆 | 波导眼盒面积 A_e (L_eye,max = 0.1234 / A_e, 反比) | `[推算]` | 同上 §3 ⑥ + `MECH/MECH_BUDGET.md` §1.7 X-1 |

★**SW 侧不参与这条杠杆的计算** (★那是结构侧的地界★) ⇒ ★**SW 侧只保证一件事: 亮度控制策略里有 25% 这条上限, 并且运行时按它裁剪** ★

### 1.2 名义值 8.26% —— 算式照抄, 一个数不许动

| 基色 | 色度 (DCI-P3) | 光度效率 Y | 证据 |
|---|---|---|---|
| 蓝 (蓝基色) | x=0.150, y=0.060 | **Y_B = 0.0798** | `[推算]` (CIE 1931 算, 引用 `MECH/DISPLAY_BIOSAFETY_CRITERIA_V2.md` §3 ② ②-b) |
| 红 | DCI-P3 红基色 | **Y_R = 0.3850** | 同上 |
| 绿 | DCI-P3 绿基色 | **Y_G = 0.5017** | 同上 |

★**等辐射功率下**★ 三基色合成白场时, 蓝光通道占白场辐亮度的份额:

```
8.26%  =  Y_B / (Y_B + Y_R + Y_G)
       =  0.0798 / (0.0798 + 0.3850 + 0.5017)
       =  0.0798 / 0.9665
       =  0.0825654…
       → 8.26%   (保留两位小数)
```

★**本机复算**: `python3 SW/tools/check_brightness_biosafety.py` 每次都重算这条式子, ★**若算式与 8.26% 不自洽 ⇒ 门禁红** ★ ([实测] = 本机脚本实算)

★**名义 8.26% vs 上限 25%** ⇒ **余量 25 / 8.26 ≈ 3.03×** ⇒ ★**即"蓝光通道可以比名义值再亮 3 倍以内, 才算还在保守上限之内"** ★

★**8.26% 是 [推算] 的名义值, 不是实测值** ★ —— ★**面板光谱本身是 `[0数据]`** (★视涯 0.49" datasheet 无光谱/蓝光主波长/色坐标, 见 `MECH/DISPLAY_BIOSAFETY_CRITERIA_V2.md` §2.1 表末 [0数据] 行★) ⇒ ★**板端必须靠实测标定才能把名义值换成实测值, 见 §4** ★

### 1.3 SW 侧为什么不自己另算一套

★**因为口径链是结构侧定的**: 判据只锚**出瞳处实测光谱辐亮度** (★`MECH/DISPLAY_BIOSAFETY_CRITERIA_V2.md` §3 ⑥ "判据只锚出瞳"★) ⇒ ★**SW 侧若自己按"面板 datasheet 亮度"折算, 就是两套口径 ⇒ 争议落在合格判定上 ⇒ 必然对不上** ★
⇒ ★**SW 侧的合法动作只有两个**: ★**(a) 亮度控制策略里写死 25% 上限** ★ **(b) 亮度 API 上留一个可标定的蓝通道占比量, 让结构侧/实验室把标定值灌进来** ★

## 3 SW 侧要保证的东西 (★本单的核心交付口径★)

### 3.1 保证项 G-1: 亮度控制策略里有这条上限 (★硬性★)

★**SW 侧的亮度控制策略必须包含以下三条, 缺一条即本单无效** ★

| # | 保证项 | 可判口径 | 谁来判 |
|---|---|---|---|
| **G-1-a** | ★**白场 (全白画面) 运行时, 蓝通道辐亮度占白场辐亮度 ≤ 25%** ★ | 蓝通道码值/占空上限 ⇒ 由标定值反推码值天花板, 运行时裁剪 | `SW/tools/check_brightness_biosafety.py` (本单) + 出瞳光谱实测 (结构侧/实验室) |
| **G-1-b** | ★**亮度 API 上存在一个「可标定的蓝通道占比量」字段** ★ (★定义见 `SW/BRIGHTNESS_API_BLUE_RATIO.md`★) | 字段名/单位/量程/标定方法/来源全在 | 同上 (C5) |
| **G-1-c** | ★**白场辐亮度最大值侧, 出瞳 L_eye ≤ 1500 cd/m² 的目标被 SW 侧引用且不许被 SW 侧自行放宽** ★ | SW 侧只引用, 不改判据 | 同上 (C1/C3/C4) |

### 3.2 保证项 G-2: 运行时怎么用这条上限 (逻辑, 不含任何编出来的实测值)

```
① 亮度 API 读标定值  blue_channel_luminance_ratio_pct   (出厂标定表 / 实机标定表)
       └─ 若未标定 (status = uncalibrated) ⇒ ★降级到名义值 8.26%★ (见 §4 降级 L-1)
② 由标定值 + 25% 上限, 反推白场亮度码值天花板 luma_code_max
       └─ ★解: 在最坏工况 (蓝通道码值取满码, 白场最亮) 下仍满足 蓝占比 ≤ 25%★
③ 运行时任何 set_brightness() 请求 ⇒ 码值一律 clip 到 luma_code_max
       └─ ★越界请求 ⇒ 拒绝/夹紧 + 打点 (不静默放过)★
④ 每次写码值 ⇒ 记录 (码值, 当时生效的 blue_channel_luminance_ratio_pct, 来源状态)
```

★**③④ 是 SW 侧唯一的执行面** ⇒ ★**其余 (面板光谱 / 波导效率 / 眼盒面积 / 出瞳辐亮度) 全是结构侧或实验室侧的地界, SW 侧只消费标定值** ★

### 3.3 SW 侧的适用范围 (★这一段是防"给 demo 屏编一个假 API"★)

| 路线 | 面板 | 蓝通道是否是 SW 可驱动的量 | 本条上限怎么落 |
|---|---|---|---|
| ★**整机路线** (视涯 0.49" SiOLED, DCI-P3) ★ | 硅基 OLED, **RGB 三基色独立码值** ⇒ 蓝光是一路**独立原色** | ★**是** ★ ⇒ 蓝通道码值/占空可设 | ★**G-1-a 直接适用**: 蓝通道码值上限由 25% 反推 ★ |
