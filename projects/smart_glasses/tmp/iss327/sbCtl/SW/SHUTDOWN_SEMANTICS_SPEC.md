## §1 口径定义页 (三状态 × 两口径 = 六格)

> **状态定义** (全项目唯一叫法, 与 `SW/POWER_STATE_SEMANTICS.md` §4 一致): **工作** = `active` · **待机** = `standby` (深睡, SYS 带电) · **关机** = `poweroff` (真断电, SoC 无电)
> ★**禁用别名**: `suspend` / `deep_sleep` / `sleep` 一律不许当电源状态名 (见 `SW/POWER_STATE_SEMANTICS.md` §4.2)

### §1.2 ★必须显式回答: demo 板要不要「关机」这个状态?

> **答案 (我的推荐默认值, ★不是代拍★, 待 boss 拍 §3 Q1)**: **demo 板不要设独立的「关机」态**。
>
> **理由 (全部 `[实测]`, 不是推理)**:
> 1. demo 板**没有"没电"这个状态**: SoM 的 7 根 VCC_DCIN 由 `RAIL_DEMO_5V` 直供, 路径上**零开关** ⇒ 任何"关机"动作都只是**软件深睡** ⇒ 深睡就是终点;
> 2. demo 板**没有电池** (`BT_432243` DNP) ⇒ 深睡的代价是**USB 5V 的静态功耗**, 不是"电池被耗光" ⇒ 用户视角 demo 板就是"一直插着电的台架", "关机"这个语义对它没有用户价值;
> 3. demo 装机态**没有充电板** (主板↔充电板的唯一跨铰链通路 `J_CHG` = **DNP** "预留 (不装)"; 充电板上的 `U_CHG` BQ25896 / `Q_CHG_LED` 都是**必装但装在 `CHG_BOARD` 上**, 不在 demo 装机范围) ⇒ "关机时充电灯"这条锁死口径**在 demo 板不适用** ⇒ 三条口径在 demo 板只剩两条;
> 4. 但**售后话术仍要一个说法** ⇒ `FRAMEWORK/AFTERSALES.md` §2① 写的是「长按侧键 10 秒 → 关机」, 台架上这个动作**必须有个响应**, 否则售后按 10 秒没反应会判"砖机"。
>
> ⇒ **建议口径 (推荐默认值)**: demo 板的售后动作仍叫**"关机"** (用户词), 但实现 = **深睡 + `U_EN_SW` 关断底板支路**, 并在售后文档里**明写一句**「demo 台架的『关机』= 停止工作 + 断底板支路; **整机才是真断电**」⇒ 口径不撒谎, 售后动作不落空。

### §6.3 ★读这张网表的一个坑 (写给下一个来读网表的人, ★也是本门禁的实现依据)

★**这张网表不是"一行 = 一个器件"**, 而是 **"一行 = 一根导线 = 同一网上两个器件脚"** ⇒ **`ref` 列只代表这条线的其中一端** ⇒ ★**从 `ref` 列统计器件会漏一半脚**。

- 例: `P1,BAT_SW,C_SW_IN,U_PWR_SW pin1,C_SW_IN,10µF ±20%,C,必装,...` ⇒ 这行的 `ref` = `C_SW_IN`, 但 **`U_PWR_SW pin1` 也是这条线的一端** ⇒ 统计 `U_PWR_SW` 的脚时, 它的 pin1 藏在 `ref=C_SW_IN` 的行里。
- ⇒ ★**本门禁的做法**: **器件归属从 node 字符串反推** (`<位号> pin<N>` ⇒ 属于 `<位号>`), **不靠 `ref` 列** ⇒ 因此像 `RAIL_BOARD_5V → U_LDO_S28 pin4` 这种 "`ref` 填了网名" 的行也能正确归属。
- ⇒ ★**电气连通性** = ★**按 `net` 名分组** (同一 `net` 名 = 同一电气节点) + ★**同一 node 字符串恒等** (解决 `SYS` / `RAIL_SYS` 这种"网名与轨名不同字"的写法)。
- ⇒ ★**"这颗开关能不能断开某条轨"的判法 = 拓扑级**: **拿掉这颗器件后, 源与受电端是否还连通** (图论里的割点/割边判定) ⇒ 而不是"网表里有没有开关器件" (见 §5 R4 的作用域化说明)。
