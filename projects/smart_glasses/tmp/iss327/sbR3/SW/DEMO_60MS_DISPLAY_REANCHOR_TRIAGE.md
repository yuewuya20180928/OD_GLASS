### 0.1 ★★★ 关键澄清: `10.09 ms` **不是** 1080p 口径的数 ★★★

★**`10.09 ms` 与显示分辨率无关, 它是「显示输出侧总额上限」= 60ms 预算上限 ⇒ demo 屏原样成立, 不重算、不作废。**★

依据 (`HW/e2e_budget_rk3572.py`, **只读引用, 本单不改**):

```python
T_FIXED_OTHER = T_PRE_EXPOSURE + T_DRAW + T_PANEL + T_RESIDUAL   # 31.00 (与显示分辨率无关的部分)
def display_out_max_for(s5, budget_ms=60.0):
    return budget_ms - T_FIXED_OTHER - (s5 + POST_MS)          # ⇒ 与分辨率无关
def compose_max_for(s5, budget_ms=60.0):
    return display_out_max_for(s5, budget_ms) - TX_MIN_1080    # ⇒ 这里才引入分辨率
```

⇒ ★**s5 = 13.31 时 `display_out_max_for` = 60 − 31.00 − (13.31 + 5.60) = 10.09 ms** ★
⇒ ★**而 `compose_max_for` = 10.09 − 7.776 = 2.32 ms (整机) ⇒ demo 屏 = 10.09 − 2.304 = 7.786 ≈ 7.79 ms** ★★ (**与 ISS-212 Q-5「余量从 2.32 放宽到 7.79」逐位吻合**) ★★
⇒ ⇒ **所以: `10.09` = 判据上限 (分辨率无关, 保留) · `2.32` = 整机口径的合成段上限 (必须换成 7.79)** ⇒
⇒ ⇒ **判据被算严的倍率 = (10.09 − 2.304) / (10.09 − 7.776) = 7.786 / 2.314 = 3.36×** ⇒ **≈ 3.4 倍** (与派活单所述一致)

### 0.2 ★`12.96 ms` (线性上界) 的定性 ★

`HW/e2e_budget_rk3572.py`: `display_out_upper_bound(px_ratio)` = 整段显示输出侧随像素数等比放大
⇒ **12.96 = T_DISPLAY_OUT(3.00) × 4.32** ⇒ **它是 @1920×1080 的数** ⇒ 判 **整机路线占位**。
⇒ ★**本单不为 demo 屏另编一个「线性上界」** (ISS-212 未发布该数 ⇒ 越权编数) ⇒
★**demo 活动口径改用 ISS-212 已发布的 `~2.75 ms` [推算] 与 `7.79 ms` 余量做判据** ⇒ 板端实测仍 **[0数据]**。

## 5. 处置规矩 (照 ISS-212 `SW/DEMO_PANEL_SPEC_TRIAGE.md` L-08 / L-16 立下的规矩)

★**整机 1080p 的那些数 (7.776 / 12.96 / 2.32 / 4.32 / 1920×1080) 不是「错」** ★
⇒ 它们属于**整机路线 (整机屏 0.49" 视涯)**, 正确处置 = ★**分栏 + 显式标注**★, **不是删掉、也不是留着冒充 demo 口径**。
