### 0.2 三态判定定义 (每段必用)

| 判定 | 符号 | 机械判据 (满足全部才可打勾) |
|---|---|---|

| **不通过** | ❌ | 至少一项明确不满足"通过标准"列 (有 [实测] 数据且数据违反标准) |

**铁律**:
1. **未验 ≠ 不通过, 但 ≠ 通过**。G3 准出时, 未验项必须逐条列出并给期望补测时间 (§8.2)。
2. **禁止把 [推算] 值填进"实测值"列**。实测值列只能填 [实测]; 推算值另填 §4 推算列。
3. **禁止写"工作正常 / 基本正常 / 无异常"** —— 通过标准列必须可机械判 (具体数值 / 具体现象 / 具体计数)。

## 10. EVT-7 FOV 保持检查

**段目标**: 证明 **ISP 的缩放路径是"整幅 scale (full-frame scale)" 而不是 ROI 裁剪**, 且输出帧的视场 = sensor 全幅视场 (对角 120.00°)。

**为什么单独开一段 (不能并进 EVT-3 驱动)**:
- EVT-3 只查"能不能出图", **查不出"出的图视场对不对"** —— ISP 跑 ROI 模式时一切正常, 只是世界被砍到 85.61° `[推算]`。
- 老板 10-25 19:33/19:42 拍板 "不裁剪 + 对角 120°" ⇒ 必须有**机械可判**的验证项, 否则这条决策在 EVT 阶段无法证伪。
- 需求出处: `SW/SW_REQUIREMENTS.md` §3.4 (M2-R7 / M2-R8) · 深度分析 `SW/ISP_SCALING_MODE.md`。

**判据算式 (直接可用, 不许写成"确认视场正常")** —— 等距鱼眼模型 `r = f·θ`:

```
r_diag   = sqrt( (w/2 − cx)^2 + (h/2 − cy)^2 )        [px]
theta_d  = r_diag / f_px                               [rad]      (等距: θ = r / f)
diagFOV  = 2 × theta_d × 180/π                        [deg]
horiz_half = (w/2 − cx) / f_px × 180/π                [deg]
vert_half  = (h/2 − cy) / f_px × 180/π                [deg]
deg_per_px_h = horiz_half / (w/2)      deg_per_px_v = vert_half / (h/2)
aniso = max/min(deg_per_px_h, deg_per_px_v)
```

**设计基准值 (与 `SW/SW_REQUIREMENTS.md` §3.4.2 表同源; 等级 = `[推算·本文推导]`, 与 `HW/LENS_SELECTION.md` §3.2 独立互证)**:

| sensor | ISP 输入 (全幅) | 设计对角 FOV | 水平半视场 | 垂直半视场 | f_px | deg/px | 俯角 25° 正前方余量 |
|---|---|---|---|---|---|---|---|
| OV04C10 | 2688×1520@60 | **120.00°** | 52.23° | 29.53° | 1474.4 | 0.0389°/px | **+4.53°** |
| AR0234CS | 1920×1200@60 | **120.00°** | 50.88° | 31.80° | 1081.1 | 0.0530°/px | +6.80° |

### 11.4 怎么判过 (机械规则)

| 规则 | 内容 |
|---|---|
| **R1 怎么算过** | CB-01 ~ CB-09 **9/9 全 ✅**, 且每项都有 `[实测]` 数据 + 数据文件路径 (§11.5) → BR-01 判 ✅ |
| **R2 怎么算未验** | 只要有 1 项没有有效实测数据 (未测 / 文件缺失 / 只有 [推算]) → BR-01 **最高判 ⚠️未验**, 并在本表下方写明未验原因 + 补测时间 |
| **R3 怎么算不通过** | 只要有 1 项 ❌ (有实测数据且违反标准) → BR-01 判 ❌, 写明子编号 + 实测值 + 违反哪条标准 |
| **R4 不许糊弄** | 禁止把 PC 侧仿真结果 (`SW/tools/` 的自测) 填进本表 —— 那是**脚本逻辑自检**, 不是**板端救砖实测**。两者在"证据等级"列必须分开写 |
| **R5 生产红线** | BR-01 判 ⚠️未验 或 ❌ 的板 → **不得进产线 / 不得交付**; 整批未验 → **不得量产** |
| **R6 追溯** | BR-01 通过后, 把 BR-01 的证据文件路径 + 该板 SN + 刷入的版本串 + 下载工具版本 写入 EVT 报告头 §1 (与 §3.5 追溯字段一致) |

### 11.5 失败怎么办 (处置决策树)

| 现象 (哪个 CB 挂了) | 最可能原因 | 立即动作 | 上限 |
|---|---|---|---|
| **进不了 BOOT** (CB-01 前就卡住, E1/E2/E3 全无) | BOOT 通路/时序错 (P1 未确认) / BOOT 引脚电平不对 | 换方式 A (跳线) / B (按键组合) 各试一次; 用逻辑分析仪抓 BOOT/RESET 波形 (§4.5.5 L2) | 重试 ≤2 次 |
| **枚举了但工具不认** | 协议不匹配 (P3) / 线不是数据线 / 工具版本不对 | 换线换口; 核对工具版本; 改走另一条分支 (原厂工具 / fastboot / DFU) | ≤2 次 |
| **识别了但写不进去** | 存储类型与分区表不匹配 (P4) / 中途断电 (F2) | **不自动重试** (半写状态未知) → 全量重刷 | ≤2 次 |
| **刷完起不来** (CB-02/04/05 挂) | bootloader 校验失败 / 分区表错 / 版本块 magic 缺失 | 跑回读校验判定"是否未生效"; 是 → 重刷; 否 → 升级 S3 | ≤2 次 |
| **起来了但画质退化** (CB-07 挂) | **标定数据丢失 (F6)** —— 返修最大的坑 | 从工厂标定台账按 SN 恢复标定 → 重刷 L2 | 按 §5.2 第 5 步 |
| **起来了但 OD 不出框** (CB-03/04/09 挂) | 模型 hash / 格式版本不匹配 (F4) | 重刷 L2 + 核对 `model=` 版本串 | 按 F4 处置 |

> 🔴 **硬规则**: **S2 连续失败 2 次 → 必须升级 S3 (JTAG), 不得"多刷几次试试"**。半写状态反复覆盖会制造更复杂的问题。
> 升级 S3 / 判 S4 返厂由**项目总工裁决**, sw-lead 不自行升级。**S2 全链路失败 = 该板判返厂 (S4), 不得进产线。**
