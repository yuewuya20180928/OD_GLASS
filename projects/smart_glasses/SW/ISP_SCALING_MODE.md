## 0. 一页结论 (TL;DR)

1. **ISP 缩放路径必须是整幅 scale (full-frame scale)** —— ROI 裁剪路线把 OV04C10 的对角 FOV 从 **120.00° 砍到 85.61°** (垂直半视场 29.53° → 20.98°), 立体角只剩 **52.30% (损失 47.70%)**, 俯角 25° 时正前方余量 **−4.02° = 直接掉出画面**。`[推算·本文推导]` (脚本 A1/A2/A4/A6)
2. **"1080p → 640×480" 这个写法本身是坑**: 对 OV04C10, "1080p" 就是 2688×1520 的一个 ROI (1920×1080), **不是**全幅 → 正确表述是 **"全幅 2688×1520@60 → 640×480@60"**。`SW/SW_REQUIREMENTS.md` §3.4.3 已写死。
3. **ISP 裁掉的正是检测价值最高的地方**: 120° 镜头的角落 **−39.5%** 桶形畸变区 = 视野边缘 (目标刚进入画面处) → 裁掉它 = 目标在**检测到之前**就已经出画。`[官方·HW/LENS_SELECTION.md §4]` + `[推算]`
4. **宽高比子路线 (16:9/16:10 → 4:3) 不是等比**: 选 **子路线 2 = 等比 scale + letterbox** (OV04C10: 640×362 内容 + 上下各 59px 黑边 = 24.58% 输出像素是黑边; AR0234CS: 640×400 + 上下各 40px = 16.67%)。理由: 几何保持 ⇒ 单 f_px 模型在输出系同样成立 (`f_out = f_px × k`), 反投影公式**零改动**; 角分辨率各向异性 1.000 (子路线 1 是 1.326)。`[推算·本文推导]`
5. **子路线 1 (各向异性拉伸) 的代价是量化的**: OV04C10 sx=0.238095 / sy=0.315789 → 目标长宽比**全局失真 32.6%** (鱼眼自身角落畸变才 20.9%) → 直接踩 REQ-GEO-07 "优先等比" 的红线; 且"鱼眼圆变椭圆" ⇒ 输出系**必须**用 fx≠fy, 与 `FISHEYE_GEOMETRY.md` §3.2 的各向同性 `r_n = √(dx²+dy²)/f_px` 不兼容 (sensor 系仍可跑, 但任何"在输出系量角度"的代码路径失效)。`[推算·本文推导]`
6. **整幅的账**: OV04C10 全幅 RAW10@60 = **2.451 Gbps** (需 4-lane MIPI, = R-GEO-1) + ISP 吞吐 **245.1 MP/s** = 250 MP/s 口径的 **98.1%** / 4K60 官方口径 497.7 MP/s 的 **49.3%** → 两个口径差 2 倍, 必须 close。`[推算]` + `[官方口径·自相矛盾]`
7. **整幅 scale 硬件上可行**: 原厂官网口径 "ISP 子系统集成**四个独立的片上缩放器 (支持 1/64 至 2 倍)**" → 2688→640 = 1/4.2、2688→1280 = 1/2.1, **都在 1/64~2× 范围内**。`[官方·PROJECT_TRACKER.md §1139 官网brief]`
8. **新发现的坑 (ISS-053 没写)**: 显示光机只有 **30° FOV** (JBD 走鹃Ⅱ, `[官方]`), 而采集 120° → **显示端有效角分辨率被 OD 链路 (0.1632 °/px) 决定, 不是光机面板 (0.12 °/px), 更不是 sensor 原生 (0.0389 °/px)** → 也就是说 "120°" 这个数字**用户能不能看见, 取决于显示映射怎么拍板** (见 §6 CR-4)。

## 1. 硬约束 (写死, 原文, 不可改写)

> **ISP 缩放路径必须为整幅 scale (full-frame scale), 禁止 ROI 裁剪 (crop+scale)、禁止 sensor ROI 读出模式、禁止为凑 4:3 而做的 aspect crop; ISP 输入必须是 sensor 全幅阵列。**

出处: `SW/SW_REQUIREMENTS.md` §3.4.1 (M2-R7 / M2-R8)。本文只做论证, 不重复定义。

| # | 约束 | 违反后果 (量化, `[推算·本文推导]`) |
|---|---|---|
| C1 | 缩放 = **整幅 scale** (取全幅 → 缩放) | OV04C10: 对角 120.00° → **85.61°**; 垂直半 29.53° → **20.98°**; 立体角 1.768 sr → 0.925 sr (**只剩 52.30%**) |
| C2 | **禁止 sensor ROI 读出模式** | OV04C10 的 1920×1080 模式 = ROI (对角 85.61°); AR0234CS 裁高到 1080p = 对角 116.75°, 立体角 90.30%, 俯角 28° 余量仅 +0.62° |
| C3 | **禁止为凑 4:3 做的 aspect crop** | OV04C10 全幅 (16:9.03) 裁成 4:3 (宽 2688→2026.67) → 线性丢 24.60% 宽, 水平半视场 52.23° → **39.38°** (HFOV 104.45° → 78.76°, **丢 25.70°**) |
| C4 | **禁止 ROI 裁剪 (crop+scale)** (ISP 内部先 crop 再 scale) | = C1 |
| C5 | **ISP 输入 = sensor 全幅阵列** | OV04C10 2688×1520@60 / AR0234CS 1920×1200@60 (这是 C1~C4 的实现前提) |

**为什么是硬约束 (不是建议)**: 老板 10-25 19:33/19:42 拍板 "sensor 输出不裁剪, 后级只缩放" + "鱼眼(等距) + 对角 120°"。ROI 路线同时违反这两条, 且后果是**用户眼前的视场**被砍 (见 §3 第 1 行)。

## 2. 三条路线的定义 (先把话说死, 免得各写各的)

| 路线 | 定义 | 输入 | 输出 | 视场 |
|---|---|---|---|---|
| **R-ROI** ❌ 禁止 | sensor ROI 读出 (或 ISP 内部 crop) + scale | 2688×1520 → **裁 1920×1080** | 640×480 / 1280×960 | **丢** (85.61° / 116.75°) |
| **R-SCALE-1** | 整幅 scale, **各向异性拉伸** (sx≠sy, 无黑边) | 全幅 | 640×480 全有效 | 保留 120° |
| **R-SCALE-2** ✅ 本文推荐 | 整幅 scale, **等比 + letterbox** (黑边 padding) | 全幅 | 640×480 (内容 640×362 + 黑边) | 保留 120° |

**R-SCALE-1 与 R-SCALE-2 的区别不在视场 (都保留 120°), 在几何**: R-SCALE-1 把 16:9 的画面压成 4:3 (鱼眼圆变椭圆); R-SCALE-2 保持画面形状 (黑边填空)。

## 4. ★ 宽高比子路线 (16:9 / 16:10 → 4:3 不是等比 —— 硬要求, 不可省)

### 4.1 前提: 为什么这一步是独立的

sensor 阵列宽高比 = **16:9.03** (OV04C10 2688×1520) / **16:10** (AR0234CS 1920×1200); 输出链路宽高比 = **4:3** (640×480 / 1280×960)。**两者不等比** ⇒ 从"全幅"到"输出"这一步, 必然要在三个动作里选一个: **拉伸 / 裁剪 / 加黑边**。裁剪已被 C3 禁止 ⇒ 只剩拉伸与黑边两条子路线。

### 4.2 子路线 1: 各向异性拉伸 (sx ≠ sy, 无黑边)

| sensor | 链路 | sx | sy | 各向异性 (sy/sx) | 水平 °/px | 垂直 °/px | 黑边 |
|---|---|---|---|---|---|---|---|
| OV04C10 | 2688×1520 → 640×480 | **0.238095** | **0.315789** | **1.326** | 0.1632 | 0.1231 | 无 |
| OV04C10 | 2688×1520 → 1280×960 | 0.476190 | 0.631579 | 1.326 | 0.0816 | 0.0615 | 无 |
| AR0234CS | 1920×1200 → 640×480 | 0.333333 | 0.400000 | **1.200** | 0.1590 | 0.1325 | 无 |
| AR0234CS | 1920×1200 → 1280×960 | 0.666667 | 0.800000 | 1.200 | 0.0795 | 0.0662 | 无 |

**优点**: 输出像素 **100% 有效** (零浪费); 640×480 全是场景 → 小目标像素数最多 (方案 B 的老卖点)。
**缺点 (全部量化)**:
1. **鱼眼圆被压成椭圆** (半轴比 1.326:1 / 1.200:1) ⇒ 输出系不再是"等距圆", 反投影必须 fx≠fy, 与 §3.2 的各向同性公式不兼容。
2. **目标长宽比全局失真 32.6%** (OV04C10) —— 全画面所有目标都被纵向拉 1.326 倍, **远大于**鱼眼自身在角落的 20.9% 切向畸变 (`FISHEYE_GEOMETRY.md` §5.4 表5) ⇒ 违反 REQ-GEO-07 "优先等比 (letterbox 加黑边)" 的明确要求; 且 YOLO 的 anchor 先验假定目标形状不失真 → 全局 32.6% 失真对 mAP 的伤害 > 局部 20.9% 畸变。
3. **角分辨率均匀性破了**: 水平 0.1632 vs 垂直 0.1231 °/px (差 1.326×) ⇒ 框的角张角 (宽/高) 依赖框在画面里的**朝向**, 不再是单一标量。
4. **在输出系直接量角度必错**: `ψ = atan2(dy_out, dx_out)` 最大偏差 **8.21°** (`FISHEYE_GEOMETRY.md` §2.3.1) ⇒ 任何"在输出系算方位"的代码路径 (显示层标签、角张角) 都要改成"先回 sensor 系", 回归面覆盖显示层 + OD 层。

### 4.3 子路线 2: 等比 scale + letterbox (k = min(dw/src_w, dh/src_h), 不足处补黑边)

| sensor | 链路 | k (等比) | 内容区 (scene) | 黑边 (上下各) | **黑边占比** | f_out = f_px·k | 角分辨率 (内容区) |
|---|---|---|---|---|---|---|---|
| OV04C10 | →640×480@60 | **0.238095** | **640×362** | **59 px** | **24.58%** (118/480) | **351.05** | **0.1632 °/px** |
| OV04C10 | →1280×960@15 | 0.476190 | **1280×724** | 118 px | 24.58% (236/960) | 702.10 | 0.0816 °/px |
| AR0234CS | →640×480@60 | **0.333333** | **640×400** | **40 px** | **16.67%** (80/480) | **360.35** | **0.1590 °/px** |
| AR0234CS | →1280×960@15 | 0.666667 | **1280×800** | 80 px | 16.67% (160/960) | 720.70 | 0.0795 °/px |

> 取整说明: 2688×1520 按 k=0.238095 缩放得 640×361.90 → 取 **640×362** (差 0.10 px, 0.03%), 不做二次裁剪; AR0234CS 1920×1200 按 k=1/3 得 640×400 (整除, 无误差)。

**优点**:
1. **几何完全保持** ⇒ f_out = f_px × k, 单 f_px 在输出系成立 ⇒ 反投影公式零改动, 角分辨率各向异性 **1.000**。
2. **目标形状不失真** ⇒ YOLO anchor 先验成立, 框角张角与框在画面里的朝向无关。
3. **框坐标往返可精确解析** (bars 边界是整数常量) ⇒ REQ-GEO-06 的 ≤2px 往返误差容易达标。
4. **零裁剪** ⇒ 120° 视场 + 角落 −39.5% 畸变区 (检测价值最高处) 全部保留。

**缺点 (必须承认)**:
1. **25% (OV04C10) / 17% (AR0234CS) 的输出像素是黑边** ⇒ NPU 算力有 24.58% 花在空像素上 (按纯 NPU 16ms 估 ⇒ 约 3.9ms 等效白烧); **但黑边上不可能有目标 ⇒ 对 mAP 无损, 只损算力与功耗**。
2. **显示链路要跟着处理黑边** (ox, oy 仿射) ⇒ 见 §6 CR-3。
3. **需要 ISP scaler 支持"缩放后指定区域填黑边"** ⇒ 原厂能力未确认 (见 §6 CR-2); 若不支持, R-SCALE-2 退化为 R-SCALE-1, 届时按 §4.2 的代价走。

### 4.4 ★ 我的选择: **子路线 2 (等比 scale + letterbox)**

**依据 (4 条, 全部可量化)**:
1. **反投影零改动 vs 全链路改动**: 子路线 2 → f_out = f_px·k, `FISHEYE_GEOMETRY.md` §3 公式一个字不改, 只在标定表加一行; 子路线 1 → §3.2 各向同性公式在输出系失效, §3.4 ψ 必须强制回 sensor 系, 显示层 + OD 层回归面至少 2 个模块。**ISS-053 已闭环验证过 §3 的公式 (往返误差 8e-15 rad) ⇒ 改动风险不对等。**
2. **角分辨率均匀性 1.000 vs 1.326**: 框的角张角 (Δθ_w × Δθ_h) 只有在等比时才是标量; 非等比时同一个物体在不同位置的角张角比会变 → `FISHEYE_GEOMETRY.md` §4.3 的几何框龄 (球面角距) 判定链会引入朝向相关的系统项。
3. **目标长宽比失真 32.6% > 鱼眼角落 20.9%**: REQ-GEO-07 明确"优先等比 (letterbox 加黑边)", 理由就是这个大小关系; 子路线 1 直接违反它。
4. **黑边的代价可量化且可控 (24.58%)**, 而裁剪的代价不可量化 (立体角 −47.70%, 用户可见视场 −28.66% 对角) ⇒ 取小代价。
