## 1. 一页纸结论 (B1)

| # | 结论 | 关键数字 / 依据 |
|---|---|---|
| 1 | **"关机" 与 "待机" 是两个电源状态, 不许用同一个 `suspend/standby` 混着写** | 关机 = 真断电 (SoC 无电); 待机 = SoC 低功耗运行 (SYS 带电)。两者**功耗差 375-714 倍** (0.15W ÷ 0.21-0.40mW) [推算] |
| 2 | **关机态 SW 不能承诺任何行为** | SoC 无电 ⇒ 无 SW 在运行、无定时任务、无日志、无 LED 反馈。**唯一可观察的充电灯是充电板本地硬件行为** (VBUS 供电 + NMOS 读 BQ25896 STAT), 不经过 SW [推算, `PROJECT_TRACKER` §0 "关机时充电灯" 行] |
| 3 | **关机态唤醒只有 3 条硬件路径**: VBUS 接入 / 充电 IC PG / 长按按键 | 前两条是充电链 (不依赖 SoC) [推算, `HW/POWER_SHUTDOWN_V3.md` §3]; **第三条依赖 SoC AON/常供电通路 ⇒ [0数据] 待原厂** —— 见 §7 未决项 U1 |
| 4 | **续航口径必须两行分列**: 待机 ~9.3h ≠ 关机 5-11 个月 | 420mAh 电芯: 待机 0.15W → **~9.3h** (U2 裁决口径 A; 旧值 2.8h [旧口径·已作废]); 关机 ~108µA → 5-11 个月 (随 AON 静态电流 10-50µA 变) [推算] |
| 5 | **SW 对外 API 只允许两个电源状态名**: `poweroff` / `standby`; `suspend` 作禁用别名 | 见 §4 命名对照。**"深度休眠" 是旧称 [旧称·已作废]**, 只在历史引用里出现 |
| 6 | ✅ **续航列口径不一致 —— 已由项目总工 2026-10-28 08:5x 裁决** (U2, 见 §6.1 与 `PROJECT_TRACKER.md` §(1.34)) | 待机 2.8h / 满载 20min / 按需 1.8h 三行都是按 "mAh ÷ (把 W 当 mA)" 直算; 按 I = P/V @3.7V + DoD 0.9 应为 待机 **~9.3h** / 满载 **~1.15h** / 按需 **~6.1h** (**差 ~3.3 倍**, DoD 0.9 口径; 满容量口径 ~3.7 倍)。关机行用的是真电流 (108µA) ⇒ 算得对。见 §6.1 与 §7 未决项 U2 |

## 2. 状态表 (逐态, 每一格都有值)

| 状态名 | SoC 是否在运行态 | 可承诺行为 | 典型功耗 | 典型续航 | 可用内存 | 可响应输入 |
|---|---|---|---|---|---|---|
| **关机 (poweroff)** | **否** —— 负载开关切 SYS, SoC 断电 | **无任何行为承诺** (无 SW / 无定时任务 / 无日志 / 无 LED 反馈)。唯一可观察的充电灯是充电板本地硬件行为, 不由 SW 控制 | **≈0.21-0.40 mW** (静态 ~108µA @3.7V) [推算] | **420mAh → 约 5-11 个月** [推算] | **0** —— 无电 ⇒ 无 SRAM/DDR 可用, 不存在"可保留状态" | **无** —— 无 SW 在运行; 唤醒只经硬件通路: VBUS 接入 / 充电 IC PG / 长按按键 |
| **待机 (standby)** | **是** —— SoC 处于低功耗运行态 (即 `standby` 态本身), SYS 带电 | 可被硬件唤醒源唤醒并回到运行态; **不承诺唤醒延迟** (无实测); **不承诺跨待机保留内存内容** ⇒ SW 进 standby 前必须落盘 | **0.15 W** [推算, V2 口径] | **420mAh → ~9.3 h** (U2 裁决口径 A; 旧值 2.8h [旧口径·已作废]) [推算] | 运行态内存布局**是否保留取决于 SoC 低功耗态的 retention 行为 ⇒ [0数据]**; SW 侧按"不可保留"设计 | **仅唤醒源** (按键 / PG / 定时器) [唤醒源清单待 AON 确认, 0数据]; 业务输入 (语音 / 触摸) 不响应 |
| **运行 (active)** | 是 | OD + 显示叠加全链路 (端到端 <60ms 目标, 口径 A/C 未锁见 Q1); 充电中禁 OD | 满载 **1.22 W** / 按需触发 **0.23 W** [推算] | 满载 **~1.15 h** / 按需触发 **~6.1 h** (U2 裁决口径 A; 旧值 20min / 1.8h [旧口径·已作废]) [推算] | 512MB DDR 内置; 静态+峰值规划 199-216MB [推算, SW 内存预算] | 全部 (按键 / 语音 / 传感器 / USB) |

★**"息屏" (display-off) 不在这张表里** —— 它是 **运行态内部的显示子状态** (SoC 仍在跑, 只是不出光), 不是电源状态, 不许拿它当 "待机" 的同义词。

## 3. 各态软件行为边界 (逐态展开)

### 3.1 关机 (poweroff) —— 无电 ⇒ 无任何行为承诺

| 项 | 边界 |
|---|---|
| SoC | 断电。**没有任何代码在执行** |
| 可用内存 | 0。无 SRAM/DDR, 无寄存器上下文 ⇒ **关机前未落盘的一切都丢** |
| 可响应输入 | **无**。SW 不响应任何输入 (语音 / 触摸 / 传感器 / USB 全部无效) |
| 可承诺行为 | **零**。不得承诺: 充电状态显示 / 定时开机 / 远程唤醒 / 日志留存 / OTA 落盘 / 任何 UI 反馈 |
| 唯一硬件可观察量 | **充电灯** —— 装在充电板 (镜框), VBUS 供电 + 本地 NMOS 读 BQ25896 的 STAT (低=充电中亮 / 高=灭 / 1Hz 闪=故障) ⇒ **关机插电时灯可亮, 但这是硬件行为, 与 SW 无关** [推算, `PROJECT_TRACKER` §0] |
| 唤醒路径 (只有这 3 条) | ① **VBUS 接入** (插 USB/充电头) → 充电链带电 → PG 有效 → 负载开关开 → SoC 上电<br>② **充电 IC PG** (BQ25896 电源良好, 开漏 LOW=源良好) → 经 N-MOS 反相驱动负载开关 ON 脚<br>③ **长按按键** —— ⚠️ 依赖 SoC AON / 常供电唤醒通路, **目前 [0数据]**, 未确认前 SW 不得把它写进用户话术的"必达"路径 (见 U1) |
| 恢复后第一件事 (SW 侧) | SoC 重新上电 ⇒ 走正常 boot ⇒ 读 CHG_STAT (跨铰链开漏, 已有 `chg_state_semantics` 接口取值) 与 PG, 让 UI 与硬件灯**一致**; 状态未知时按"在充电"处理 ⇒ 禁 OD |
| SW 不得做的事 | 不得在关机态承诺任何"还会发生的事"; 不得把 `poweroff` 实现成"写个 flag 再睡" (那是 `standby`, 见 §5) |

### 3.2 待机 (standby) —— SoC 在运行态, 低功耗

| 项 | 边界 |
|---|---|
| SoC | 低功耗运行态 (standby), **SYS 带电** |
| 可用内存 | **取决于 SoC 低功耗态是否保留 DDR 内容 ⇒ [0数据]** (ARS45 侧未确认)。**SW 按"不可保留"设计**: 进入 standby 前把会话/配置/计数落盘到 NVM |
| 可响应输入 | 仅唤醒源 (按键 / PG / 定时器)。业务输入 (语音 / 触摸 / 传感器) 不响应 —— 传感器帧率、OD 推理、显示合成全部停 |
| 可承诺行为 | ① 能被唤醒并回到运行态 ② 唤醒后从落盘状态恢复 ③ **不承诺**唤醒延迟数值 (无实测, 且 AON 未知) ④ **不承诺**佩戴安全: 0.15W 贴着皮肤 → 皮肤侧 45.9-46.9°C, **超 43°C 红线** [推算, `HW/POWER_BUDGET_V2.md` §4.2] ⇒ 待机是"摘下来放包里"的状态, 不是"戴着也能站"的状态 |
| 典型功耗 | 0.15W [推算, V2 口径] |
| 典型续航 | 420mAh → ~9.3h (U2 裁决口径 A; 旧值 2.8h [旧口径·已作废]) [推算] |
| 进/出 standby 的 SW 动作 | 进: 停 OD → 停显示 → 落盘 → 关 sensor/光机 → 让出 NPU/DDR 资源 → 进低功耗态。出: 唤醒 → 重配 sensor/光机 → 恢复落盘状态 → 重开 OD |
| 遗留硬件依赖 | 进 standby 前能否真正关掉 sensor 与光机, 取决于 SoC 低功耗态的外设 rail 行为 ⇒ [0数据]; SW 侧给出"按硬件断电顺序"的最保守实现 |

### 3.3 运行 (active) —— 唯一有性能承诺的状态

| 项 | 边界 |
|---|---|
| 可承诺行为 | 端到端 <60ms (口径 A/C 未锁, 见 Q1) 的 OD + 显示叠加; 充电中禁 OD; 温度超阈降载 (`thermal_tiers_skin`) |
| 典型功耗 | 满载 1.22W / 按需触发 0.23W [推算] |
| 典型续航 | 满载 20min / 按需触发 1.8h (锁定口径, 复核见 U2) [推算] |
| 与电源状态的关系 | 运行态内部还有"息屏 (display-off)"与"按需触发占空比"两种降载手段 —— **它们都不是电源状态**, 别混进本表命名 |

### 4.1 电源状态

|---|---|---|---|---|

### 4.2 分层命名 (三层必须对齐)

| 层 | 关机 | 待机 | 谁定 |
|---|---|---|---|
| 用户话术 (售后) | "关机" (长按 10s = 关机) | "待机" | 老板 10-27 + `PROJECT_TRACKER` §0 |
| **SW API / 状态机** | **`poweroff`** | **`standby`** | **本文 (sw-lead)** |
| Linux 内核 | `reboot(RTC_POWER_OFF)` / 触发负载开关关断 | `echo mem > /sys/power/state` (低功耗态) | 内核语义, 对外**不出现** |

## 5. SW 侧实现约定 (状态机 + 关机序列)

### 5.1 状态机

```
        ┌──────────────── poweroff (关机, SoC 无电) ────────────────┐
        │            ↑ 硬件唤醒 (VBUS / PG / 按键)                  │
        │            ↓                                              │
   active (运行) ──→ standby (待机, SYS 带电) ──────────────────────┘
        │  ↑            │  ↑                                          │
        │  └────────────┘  └──────── 硬件唤醒源 / 定时器 ────────────┘
        └─ poweroff: 落盘 → 写 PWR_CTRL GPIO = 高阻 → 断电 (不可逆, 无"取消")
```

★**`poweroff` 与 `standby` 必须是两个独立状态, 不许共用一个 `suspend` 入口。** 理由: 二者功耗差 375-714 倍 [推算], 唤醒路径不同 (待机可被软件定时器唤醒, 关机只能被硬件唤醒), 承诺边界不同 (待机要落盘, 关机无状态可留)。

### 5.2 关机序列 (SW 侧, 顺序不可改)

| 步 | 动作 | 为什么必须在这个位置 |
|---|---|---|
| 1 | 拒绝新请求 (停 OD / 停显示 / 停新帧接入) | 后面没有执行机会, 必须先停 |
| 2 | 把必要状态落盘 (NVM / eMMC) + fsync | **关机态无 SW**, 未落盘的一律丢 |
| 3 | 写最后一条关机日志 (含原因: 用户长按 / 电压 / 温度) 并 flush | 这是关机后唯一存在的痕迹 |
| 4 | (可选) 通知充电板关机意图 | **当前网表无此通路 ⇒ 不做**, 记 U3 |
| 5 | 写 `PWR_CTRL` GPIO = 高阻 → 负载开关掉回 10k 下拉 → SoC 断电 | 最后一步; 之后**任何** flash/DDR 写都会在断电中途丢数据 |
| 6 | 之后不再有 SW 执行 | 状态由硬件保持 (ON 脚下拉 = 默认关), 软件不需要锁存 |

★**关机不可逆**: 第 5 步落下就没有"取消关机"这个 API。唯一恢复路径是 §3.1 的 3 条硬件唤醒路径。

### 5.3 进入 standby 的序列 (与关机相对)

停 OD → 停显示 → 落盘 → 关 sensor / 关光机 → 释放 NPU / DDR → 进低功耗态。★进 standby **前必须落盘** (retention 未确认, 见 §3.2)。

## 6. 续航口径 (两行分列, 不许混算)

| 状态 | 功耗 | 420mAh 电芯续航 | 适用场景 | 证据 |
|---|---|---|---|---|
| **待机 (`standby`)** | **0.15 W** | **~9.3 h** (340mAh 档 ~7.6h) | 摘下放包里一晚 | [推算] V2 口径 + **U2 裁决口径 A** (旧值 2.8h [旧口径·已作废]) |
| **关机 (`poweroff`)** | **≈0.21-0.40 mW** (静态 ~108µA @3.7V) | **约 5-11 个月** | 仓库/货架/长期存放 | [推算] `HW/POWER_SHUTDOWN_V3.md` §6 (AON 10µA → ~11 个月; 50µA → ~5.4 个月) |

★**这两行不是同一个口径, 不能相加、不能互相替代**:
- "待机" 是 **SoC 还活着** 的状态 ⇒ 续航小时级, 且佩戴会超皮肤温度红线;
- "关机" 是 **SoC 没电** 的状态 ⇒ 续航月级, 但 **SW 一律不承诺任何行为**。

★**锁死口径 (§0 #38, 老板 10-25 拍板)**: 续航写成 "**按需触发场景下 ≥1h**" —— **不写 "持续满载 ≥1h"** (持续满载 1.22W → 皮肤 96.1°C, 热学上不成立)。本表的 ~1.15h / ~6.1h / ~9.3h 是**分状态的功耗推算值**, 不是锁死的续航承诺 (旧值 20min / 1.8h / 2.8h [旧口径·已作废])。

### 6.1 ⚠️ 续航列的算式自检 (U2)

`HW/POWER_SHUTDOWN_V3.md` §6 的四行续航里, **三行算的是 "mAh ÷ (把 W 当 mA)"**, 只有关机行用的是真电流。逐行拆:

| 档 | 功耗 | HW 文档写的续航 | 实际算式 | 按 I = P/V @3.7V (DoD 0.9 → 可用 378mAh) | 差 |
|---|---|---|---|---|---|
| 关机 | 0.21-0.40 mW (108µA) | ~5.4 个月 | 420000µAh ÷ 108µA = 3889h | 378000µAh ÷ 108µA = 3500h ≈ **4.8 个月** | 口径 ✅ 一致 (用真电流) |
| 待机 | 0.15 W | 2.8 h | **420mAh ÷ 150mA** (把 0.15W 当 150mA) | I = 0.15/3.7 = 40.5mA ⇒ 378 ÷ 40.5 = **~9.3 h** | **差 ~3.3 倍** (满 420mAh 口径 ~3.7 倍) |
| 满载 | 1.22 W | 20 min | **420mAh ÷ 1220mA** | I = 1.22/3.7 = 330mA ⇒ 378 ÷ 330 = **~1.15 h** | **差 ~3.5 倍** |
| 按需触发 | 0.23 W | 1.8 h | **420mAh ÷ 230mA** | I = 0.23/3.7 = 62mA ⇒ 378 ÷ 62 = **~6.1 h** | **差 ~3.4 倍** |

★**差 ~3.3 倍 (DoD 0.9 口径) / ~3.7 倍 (满 420mAh 口径) 的来源就是漏了 "W → mA 要除以电池电压" 这一步**。注意:
- 关机行**不受影响** (本来就用 µA) ⇒ 老板锁死的 "关机(断电) <0.05W" 与 "5-11 个月" 两项都成立, 不必改;
- 待机/满载/按需三行是**偏保守** (把续航说短了), 对外若照抄 2.8h 会**低报**用户可用时长;
