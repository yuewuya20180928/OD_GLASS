★**逐格人话结论 (③)** ★
- **rootfs ≤ 30 MiB** ⇒ **不必须 eMMC** ⇒ 推荐 C (只读 rootfs + app/model A/B) 成立 ⇒ **≥128MB NOR 就够** (64MB NOR 除外, 它在 rootfs ≥ 20 MiB 时全格装不下 ⇒ **该列整列作废**)。
- **30 < rootfs ≤ 64 MiB** ⇒ **不必须 eMMC** ⇒ 降级 **方案 B** (单份 + overlay, 回滚退化为重刷) + **≥128MB NOR** ⇒ 板侧代价 0。
- **rootfs > 64 MiB** ⇒ ★**LAY-08 判 "必须 eMMC"**★, 但 ★**LAY-03 算术说 256MB NOR 仍装得下 (上限 199.969 MiB / 缩槽后 207.969 MiB)**★ ⇒ **这是本矩阵唯一的口径冲突带 (64, 71.969] MiB** (128MB NOR 装得下 vs LAY-08 说必须 eMMC) ⇒ **需总工/老板裁决** ⇒ 本单不替老板拍。
  - 冲突的根因: LAY-08 的 ">64MB ⇒ 必须 eMMC" 是 §4.1 时代写死的 `[推算]` 规则 (那时假定 SPI-NOR 封顶 64MB); 而 LAY-03 是纯容量算术 ⇒ **256MB NOR 这档在 §4.1 写的时候不存在**。
  - ★**型号可行性 (自己查, [官网])**: Winbond 官方 QSPI NOR 产品线密度覆盖 **8Mb~2Gb** (W25Q-NE) / **32Mb~2Gb** (W25Q-RW) / **8Mb~512Mb** (W25Q-PY) ⇒ **512 Mbit / 1 Gbit / 2 Gbit 全在官方产品线内** ⇒ 64/128/256 MiB 三档 NOR 都买得到; W25Q256JV 官网规格 = **256 Mbit / 32 MB · V=2.7~3.6 V** ⇒ 与 `VDD_3V3_IO` 电源域匹配。
  - ★**命名陷阱 (⇒ 订正拍板页用词)**: Winbond 料号里的数字是 **Mbit 不是 MB** —— `W25Q64` = 64 Mbit = **8 MB**, `W25Q256` = 256 Mbit = **32 MB** ⇒ 拍板页现在写的「外挂 SPI-NOR **16~64 MB**」在**两个层面都错**: ① 容量维度: ISS-080 已锁死 **flash ≥ 128MB (=1 Gbit)**; ② 料号维度: 「W25Q64」这类写法会被读成 64 MB, 实际是 8 MB。

## §2 rootfs 体积的可判区间 (★结论不依赖那个 0 数据★)

### §2.1 下界 (机器解 + 实跑自证)

- **决策有效下界 = 7.969 MiB (8355840 B)** —— `[实测]` 解析解 + 实跑自证 (上限处 LAY-03 PASS / +1 MiB 处 FAIL, 见 §1.1 表): **rootfs ≤ 7.969 MiB ⇒ 连最小档 64MB NOR 都装得下推荐 C 全表 ⇒ 存储选择根本不再是决策项** ⇒ 这就是决策区间的下边界。
- ★**ARS45 必须携带的最小集合** (rootfs 之外, 推荐 C 形态)★: bootloader **1** + kernel **8** + app_a/app_b **8×2** + model_a/model_b **2×11 (缩到实测下限)** + isp **1** + version_block **32 KiB** = **48.03 MiB**; 按 §4.1 基准 (model 15×2) = **56.03 MiB**。`[实测]` model 值 + `[推算]` 其余分区大小。

### §2.2 上界

- **上界 = 90 MB** —— `[推算]`: rootfs 一旦越过 90 MB, 推荐 C 的分区法 (86.03 MiB 量级的表) 本身要重排, 且 128MB NOR (上限 71.969 MiB) / 256MB NOR (上限 199.969 MiB) 的档位关系会翻转 ⇒ **90 MB 是"决策格局发生质变"的刻度**。
- ★**区间外也有确定答案 (没有"没答案"的空间)**★: rootfs > 90 MiB ⇒ 256MB NOR 仍撑到 **199.969 MiB** (缩槽后 207.969 MiB) ⇒ 再往上**必须 eMMC** ⇒ 板侧代价出现。⇒ **真值落在哪一格都按那一格办, 不存在"等数据出来再判"的状态**。

### §2.3 ★逐字写清★

> ★**rootfs 的真值仍 [0数据]** (板没做出来; `SW-FW-B3` severity medium 一直挂着) —— **但本矩阵每一格的结论都不依赖真值**: 真值落在哪一格就按那一格办 ★
>
> ★**本单不试图去填那个 0** —— 填不上 (板没做出来)。**本单的目标是让结论不再依赖它。**
>
> ★**A7S 那台板 (Allwinner A733 / Debian trixie) 的数不许冒充实测真值** —— 本机 `getent hosts radxa-cubie-a7s.local` **无解析** + 本机**没有 `sshpass`** ⇒ **这条路当前不可用** ⇒ **即便后来连上了, 也只能当 [实测]-代理下界, 且必须标明被测对象不是 ARS45 板**。
>
> ★**本单的降级方案 (查不到 ⇒ 给可判区间 + 逐格结论) 就在 §2.1~§2.2 本身** —— 它不是兜底选项, 它是本单的合格形态。

## §3 零代价可执行路径 (★一等选项★)

### §3.1 路径

> **demo 阶段只 ADB push, 不外挂存储** ⇒ **板侧零动作** (网表 / 板面 / 板框 / BOM 全不动) ⇒ ⇒ **Q3 不卡这一趟**

### §3.2 ★代价必须写清 (不许只写好处)★

| 得 | 失 |
|---|---|
| 板侧零动作 ⇒ 不触发板 md5 第二次 ⇒ 不作废 Gerber / 投产包 / 留证链 / 盖章 / 发布 | **无 S2 救砖** (BOOT + 厂商下载工具强制重刷那条链 `SW/FLASH_AND_VERSION.md` §4.4 / §4.5 整条不成立) |
| 存储容量决策可以**推迟到第一次真实构建之后**再判 (那时 rootfs 真值自然有了) | **无 A/B 回滚** ⇒ 只能**重刷** ⇒ 引 §4.1 **方案 B 的降级口径** (单份 + overlay, 回滚退化为重刷) |
| rootfs 大小不受 30 MiB 分档约束 (因为不住在 NOR 上) | 每次改系统都要插线 (但 §4.2 已论证: **锁死 #11 = 第一款不上无线 ⇒ 插线本来就要插** ⇒ A/B 的收益本来就只剩"省掉重刷 rootfs 这一步") |
| —— | 若最终存储放不下, 仍要付 eMMC 档的板面代价 —— 只是**可以晚点付, 而不是现在付** |

### §3.3 这条路径对 Q3 判定的意义

⇒ **给了老板一个【零代价选项】** ⇒ ⇒ **Q3 应当从「整卡挂着 (时限型)」正确分档, 而不是继续整卡挂着** —— 分档见 §4。

## §4 时点结论 (含板框依赖)

### §4.1 结论 (★标 [推算], 依据逐条列★)

1. **若最终要外挂存储 ⇒ 进网表的时点 = 板那一趟开工前** —— 引 `HW/PCB/BOARD_ONEPASS_COMMIT_ORDER.md` **INV-1** (板 md5 全生命周期只许变 1 次 ⇒ 全部 A 类步必须同趟做完) / **INV-2** (B 类步必须跑在最后一次 A 类步之后 ⇒ 留证产物永远只对应唯一一版板 md5) / **INV-3** (变更次数 ≤ 1) / **INV-4** (B 类步不许抢跑) ⇒ **晚进的代价 = Gerber + 投产包 + 留证链 + 盖章 + 发布全部作废重做**。
2. ★**但这个"时限"必须分档, 因为"板宽 12→15 mm"这个代价【只在产品板档成立】**★:
   - **台架板档 `B160x100`** (160×100 mm · 8 铜层 · 1.60 mm · 现役) ⇒ eMMC 的 ~25% 板面代价在 160 mm 宽的板上 **≈ 0** ⇒ ★**连 eMMC 档也不卡这一趟**★ ⇒ 时点压力从「**时限型**」降为「**建议型**」。
   - **产品板档** (`F30A` 60×30 / `P60x15` 60×15) ⇒ 板宽 12→15 mm 成立 ⇒ ★**eMMC 档才真卡 (时限型)**★。
   - ★**SPI-NOR 档**: `J_BOOT1` 焊盘位已在板 + 4×0Ω 已必装 ⇒ **两档都不卡**（台架板 / 产品板都零动作）★。
3. ⇒ ⇒ **Q3 的"时限型卡"是【分档才成立】的, 现在整卡挂着是【口径过粗】** ⇒ 本单的作用就是把分档算出来 (§1.3)。
