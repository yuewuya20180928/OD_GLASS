## 2. 相机模型与网格链

### 2.1 等距鱼眼模型 (推导)

球面投影下, 入射光线与光轴夹角 θ, 若要求像面上**弧长**与角度成正比 (等距投影), 则

```
r = f · θ                                            [r: 像面半径, f: 焦距]
```

用像元数表达 (等距的核心性质: **θ 与半径是线性的**):

```
r_n ≡ r / f_px = θ            (r_px = 图像上到主点的像素距离, f_px = f / 像元尺寸)
```

⇒ **一条鱼眼图像上的等半径圆, 对应场景里的等极角圆** —— 这就是"等距 = 角分辨率在径向均匀"的来源, 也是本项目后面所有反投影的基础。

**f 的来源** (本文采用的推导, 镜头厂标称值一到手即替换):

```
f_mm = (半对角尺寸 mm) / (对角半视场 60° 的弧度)
OV04C10 : 半对角 = √((2688×0.002/2)² + (1520×0.002/2)²) = 3.0880 mm → f = 3.0880/1.04720 = 2.9488 mm
AR0234CS: 半对角 = √((1920×0.003/2)² + (1200×0.003/2)²) = 3.3962 mm → f = 3.3962/1.04720 = 3.2432 mm
```

#### 2.3.1 ⚠️ 非等比缩放的处理规则 (写死, 免得以后各写各的)

**规则 (几何模型住在 sensor 像素系, 网格变换是显式的逐轴仿射)**:

```
sensor_px = out_px / s + o          (逐轴: sx, sy, ox, oy)
```

于是:

```
dx_sensor = dx_out / sx ,  dy_sensor = dy_out / sy      ← 先回到 sensor 系, 再算角度
r_sensor = √(dx_sensor² + dy_sensor²)
```

**为什么必须先回 sensor 系**: 若直接在输出图上算 `ψ = atan2(dy_out, dx_out)`, 非等比缩放会把 ψ 系统性拉偏 (1.333× 拉伸下, sensor 系里 45° 的方向在输出图上变成 atan(1.333) = 53.13° → **偏 8.13°**; 全向最大偏差 **8.21°**, 出现在 sensor 系 40.89° 方向上)。
**另一条路线 (不推荐)**: 在输出图上直接用**各向异性**鱼眼模型 —— 鱼眼圆变成椭圆, 模型不再是 `r=fθ`, 还得再套一层, 得不偿失。

**因此, ISP 的宽高比方案一旦拍板, 只要把 (sx, sy, ox, oy) 四个数写进配置表, 几何代码一行都不用改** —— 这是本设计的主要鲁棒性来源。
**顺带一条工程要求 (写进 REQ-GEO-07)**: sensor 全幅 → 640×480@60 的缩放**必须等比 (letterbox 加黑边)**, 理由: YOLO 的 anchor 先验与训练分布假定"目标形状不失真", 全局 1.333× 的纵向拉伸会让**所有**目标 (不只边缘) 的长宽比失真 33%, 远大于鱼眼自身在角落的 20.9% (表5)。⚠️ 该项属 `PROJECT_TRACKER.md` R16/Q16 的拍板范围, 本文只报软件影响, 不越界拍板。

> **β/ψ 的作用**: 相机装在眼镜上 (下俯 25°), 所以"图像正上方"对应的是**世界里的水平线以上 25°** —— 用户看框的位置时, 关心的是世界方位, 不是图像方位。§3.5 给出换算。

## 3. ★ 反投影: 图像像素 → 真实方位角 (步骤 + 参数来源 + 伪码)

### 3.1 步骤总览 (5 步, 每步一个公式)

```
输入: 检测框 (x1,y1,x2,y2) 在 [OD 640×640] 坐标系
      几何标定表 (f_px, cx, cy, k1, k2, k3)  + 网格变换 (sx, sy, ox, oy)  + 安装姿态 (beta, yaw)

步骤 0  坐标归一: 640×640 → 640×480 → sensor 像素系        (§3.1.1)
步骤 1  归一化半径: r_n = √(dx² + dy²) / f_px                (§3.2)
步骤 2  极角 θ:  解 θ(1+k1θ²+k2θ⁴+k3θ⁶) = r_n              (§3.3)   [等距 + KB 修正]
步骤 3  方位角 ψ = atan2(dy, dx)                             (§3.4)
步骤 4  世界方位: bearing / elev  (叠加 β, yaw)              (§3.5)
输出:  (θ, ψ) → 世界 (bearing, elev);  框的角张角 (Δθ_w × Δθ_h)
```

#### 3.1.1 步骤 0 — 坐标归一 (逐轴仿射, 全部写死成 4 个数)

```
OD 640×640 → ISP 640×480 :  x480 = x640 − 80 ,  y480 = y640 − 80        (OD 侧 letterbox 逆映射, k=1.0)
ISP 640×480 → 显示 800×600:  x800 = x480 × 1.25 ,  y800 = y480 × 1.25    (显示上采样)
ISP 输出 → sensor           :  x_s = x480/sx + ox ,  y_s = y480/sy + oy
                               (sx, sy, ox, oy 由 §2.3.1 的配置表给出; bars = ISP scaler 的 padding 参数)
```

> ⚠️ **80px / 1.25 这两个数是合成后的等效值, 与锁定链路一致**: OD 侧 letterbox 在 **640×480** 上做 (k=1.0, 上下各 80px), 显示侧再上采样 ×1.25 到 800×600 ⇒ 合成系数 = 1.25 (= 1/0.8, 与旧链路的净系数**完全相同**, 故框坐标数值不变)。
> ⚠️ **这两个数 (80px 黑边 / 1.25 上采样) 来自已定的缩放链**, 但它们是**硬编码在 `SW_REQUIREMENTS.md` §可复用清单里的 letterbox 参数**, 必须参数化 (A7S 的 `letterbox_inverse` 教训: 参数写死 `YOLO_INPUT_W/H=640`) → 写进 REQ-GEO-06。
> ⚠️ **黑边只生成一次 (CR-3)**: bars (黑边 padding) 的唯一来源 = ISP scaler 的 padding 参数 (写进 geo_calib.conf); OD letterbox 与显示上采样**只做仿射合成, 复用同一组 (ox, oy)**, 不许各自重算 → `SW/DISPLAY_MODE.md` §8.10。

### 3.2 步骤 1 — 归一化半径

```
dx = x_s − cx ,  dy = y_s − cy
r_n = √(dx² + dy²) / f_px            ← 等距模型下, r_n 的数值 = θ 的数值 (rad)
```

### 3.3 步骤 2 — 极角 θ (等距 + 畸变多项式修正 + 单调反解)

**理想模型 (无标定参数时的降级路径)**:

```
θ = r_n                                     (等距, 零成本, 零标定)
```

**标定模型 (推荐, 有镜头厂/ISP 标定表时)**:
等距模型与真实镜头总有偏差 (真实镜头不会严格等距), 偏差用**径向多项式**表达 (Kannala-Brandt 形式):

```
正向 (场景 → 像素):   r_n = θ · (1 + k1·θ² + k2·θ⁴ + k3·θ⁶)
反向 (像素 → 场景):   解 θ 使 θ·(1 + k1·θ² + k2·θ⁴ + k3·θ⁶) = r_n
```

**为什么用"正向 + 数值反解"而不是"直接写反向多项式"**:
1. 标定数据 (镜头厂给的畸变曲线) 本来就是正向的 (θ → r);
2. 正向函数对真实镜头**严格单调递增** ⇒ 反解唯一 ⇒ 数值反解 (Newton, 3~5 次迭代, 或 4096 点 LUT + 二分) **不会多解、不发散**;
3. 直接写反向多项式需要额外约束, 边缘容易跑飞 (这正是 OpenCV `fisheye::undistortPoints` 用迭代法的原因)。

**Newton 反解伪码**:

```
θ ← r_n                                   (初值: 忽略畸变项)
repeat 4~6 次:
    f  = θ·(1 + k1θ² + k2θ⁴ + k3θ⁶) − r_n
    df = 1 + 3k1θ² + 5k2θ⁴ + 7k3θ⁶
    θ ← θ − f/df
```

**LUT 方案 (投板后推荐)**: 对 θ ∈ [0°, 60°] 建 4096 点 LUT (`θ ↔ r_n`), 查询时二分 + 线性插值 ⇒ 每次反解 <0.2 µs, 且避免浮点迭代在边缘的收敛问题。**实现成本: 一次性的 4096×float 表 (16KB) + 一次二分**。

> **精度校验 (脚本自检)**: 含 (k1,k2,k3) = (0,0,0) / (−0.02, 0.01, −0.003) / (0.03, −0.01, 0.002) 三组系数、θ ∈ {0.5°, 5°, 15°, 30°, 45°, 60°}、ψ 六方向, **正反往返最大误差 ≤ 8e-15 rad** (纯数值精度, 不含标定残差)。`[实测·脚本自检]`

### 3.4 步骤 3 — 方位角 ψ

```
ψ = atan2(dy, dx)          (相机系: 0 = 画面右, +90° = 画面下)
```

**⚠️ 必须先做完步骤 0 (回到 sensor 系) 再算 ψ**, 否则非等比缩放会引入最大 8.21° 的系统偏差 (§2.3.1)。

### 3.5 步骤 4 — 世界方位 (叠加安装姿态)

相机绕自身横轴下俯 β (结构给, ≤25°), 绕竖轴偏航 yaw (结构给):

```
elev(bearing 侧) = asin( sinθ·sinψ·cosβ − cosθ·sinβ )       [世界仰角, deg]
bearing          = ψ + yaw                                   [世界水平方位]
```

**校验**: β=0, θ=30°, ψ=90° (画面正下方) → elev = 30.000000° ✓ (脚本自检)。
**含义**: 眼镜下俯 25° 时, 图像正下方 (ψ=90°, θ=0) 对应世界仰角 **−25°** (地面方向), 图像正上方对应 **+25°**。

### 3.6 ★ 参数来源 (f 与畸变系数从哪来 — 任务书验收项 1)

#### 3.6.1 ⚠️ 板端自标定的能力边界 (必须写进 RFQ, 否则边缘无解)

**棋盘格/圆点标定板只能覆盖 ±40° 左右** (标定板放不进鱼眼的边缘视野) ⇒

| 区域 | 标定覆盖 | 残差来源 |
|---|---|---|
| 中心 ±40° | 板端自标定可覆盖 | 标定板精度 + 拟合噪声 |
| 边缘 40°~60° (角落区) | ❌ **自标定覆盖不到** | **只能靠镜头厂标称畸变曲线** |

⇒ **RFQ 必须写死**: "厂商随货提供 **等距投影 f + 全视场畸变曲线 (至少 8 个角度点的 r(θ) 表) + 主点**"。没有这条, **边缘 (占画面 ~40% 面积) 的方位角就没有可信解**, 而边缘恰恰是眼镜用户最需要方位角的地方 (视野边缘的目标)。

#### 3.6.2 ⚠️ 标定参数缺失时的降级行为 (写死, 禁止"拿估计值当标称值")

| 情形 | 行为 | 禁止 |
|---|---|---|
| 有 f + 有 k | 正常反投影 (KB 路径) | — |
| 有 f, 无 k | 等距模型 (k=0), 打 `geo_model=equidistant` | 不得对外宣称"已标定" |
| 无 f (镜头未给) | 用 §2.1 反算值, 打 `geo_calib=derived` **+ `geo_quality=low`** | 不得把反算值当标称值用于对外承诺 |
| 连 f 都无 | 方位角 API 返回 `INVALID`, 只出像素框 | 不得输出"看起来对"的假角度 |

> **这条是本项目的通用铁律的落地**: `[0数据]` 必须标出来, 不能用 `[推算]` 冒充 `[实测]`。

### 3.7 代码伪码 (C++ 风格, 落到 `SW/` 代码目录)

```cpp
// ---------- 几何标定表 (来自 /etc/ars45/geo_calib.conf, 由 ISP/镜头标定流程写入) ----------
struct GeoCalib {
    // --- 等距模型基座 ---
    double f_px        = 0.0;   // 焦距 (像素) = f_mm / pitch_mm
    double cx          = 0.0;   // 主点 (sensor 像素系)
    double cy          = 0.0;
    // --- 残余径向畸变 (Kannala-Brandt 形式, 相对等距模型) ---
    double k1 = 0.0, k2 = 0.0, k3 = 0.0;
    bool   calibrated = false;  // 标定表是否真实存在 (false = 走降级路径)
    // --- 网格变换: sensor 像素 = out_像素 / s + o ---
    double sx = 1.0, sy = 1.0, ox = 0.0, oy = 0.0;
    // --- 安装姿态 (mech 提供) ---
    double pitch_down_deg = 25.0, yaw_deg = 0.0;
};

// ---------- LUT: 4096 点 theta <-> r_n (启动时按标定表生成) ----------
struct ThetaLut {
    static constexpr int N = 4096;
    std::array<float, N + 1> rn{};   // rn[i] = theta_i * (1+k1 th^2+k2 th^4+k3 th^6)
    void build(const GeoCalib& g) {
        const double th_max = M_PI / 3.0;          // 60 deg = 对角半视场上限
        for (int i = 0; i <= N; ++i) {
            const double t = th_max * i / double(N);
            rn[i] = float(t * (1.0 + g.k1*t*t + g.k2*std::pow(t,4) + g.k3*std::pow(t,6)));
        }
    }
    // 反解: r_n -> theta (二分 + 线性插值); 单调 -> 唯一解
    double theta_of(double rn) const {
        if (rn <= 0.0) return 0.0;
        if (rn >= rn[N]) return double(N) * (M_PI/3.0) / N;   // 越界(裁切/坏标定) -> 夹到边界
        int lo = 0, hi = N;
        while (hi - lo > 1) { const int mid = (lo+hi)/2; if (rn[mid] <= rn) lo = mid; else hi = mid; }
        const double seg = rn[lo+1] - rn[lo];
        const double w   = (seg > 0.0) ? (rn - rn[lo]) / seg : 0.0;
        return (lo + w) * (M_PI/3.0) / N;
    }
};

// ---------- 步骤 0: 坐标归一 (逐轴仿射) ----------
struct Pt { double x, y; };
inline Pt to_sensor_px(double x_out, double y_out, const GeoCalib& g) {
    return Pt{ x_out / g.sx + g.ox, y_out / g.sy + g.oy };
}

// ---------- 步骤 1~4: 像素 -> (theta, psi) -> 世界方位 ----------
struct RayDir { double theta_rad, psi_rad; double bearing_deg, elev_deg; };

inline RayDir pixel_to_ray(double x_out, double y_out, const GeoCalib& g, const ThetaLut& lut) {
    const Pt p  = to_sensor_px(x_out, y_out, g);
    const double dx = p.x - g.cx, dy = p.y - g.cy;
    const double rn = std::sqrt(dx*dx + dy*dy) / g.f_px;      // 步骤1
    const double th = lut.theta_of(rn);                        // 步骤2 (等距 + KB 修正)
    const double ps = std::atan2(dy, dx);                      // 步骤3
    const double b  = g.pitch_down_deg * M_PI / 180.0;
    const double s  = std::sin(th)*std::sin(ps)*std::cos(b) - std::cos(th)*std::sin(b);
    RayDir r;
    r.theta_rad   = th;
    r.psi_rad     = ps;
    r.bearing_deg = ps * 180.0 / M_PI + g.yaw_deg;            // 步骤4
    r.elev_deg    = std::asin(std::clamp(s, -1.0, 1.0)) * 180.0 / M_PI;
    return r;
}

// ---------- 框 -> 方位角语义 (应用层 API) ----------
struct BoxAngles {
    RayDir  center;          // 框中心的方位
    double  theta_w_deg;     // 框的角宽 (场景张角)
    double  theta_h_deg;     // 框的角高
    double  az_spread_deg;   // 框在方位角上的跨度 (左右两端点的 bearing 差)
};
BoxAngles box_to_angles(int x1,int y1,int x2,int y2, const GeoCalib& g, const ThetaLut& lut) {
    const RayDir c = pixel_to_ray(0.5*(x1+x2), 0.5*(y1+y2), g, lut);
    const RayDir a = pixel_to_ray(x1, y1, g, lut);   // 左上
    const RayDir b = pixel_to_ray(x2, y2, g, lut);   // 右下
    BoxAngles o;
    o.center = c;
    o.theta_w_deg = std::hypot(b.x - a.x, b.y - a.y) * 0.0   // 占位: 见下方"角张角"实现
                     + 0.0;
    // 角张角: 用四边的极角差 (沿径向) 与方位差 (沿切向) 分别量
    o.theta_w_deg = std::fabs(b.psi_rad - a.psi_rad) * 180.0 / M_PI;          // 切向(水平)跨度
    o.theta_h_deg = std::fabs(b.theta_rad - a.theta_rad) * 180.0 / M_PI;      // 径向(垂直)跨度
    o.az_spread_deg = o.theta_w_deg;
    return o;
}
```

> ⚠️ 上面 `box_to_angles` 的 `theta_w_deg` 两行是**示意**, 正式实现按 §7 REQ-GEO-04 的定义 (逐边在 sensor 系量角差) 落地; 数值自检见 §10 脚本 (往返误差 ≤ 8e-15 rad)。

### 3.8 精度预算 (每个误差来源多少度)

| # | 误差来源 | 量级 | 能否消除 | 等级 |
|---|---|---|---|---|
| E1 | **等距模型 vs 真实镜头** (k1..k3 未标定) | 边缘区最大; 无标定时角误差可达 **数度~十几度** | 需镜头厂畸变曲线 (RFQ) | `[0数据]` |
| E2 | **主点偏移** (cx,cy 未标定) | 偏心量 Δc px → 角误差 ≈ Δc/f_px × (1 rad→deg); 10px @ OV04C10 = **0.39°** | 需 ISP 标定 | `[0数据]` |
| E3 | **非等比缩放未补偿** | **8.21°** (1.333× 拉伸下 ψ 的全向最大偏角, 出现在 sensor 系 40.89° 方向; 45° 方向偏 8.13°, §2.3.1) | 显式 (sx,sy) 即可消除 | `[推算]` |
| E4 | **把鱼眼当直行反解** | **13.7°** (角落) / 9.9° (H边) / 2.3° (V边) (表6) | 用等距反解即消除 | `[推算]` |
| E5 | 像素量化 (框角点取整) | ±0.5 px → ±0.5×res = **0.02°** (OV04C10) | 亚像素框可再降, 不必做 | `[推算]` |

| E7 | 框本身的回归误差 (YOLO) | 与投影无关, 2~5 px (OD 640×640 尺度; 1 OD px = 3 sensor px = 0.1167°) → **0.23~0.58°** | 与几何无关 | `[推算]` |

**结论**: **E3 + E4 是软件能自己消除的 (且是最大的两个), 必须消除; E1/E2/E6 靠标定与结构公差, 属于 0 数据 → 必须进 RFQ 与结构接口; E5/E7 是噪声底, 不必优化。**

## 4. ★ 框龄口径: 从「像素行差」改为「方位角差」

### 4.1 为什么要拆成两个量 (先定义, 再改口径)

「框龄」这个词在本文之前被混着用了两种完全不同的东西, 必须拆开:

| 量 | 是什么 | 单位 | 由什么决定 | 谁用 |
|---|---|---|---|---|
| **时间框龄 (frame age)** | 框比它对应的画面晚几个**显示帧** | **帧** (无量纲整数) | **时间戳 + 帧周期** (`ceil(T_od/P)`) | 端到端延迟预算 (`SW/SW_REQUIREMENTS.md` §10.2) |
| **几何框龄 (angular staleness)** | 框代表的场景方向 与 当前画面内容代表的方向 之间的**角度差** | **度** | **投影模型 + 运动** | 感知质量判断 / 应用层"目标在哪" / 切档辅助 |

**旧口径的问题**: 用「像素行差」表达框龄, 隐含两个假设 —— (a) 像素位移 ∝ 方位角位移 (直行投影假设, 鱼眼下错 **2.3~13.7°**, 表6); (b) 运动是匀速直线 (转头/转身时不成立)。两个假设在鱼眼镜上都不成立。

### 4.2 ★ 时间框龄: **判定链一字不改** (回归保护)

```
age = ceil(T_od / P)              P = 16.67ms (60fps) 或 33.33ms (30fps)
```

**age 是纯时间量, 从时间戳算出来, 与投影模型、畸变、框的位置全都无关。**
⇒ **几何修正不可能改变 50.3ms ✅ / 67.0ms ❌ 的结论**。

### 4.3 ★ 几何框龄 (新口径): 定义与计算步骤

**定义**:

```
Δθ_geo = 框 (来自第 k 帧) 的方位角  与  当前显示帧 (第 k+n 帧) 中同一目标的方位角  之差
        = 角空间中两点之间的角距
```

**计算步骤 (每帧一次, 只对"被跟踪/被选中"的目标做, 不做全量)**:

```
输入: box_src (第 k 帧的框, OD 640×640 坐标)  +  box_cur (第 k+n 帧的框, 同系)
步骤 1  两个框的中心 → 步骤 0 归一到 sensor 像素系
步骤 2  各自反投影 → (θ_src, ψ_src) 与 (θ_cur, ψ_cur)      [§3]
步骤 3  角距:
        Δθ_geo = arccos( cosθ_src·cosθ_cur + sinθ_src·sinθ_cur·cos(ψ_src − ψ_cur) )
步骤 4  (可选) 时间当量: Δt_geo = Δθ_geo / ω_target        [§4.4]
输出:  Δθ_geo (deg) 写进打点 CSV
```

> **为什么用球面角距而不是"两点的像素距离"**: 角距是投影无关的量 (在 sensor 系算), 直接可比、可累加、可换算成时间当量。
> **为什么只对被跟踪目标做**: 全量框每帧反投影 = N×(LUT 二分) ≈ 100×0.2µs = 20µs, 其实也不贵; 但 Δθ_geo 只对"被选中/被跟踪的目标"有意义 (一个框和它自己比没意义), 所以语义上就是 per-track。

### 4.4 ★ 换算方法 (任务书验收项 2: 含 60fps / 30fps 两种帧率的时间量)

**核心换算 (一句话)**:

```
Δθ_geo (度)  →  时间当量 Δt_geo = Δθ_geo / ω        (ω = 目标相对头部的角速度, 度/秒)
一帧的角位移 = ω × P                             P = 16.67ms @60fps / 33.33ms @30fps
⇒ 60fps 下 Δθ_geo = 0.50° 相当于"落后 16.7ms" (ω=30°/s)
⇒ 30fps 下 Δθ_geo = 1.00° 相当于"落后 33.3ms" (ω=30°/s)
```

|---|---|---|---|

*(像素按 OV04C10 径向 0.0389°/px; AR0234CS 0.0530°/px → 同角度下像素数 ×0.733; 显示帧 800×600 = 640×480 ×1.25, 在显示帧上再乘该缩放系数)*

### 5.1 先复现硬件总工给的三个畸变量级 (表2)

> ✅ **三个数逐格复现** (OV04C10) ⇒ 本文的几何模型与 hw-lead 的镜头模型是**同一套**, 后续所有推导可以互相引用。

### 5.2 对「框位置 (方位角)」的影响

| 影响 | 量 | 处理 |
|---|---|---|
| 框中心的方位角误差 | **0°** (若用等距反投影) | 模型内自洽 |
| 框中心的方位角误差 | **2.3~13.7°** (若用直行反解) | 表6 → **必须用等距反解** (§3) |
| 框角点的方位角误差 | 同上 + 标定残差 E1 | 需镜头厂畸变曲线 |

⇒ **畸变对"框位置"的影响 = 全部体现在"你用哪个模型反解"**。用等距模型 → 畸变被正确吸收 (桶形畸变本来就是等距投影的一部分, 不是"误差")。

### 5.3 ★ 对「IoU / NMS」的影响 —— **结论: 畸变本身不降低 IoU** (重要澄清)

**推理**: 畸变是**全局单调的径向映射** `r_img = g(θ)·r_gn` (g 单调)。它对**所有目标一视同仁**地作用, 因此:

| 量 | 是否受畸变影响 | 理由 |
|---|---|---|
| 检测框 vs GT 框的 **IoU** | **否** (偏差 = 0) | GT 与检测都在**同一张畸变图**上; 单调径向映射对所有框同等作用, 框之间的相对包含关系不变 |
| **NMS 的去重判定** | 否 | 同上 (IoU 序不变) |
| 框的**方位角 / 张角** | **是** | 需要把像素换算成角 → 换算模型必须对 (§3) |
| 框的**长宽比** (场景真实形状) | **是** | 局部各向异性 (表5) |
| **小目标召回** | 可能略降 | YOLO 的 anchor/形状先验来自直行图训练; 鱼眼图上边缘目标的形状分布与先验不同 → 边缘召回可能掉几个点。**量化 = 0 数据** (必须投板后用真数据测, 别猜) |

> ⚠️ **这条必须写清楚, 否则会被误读成"畸变毁检测"**: 畸变不是检测精度问题, 它是**语义换算问题**。OD 依然照常跑, IoU 照常算, 框照常画。**老板 19:33 的决定对 OD 精度的影响 = 边缘召回的未知量 (0 数据), 不是"框不能用"。**

### 5.4 对「框形状 / 尺寸」的影响 (局部各向异性, 表5)

**推导**: 等距投影下, 场景里"等大"的一小块 (在球面上: 径向张角 d, 切向弧长 d) 在图像上:

```
径向:   Δr_rad  = f·d
切向:   Δr_tan  = f·θ·d/sinθ
各向异性 A = 切向/径向 = θ/sinθ          (等距)
                       = 1/cosθ          (直行)
```

| 位置 | θ | **等距 A** (鱼眼) | 直行 A | 切向角分辨率 (OV04C10) |
|---|---|---|---|---|
| 中心 | 0° | 1.000 (+0.0%) | 1.000 (+0.0%) | 0.0389 °/px |
| 垂直边 | 29.53° | **1.046 (+4.6%)** | 1.149 (+14.9%) | 0.0372 °/px |
| 水平边 | 52.23° | **1.153 (+15.3%)** | 1.633 (+63.3%) | 0.0337 °/px |
| 角落 | 60.00° | **1.209 (+20.9%)** | 2.000 (+100.0%) | 0.0321 °/px |

**读法**:
- 鱼眼下, 目标的图像长宽比最大失真 **20.9% (角落)**; 直行下是 **100%** ⇒ **鱼眼的形状失真比直行小 1.5~4.8 倍** ⇒ **对 OD 是净收益** (YOLO 的形状先验更接近)。
- 切向角分辨率在角落比中心**细 1.21×** (0.0321 vs 0.0389 °/px) ⇒ 边缘目标的细节比中心更好, 与"鱼眼角分辨率均匀"的直觉一致 (但均匀性是在径向严格成立)。

### 5.5 ★ 只对画面中心区做校正 —— 可行吗? (表4)

**"中心区"取多大?** 按 `|D| ≤ ε` 反解出中心区半径 r_c:

| ε (容许畸变) | θ_c | **r_c (OV04C10)** | **r_c (AR0234CS)** | r_c / 半宽 | **覆盖面积占比** |
|---|---|---|---|---|---|
| 1% | 9.91° | **255.1 px** (0.5102 mm) | 187.1 px | 0.190 | **3.6%** (3.8%) |
| 2% | 14.01° | **360.4 px** (0.7209 mm) | 264.3 px | 0.268 | **7.2%** (7.6%) |
| 5% | 22.08° | **568.2 px** (1.1364 mm) | 416.6 px | 0.423 | **17.9%** (18.8%) |

**结论: 不可行 / 不划算。 四条理由 (逐条可判)**:

| # | 理由 | 数字 |
|---|---|---|
| 1 | **收益区太小**: 想要 ≤1% 畸变 → 只覆盖画面 **3.6%** 面积; 放宽到 ≤5% → 也只覆盖 **17.9%**。画面其余 82% 仍是畸变的, 而用户看的目标大多不在正中心 | 表4 |
| 2 | **收益本身微小**: 中心区畸变本来就只有 1~5% ⇒ 即便完美校正, 对框位置的改善是 **0.05~0.25°** (E1 的一部分), 比标定残差 E2 (0.39°) 还小 | 表4 + §3.8 |
| 3 | **成本不降级**: ISP 的几何流水线是**逐帧逐像素重采样**, 区域化 (只校正中心圆) 在硬件上通常**不能只算那块** ⇒ 负载还是 30-50% 的几何流水线, 只是多一次边界判断 | `HW/LENS_SELECTION.md` §3.5 |
| 4 | **会造出可见的拼接缝**: 在 r_c 处, 内外两套映射的尺度差 = ε (1~5%)。r_c = 568px 时, 5% 的尺度跳变 = **28 px 的错位环** (肉眼可见的一道环) | 表4 |

⇒ **最终结论 (写死)**: **不做任何 LDC, 中心区也不做。**
**替代方案**: **框级解析反投影** —— 成本是 **O(框数)** (每框一次 LUT 二分, ≈0.2µs), 精度是**解析精确** (不是重采样近似), 而且**只在需要语义的时候才算** (§3.7)。100 个框/帧 ≈ 20µs, 对 S8 (画框 1.0ms) 的占比 **2%**。

> **一句话**: LDC 是**用 0.02ms 换不了的问题**去花 ISP 30-50% 的几何流水线预算; 我们要的是**角度**, 不是**形状**, 角度用解析法拿, 不要用重采样拿。

### 6.3 ⚠️ 一个必须说清的坑 (反投影框的"正确性陷阱")

如果将来真做方案 B, 会踩这个坑:
**"把框反投影回直角坐标再画"是错的** —— 因为**画面本身就是鱼眼的**。你在直角坐标里画出的"正确矩形", 叠到鱼眼画面上, 会与目标**错位** (目标在鱼眼图里是弯的)。
**要画弧框, 正确做法是**: 在**角空间**定义框 (角宽 × 角高), 再**正向映射**回鱼眼图 (每个角点 → 像素, 边 → 弧)。即**正向投影, 不是反投影**。
⇒ 所以"要不要把弯框反投影回直角坐标"这个问法本身就有陷阱: **反投影得到的是角坐标 (语义正确), 但画的时候必须正向投回图像 (像素正确)**。方案 B 若做, 走的是"角空间 → 正向投影 → 画弧", 不是"反投影 → 直角坐标 → 画直框"。

## 10. B6 自证复现命令 (别人一条命令就能复核本文的全部数字)

### 10.1 几何自检脚本 (本文所有表都由它算出)

```bash
cat > /tmp/fisheye_geo.py <<'PY'
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
FISHEYE_GEOMETRY 自检 (sw-lead, 2026-10-25) —— SW/FISHEYE_GEOMETRY.md §10
用法:
  python3 fisheye_geo.py            # 全表 + 自检 (rc=0 表示全部自检通过)
  python3 fisheye_geo.py --tables   # 只打印数字表 (与文档逐格对照)
"""
import math

DIAG_FOV_DEG = 120.0          # 对角 FOV (老板 10-25 19:42 工作基线: 鱼眼 等距 对角120)
P60 = 16.67                  # 帧周期 ms @60fps
P30 = 33.33                  # 帧周期 ms @30fps

SENSORS = {
    "OV04C10":  dict(pitch_mm=0.002, w=2688, h=1520,
                     note="1/3\" 2688x1520@60; 像元 2.0um [推算]"),
    "AR0234CS": dict(pitch_mm=0.003, w=1920, h=1200,
                     note="1/2.6\" 1920x1200@60; 像元 3.0um [官方]"),
}

def D2R(d): return d * math.pi / 180.0
def R2D(r): return r * 180.0 / math.pi

def build_sensor(name, diag_fov_deg=DIAG_FOV_DEG):
    s = dict(SENSORS[name]); s["name"] = name
    s["half_diag_mm"] = math.hypot(s["w"]*s["pitch_mm"]/2.0, s["h"]*s["pitch_mm"]/2.0)
    s["f_mm"]  = s["half_diag_mm"] / D2R(diag_fov_deg/2.0)      # 等距: f = 半对角 / theta_diag_half
    s["f_px"]  = s["f_mm"] / s["pitch_mm"]
    s["res_rad_deg_px"] = R2D(1.0 / s["f_px"])
    s["th_h"] = (s["w"]/2.0) / s["f_px"]
    s["th_v"] = (s["h"]/2.0) / s["f_px"]
    s["th_d"] = math.hypot(s["w"]/2.0, s["h"]/2.0) / s["f_px"]
    return s

def distortion_pct(theta_rad):
    """D% = (r_实际 - r_理想)/r_理想; 实际=等距 f*theta, 理想=同焦距直行 f*tan(theta)"""
    return 100.0 * (theta_rad - math.tan(theta_rad)) / math.tan(theta_rad)

def theta_of(rn, k1=0.0, k2=0.0, k3=0.0, iters=60):
    """反解: r_n -> theta (等距 + KB 多项式), 单调 -> Newton"""
    if rn <= 0.0: return 0.0
    th = rn
    for _ in range(iters):
        f_  = th*(1.0 + k1*th**2 + k2*th**4 + k3*th**6) - rn
        df = 1.0 + 3*k1*th**2 + 5*k2*th**4 + 7*k3*th**6
        step = f_/df if df != 0 else 0.0
        th -= step
        if abs(step) < 1e-14: break
    return th

def pixel_to_azimuth(x, y, cx, cy, f_px, k1=0.0, k2=0.0, k3=0.0):
    dx, dy = x-cx, y-cy
    rn = math.hypot(dx, dy)/f_px
    return theta_of(rn, k1, k2, k3), math.atan2(dy, dx)

def azimuth_to_pixel(theta, psi, cx, cy, f_px, k1=0.0, k2=0.0, k3=0.0):
    rn = theta*(1.0 + k1*theta**2 + k2*theta**4 + k3*theta**6)
    return cx + rn*f_px*math.cos(psi), cy + rn*f_px*math.sin(psi)

def elevation_of(theta, psi, pitch_down_deg=0.0):
    b = D2R(pitch_down_deg)
    s = math.sin(theta)*math.sin(psi)*math.cos(b) - math.cos(theta)*math.sin(b)
    return R2D(math.asin(max(-1.0, min(1.0, s))))

def age_of(tod, P): return int(math.ceil(tod/P - 1e-9))

def table_sensor():
    print("="*100); print("[表1] 鱼眼(等距) 120° 对角: 传感器 / 镜头 / 角分辨率"); print("-"*100)
    print("%-10s %-9s %-9s %-9s %-9s %-9s %-9s %-9s" % ("sensor","pitch","array","f_mm","f_px","halfDiag","res_rad","diagFOV"))
    for n in SENSORS:
        s = build_sensor(n)
        print("%-10s %-9.4f %-9s %-9.4f %-9.1f %-9.4f %-9.4f %-9.2f" % (
            n, s["pitch_mm"], "%dx%d"%(s["w"],s["h"]), s["f_mm"], s["f_px"],
            s["half_diag_mm"], s["res_rad_deg_px"], 2*R2D(s["th_d"])))

def table_distortion():
    print(); print("="*100)
    print("[表2] 边缘畸变量级 D% = (r_实际-r_理想)/r_理想; 复现 HW/LENS_SELECTION.md §3.1 的 -39.5/-29.4/-9.0")
    print("-"*100)
    for n in SENSORS:
        s = build_sensor(n); print("  -- %s --" % n)
        for label, th in (("角落(对角)", s["th_d"]), ("水平边中点", s["th_h"]), ("垂直边中点", s["th_v"])):
            print("     %-12s theta=%6.2f deg   D=%+6.1f%%" % (label, R2D(th), distortion_pct(th)))

def table_roi():
    print(); print("="*100); print("[表3] ⚠️ ISP 输入模式决定真实 FOV ('不裁剪' 必须落到全幅)"); print("-"*100)
    for n in SENSORS:
        s = build_sensor(n)

def table_center_zone():
```
