# DISPLAY_FRAME_COUNTER —— 显示帧计数器规格 (手机测端到端延时的前置)

> 出品: 项目总工 (moli) · 2026-11-04 · 对应 ISS-179 · 老板 2026-11-04 10:03 决定「高速相机不采购, **用手机测**, 只测端到端延时」
> ★**为什么必须有它**: 手机要能"数出帧" ⇒ 屏上必须有一个**可数的帧号/时间码** ⇒ 没有它, 手机拍到的只是"画面变了", 数不出延时。

---

## 0. 一句话

在**送进 MIPI-DSI 之前的那一帧**上, 用**已有的画框通路**把一个**单调递增的帧号 + 相对开机毫秒时间戳**烧进左上角 ⇒ 手机慢动作拍屏就能数出帧 ⇒ 端到端延时 = 数出来的帧差 × 每帧时长。

---

## 1. 烧在哪 (★最容易做错的一处)

| 项 | 要求 | 为什么 |
|---|---|---|
| 位置 | **合成之后、送进 DSI 之前**的那一帧 (即 `t_compose` 之后的输出缓冲) | 手机拍到的是屏上**实际显示**的那一帧 ⇒ 屏上帧号 = 实际显示帧号 |
| 通路 | **复用已有的画框通路** (Y 平面那一路, NV12 Y plane) | ★别新开一条渲染路径 ⇒ 别动合成段结构、别加第二套缩放 |
| 帧号取值 | 取**"这一帧进合成之前"的计数器值**, 不是"画完这帧之后"的计数 | ★否则**差一帧** (60fps 下 16.7ms, 直接把 60ms 判据打穿) |

★**差一帧是本规格最致命的风险** ⇒ 实现后必须做 **§5 自证**。

---

## 2. 画面内容

```
┌──────────────────────────────────────────┐
│ #0001234  T+012345ms        ← 左上角      │   ← 只占左上角一小块, 不挡检测框
│                                          │
│              (检测画面 + 画框)            │
│                                          │
└──────────────────────────────────────────┘
```

| 元素 | 规格 |
|---|---|
| 帧号 | `#%07d` —— 7 位, 零填充, 单调递增 (uint32 回绕无碍) |
| 时间戳 | `T+%06dms` —— **相对开机**的毫秒 (取软件打点同一时钟域) |
| 位置 | 左上角, 边距 8 px (1920×1080 基准) |
| 字号 | 等宽粗体, 高 24 px (1080p 下 ≈2.2% 高度) ⇒ 手机慢动作里能数清 |
| 颜色 | **白字 + 1px 黑描边** (避免亮背景看不清); 可选反色 |
| 背景 | **不要**加不透明底板 (会挡画面) |
| 开关 | **默认关**; 由配置/环境变量打开 (例: `DEMO_FRAME_COUNTER=1`) ⇒ 出厂默认行为不变 |

★**时间戳用哪个时钟**: 与 `SW/ARS45_INT8_CHAIN.md` §4 的 9 个埋点**同一时钟域** (软件单调时钟, 建议 CLOCK_MONOTONIC), 不要混用 wall clock ⇒ 否则和打点对不上。

## 3. 接口签名 (可直接照抄实现)

```c
/* 帧计数器: 由合成段在"送进 DSI 之前"调用一次 */
/* 约定: 调用方传入**本帧进入合成之前**取到的帧号与时间戳 */
typedef struct {
    uint32_t frame_no;      /* 单调递增帧号 (进合成之前取) */
    uint32_t t_ms;          /* 相对开机毫秒 (同一时钟域) */
} demo_fc_t;

/* 画在哪: NV12 的 Y 平面, 左上角; 只改 Y, 不碰 U/V (与画框同一条规则) */
void demo_frame_counter_draw(uint8_t *y_plane,
                             uint32_t y_stride,   /* 字节/行 */
                             uint32_t width, uint32_t height,
                             const demo_fc_t *fc);
```

**调用点 (唯一)**: 合成段生成输出帧之后、`t_display` 打点之前。
★**不要**在画框函数里自增计数 ⇒ 那会得到"画完之后的计数" = 差一帧。

---

## 4. 与 9 个埋点的关系 (来源 `SW/ARS45_INT8_CHAIN.md` §4)

| 埋点 | 含义 | 与帧计数器的关系 |
|---|---|---|
| `t_capture` | sensor 曝光 → 帧到 CPU | 手机法**测不到**这个起点 (曝光瞬间只有传感器知道) |
| `t_pre` | 缩放/归一化 | 软件段 |
| **`t_npu`** | **纯 NPU 推理** | ★**M-NPU 的数从这里出** (决定 age=1 还是 2) |
| `t_sdk_total` | SDK 总耗时 (含反量化) | 与 `t_npu` 差值 = 反量化开销 |
| `t_decode` | decode + NMS | 软件段 |
| `t_draw` | 画框 | ★**帧计数器的绘制算在这段之后** |
| `t_compose` | 叠加进显示帧 | 帧计数器烧在这之后 |
| `t_display` | 送 MIPI-DSI → 光机 | 端到端预算最后一跳 |
| `t_e2e` | 端到端 (软件口径) | **口径C 的数**: 读出完成 → 出光 |

★**帧号 + 时间戳打印在同一帧上** ⇒ 手机拍到的帧号与软件日志里的 `t_display` 可以**对表** (帧号 ↔ 时间戳), 这是把"手机数出来的数"和"软件打点"缝在一起的关键。

## 5. 自证 (★实现完必须跑, 不许跳)

| # | 判据 | 怎么验 |
|---|---|---|
| S1 | 帧号**连续无跳变** | 连跑 300 帧, 屏上帧号与日志里的帧号一一对应, 差 0 |
| S2 | **帧号与 `t_display` 打点同帧** | 取第 N 帧: 屏上帧号 == 写该帧时打点的帧号 (★差一帧就红) |
| S3 | 时间戳单调不减 | 300 帧内 `t_ms` 不回退 |
| S4 | 关闭开关后画面无变化 | `DEMO_FRAME_COUNTER` 不设 ⇒ 输出帧与开之前**逐字节相同** |
| S5 | 不碰 U/V | 只改 Y 平面 ⇒ 画面不偏色 (已有判据: 框不错位/无色偏) |

---

## 6. 测不了的 (不许过度承诺)

- ★**分不出"面板自身光电延迟"** ⇒ **M-OPTIC (只测面板那一段) 继续 deferred, 不因本功能复活** (老板 10-25 决定)。
- ★**不是曝光瞬间的精密基准** (±1 帧 + 滚动快门) ⇒ **口径A 的起点仍以软件打点为准**。
- 主观验收 (M-DIZZY) 与本功能**互补不替代** (它验不了 "60ms" 这个数)。
