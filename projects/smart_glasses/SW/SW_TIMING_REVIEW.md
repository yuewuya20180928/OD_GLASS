### 2.3 逐条不通过

**F1 · 复位释放时刻不由已画出的器件决定** ❌
- `PG_VCORE` / `PG_VIO` 只是测试点 (网表 P8: "PG (开漏, 需上拉)", note 写"若原厂要求 PG 参与上电时序, 在此补上拉电阻位") → **当前它们既没有上拉, 也没有连到任何逻辑**。
- 监督器分压接的是 `RAIL_V_SOC_IO` (网表 P8: `V_SOC_IO | R_SUPV_DIV1 | R_SUPV_DIV1`)。
- ⇒ 只要 V_CORE 慢于 V_SOC_IO, SoC 就会在主轨还在爬的时候被释放复位。
- **保守假设 (原厂 TBD-12 未回时的写法)**: 假设 SoC 对 V_CORE 的要求是"必须在 RESET 释放前稳定 ≥ X ms", X 未知 → **软件侧按"复位释放 = 所有轨都稳"设计, 并且 EVT 必须实测 V_CORE 与 RESET_N 的相对时刻**。

**F2 · 网表 RC 注记与原值不符** ❌ (这是会让 SW 返工的典型)
- 网表 P8 `C_RST` 行 note: "τ=100ms; **释放时期待原厂 TBD-12**"。
- 实算: 释放 τ = (10k+1k)×100nF = **1.1ms**, 断言 τ = 1k×100nF = **100µs**; 差 **90.9 倍**。
- **后果**: `SW/FLASH_AND_VERSION.md` §4.5.2.1 的 S2 救砖时序表 (t1/t2/t3/t4) 是照"复位被拉住 100ms" 的假设写的; 真值是 1.1ms → **SOP 里任何"先做 A 再按 RESET"的时序化操作都不可靠** (见 §5.5)。

**F3 · 监督分压是 0Ω 位, 装配规则缺失** ❌
- `R_SUPV_DIV1` / `R_SUPV_DIV2` 的 value 都写 "[待选型] 分压上臂 (0Ω 跳线位)" / "(0Ω 跳线位)", dnp = **必装**。
- 两颗都装 0Ω ⇒ 下臂 = 0 ⇒ SENSE = GND = **V_SOC_IO 对地短路** (TPS62130A 输出短路 → 进限流 → SoC IO 域塌陷 → 整机不启动, 且器件发热)。
- 两颗都 DNP ⇒ SENSE 悬空 ⇒ 释放时刻未定义。
- ⇒ **必须写死: 上臂装实值 (监视 3.0V 需 R1/R2=6.407, 例如 R1=64.9k/R2=10k), 下臂装实值, 两颗都不得为 0Ω; 且 BOM 必须区分 "0Ω 位" 与 "实值位"**。

**F4 · 供电器件的控制脚在网表里不存在** ❌
- `TPS62130A` (2 颗) 有 `EN` + `SS`; `TPS7A20` (7 颗) 有 `EN`; `TPS3808G01 类` (1 颗) 有 `CT` + `MR`。
- grep 全网表: **EN 0 条、SS 0 条、CT 0 条、MR 0 条**。
- ⇒ "电源什么时候起、复位什么时候放" **在网表层面是未定义的**。这正好解释了 F1: PG 没有上拉、没有逻辑消费者。

**F5 · RESET_N / BOOT_N 的上拉挂在另一条 1.8V 轨上** ❌ (自己发现, 任务书未要求)
- `R_PU_RESET_N` 10k → `RAIL_VDD_1V8_IO`; `R_PU_BOOT_N` 10k → `RAIL_VDD_1V8_IO`。
- 而 `VDD_1V8_IO` 是**另一条** 1.8V 轨 (TPS7A20 从 SYS 生), `V_SOC_IO` 本身就是 3.3/1.8/1.2V 三选一 [TBD-02] —— 若 V_SOC_IO = 1.8V, 则 SoC 的 IO 域是**另一条 1.8V**。
- ⇒ **两条不同的 1.8V 轨在驱动同一个复位/启动网**: IO 域掉电时复位脚仍被"外部 1.8V 撑着" ⇒ 幽灵复位 / 释放不可靠。
- **建议**: RESET_N/BOOT_N 的上拉应改挂 **SoC 自己的 IO 电源域** (V_SOC_IO), 而不是另一条 LDO 的 1.8V; 这条要等 TBD-02/TBD-01 定了电压才能改 (换料不换板, 改 1 颗电阻位置)。

**F6 · 监督器自身的供电与被监督轨同源** ⚠️
- `U_SUPV VDD` = `RAIL_VDD_1V8_IO` (也是 SYS 的 LDO), 被监督的 V_SOC_IO 也是 SYS 的 DC-DC ⇒ **两者同时起**。
- TPS3808 在 SENSE < VIT 时会主动拉低 RESET (这没问题), 但**它自己上电到"能正确判定"之间的窗口没有定义** ⇒ 上电初期 RESET 的电平是"未定义"而不是"确定拉低"。
- ⇒ 建议监督器改挂一条**不受开关控制的常供电轨** (SYS 直供或独立 LDO), 或至少在 BOM 里写死 "U_SUPV 的 VDD 必须是上电最早起的那条轨"。

### 2.4 推荐方案 (不改总体方案, 只补 4 处)

> 以下是**软件侧提出的硬件改动请求**, 由项目总工裁决; 本文不拍板。

|---|---|---|---|
| **P0** | **把两路 PG 接进复位链** | 两个 DC-DC 的 PG (都是开漏) **可以直接并联** (开漏输出允许线与) → 并联点加一颗上拉 → 用 1 颗小 N-MOS (或双管阵列) 把 `RESET_N` 拉低, 除非该点为高 | 零新增 IC 级别 (1 MOS + 1 上拉 + 1 栅阻); 效果 = 复位只在 **V_CORE 与 V_SOC_IO 同时在 regulation** 时释放, **不依赖原厂 TBD-12 也能把时序定住**。⚠️ 前提: PG 极性必须先按 TPS62130A datasheet 核对 (高阻=好 还是 拉低=好) —— 极性反了 AND 逻辑就反 |

| **P1** | **复位/启动上拉改挂 SoC 的 IO 域** | 等 TBD-02 定 V_SOC_IO 电压后, 把 R_PU_RESET_N / R_PU_BOOT_N 改挂 V_SOC_IO | 消除两条 1.8V 轨共驱一个复位网 |

### 2.5 保守假设 (TBD-12 未回时, 软件侧按这个写)

| 假设 | 保守取值 | 依据 / 影响 |
|---|---|---|
| A1 | **RESET 释放 = 所有电源轨都稳定** (不假设任何轨先起) | 原厂 TBD-12 未回; 软件的启动流程必须先做"电源域自检"再跑 OD |
| A2 | **RESET 释放最坏时间上界按 100ms 预算** (软启动未知 → 用 10× 裕量) | 20ms (监督器) + 1.32ms (RC) + 未知爬升 → 取 100ms 规划; 产测/产线的"上电到可通信"超时设 ≥ 2s |
| A3 | **RESET 在运行期可能被再拉低** (欠压/监督窗口跌落) | 软件必须处理"运行中被复位" ⇒ 已有看门狗 M8-R5 的恢复逻辑要覆盖 "复位后自动重进 OD" |
| A4 | **SoC 的 IO 域电压 = V_SOC_IO (TBD-02)**, 复位/启动脚的电平域 = IO 域 | 决定上拉挂哪条轨; TBD-02 未回前, 复位脚的电平判定写"跟随 SoC IO 域" |
| A5 | **首读温度 = −256°C** (TMP117 复位后) | [官方] TMP117: 复位后温度寄存器读 −256°C 直到首次转换完成; 软件必须丢弃首读 |
| A6 | **I2C_A 速率上限 100kHz** | 见 §3.5; 跨铰链电容 300pF 时 t_r=1195ns > 标准模式 1000ns 上限 |

## 3. 充电状态回读链评审 (任务项 2)

### 3.1 两条链的实际走法

```
【数字链 (快, µs 级)】BQ25896 STAT(开漏) ─CHG_BOARD─ J_CHG pin5 ─铰链─ R_PU_CHG_STAT 10k → ??? ─→ SoC GPIO
                       BQ25896 PG  (开漏) ─CHG_BOARD─ J_CHG pin6 ─铰链─ R_PU_PG 10k → RAIL_VDD_3V3_IO ─→ SoC GPIO
【模拟链 (慢, 0.4s 级)】VBUS_5V(充电板) ──?铰链?─ R_VBUS_DET_1 1M ─┬─ NET_VBUS_DET ─→ SoC ADC (+100nF)
                                            BAT(镜脚本地) ─ R_BAT_DET_1 1M ─┴─ NET_BAT_DET  ─→ SoC ADC (+100nF)
```

### 3.2 开漏跨铰链: 逐项分析

| 问题 | 分析 | 结论 |
|---|---|---|
| **上拉放哪** | `R_PU_CHG_STAT` 标 `CHG_BOARD`, `R_PU_PG` 标 `MAIN_PCB` —— **两者不一致**; 而 `RAIL_VDD_3V3_IO` 是 MAIN_PCB 的轨, **充电板根本没有 3.3V 轨** (充电板只有 VBUS_5V 5V / REGN 5V / BAT_CHG / TS) | **❌ 必须把 CHG_STAT 的上拉改到镜脚本地 3.3V** (与 PG 对齐)。若照网表装在充电板: 轻则上拉无源 → **CHG_STAT 在铰链上悬空** (SoC 读到随机值 → "充电时禁 OD" 门禁误触发/漏触发); 重则被迫接 5V → **5V 灌进 3.3V 的 SoC GPIO** |
| **要不要施密特缓冲** | 数字链的干扰源是铰链反复开合的机械噪声 + 板上开关噪声。**10k 上拉 + 接收端 100nF~1µF 滤波 + 施密特** 三选一: (a) 只上拉不滤波 → 边沿慢、易被耦合脉冲误触发; (b) 上拉 + 接收端 RC → 上升沿变慢 (10k×200pF=2µs, 无碍, 因为状态是慢信号) 且对 <2µs 的毛刺完全免疫; (c) 施密特 → 额外一颗 IC + 2 个 SoC GPIO, **且 SoC 引脚预算已经很紧** (C-min 41 / C-base 57, `HW/SOC_PIN_BUDGET.md`) | **不需要施密特**。推荐 (b): 上拉挪到镜脚本地 3.3V + 接收端加 **10nF~100nF** 到地。理由: CHG_STAT/PG 是**慢状态位** (充电开始/结束是秒级事件), 用时间滤波换抗噪比用施密特更划算, 而且省 SoC 引脚 + 省一颗 IC + 少一个 5.1k 级的额外漏电路径 |
| **上升沿** | 10k 上拉 + 铰链线缆电容 (估 100-300pF) ⇒ t_r = 0.8473×10k×C = **0.85~2.5µs** | 对"秒级状态位"完全够; 但**它决定了 SW 的采样策略**: 不能在中断里立刻采, 要等边沿稳定 (≥1ms) 再判 |
| **远端漏电** | 铰链 FPC 的表面漏电阻 (污染/汗液/潮气) 可到 10⁹Ω 级 [推算]; 10k 上拉 + 1GΩ 漏电 ⇒ 漏电造成的电平偏移 = 3.3V × 10k/1.01GΩ ≈ **33µV** ⇒ 完全可忽略 | ✅ 漏电不是问题 (因为上拉只有 10k, 不是 100k)。**但这正是"上拉必须小"的另一个理由**: 若为了省电流把上拉提到 100k, 漏电偏移变成 330µV (仍可忽略) —— 结论不变, 10k/4.7k 都行, **关键是上拉在接收端且不超过 100k** |
| **开漏驱动端在充电板、接收端在镜脚, 中间是开漏** | 充电板掉电 (没插 USB) 时 BQ25896 的 STAT 是高阻 ⇒ 接收端上拉 ⇒ 读到 "高" ⇒ 必须定义 **"高 = 不在充电"** 还是 "高 = 未知" | ✅ **语义已由 P10 页写明 (不再需要回原厂)**: `STAT` 开漏 **LOW = 充电中 / HIGH = 完成或禁用 / 1Hz 闪烁 = 故障**; `PG` 开漏 **LOW = 输入源良好** (VBUS 在 VVBUS_OP 内且 IBATSRC>30mA)。⚠️★**同名不同义**: 本设计里三个都叫 "PG" 的信号语义相反 —— BQ25896 `PG` **低=好**、TPS62130A `PG` **高阻=好**、`U_SUPV RESET` **低=复位中** ⇒ SW 侧必须**按来源命名** (`chg_pg_src_ok` / `dcdc_pg_good` / `soc_reset_n`), 否则必然写反 |
| **STAT 的 1Hz 闪烁 = 故障** | P10 页写明 STAT "1Hz 闪烁 = 故障" | ★**SW 的充电状态机必须解三态 + 闪烁**: 充电中 / 完成或禁用 / **闪烁=故障**。闪烁不是"充电"也不是"完成" —— 若只写二态判断, 故障会被误判成"完成"或"未充电" ⇒ 禁 OD 门禁会放行一个正在报故障的充电系统。⇒ 判据: 连续 3 个采样窗口看到翻转 ⇒ 判 `chg_fault` 并上报 + 保持禁 OD |
| **是不是唯一的充电判据?** | 不是。BQ25896 的 I2C **已裁决不过铰链** (V1.5 裁决 4) ⇒ **软件永远读不到充电 IC 的寄存器** ⇒ 充电状态只有 CHG_STAT/PG/VBUS_DET 三条 | ⇒ 这直接决定 SW 的 **M-CHRG 门禁** 实现: 只能用这三条, **不许写"读充电 IC 寄存器"的代码** |

### 3.3 模拟链 (VBUS_DET / BAT_DET) 的问题 —— 这是本项里比开漏更严重的一半

| 项 | 数值 | 后果 |
|---|---|---|
| 源阻抗 | (1M×1M)/(1M+1M) = **500kΩ** | ADC 前端 RC 太大 |
| 时间常数 | 500kΩ × 100nF = **50ms** | 一次转换读数要等 |
| 建立到 12bit 半 LSB | n·τ, n = ln(1/(0.5·LSB/FS)) = 9.01 ⇒ **451ms** | "插上充电器 → 立刻禁 OD" 会有 **0.45s 空窗**; 充电时皮肤温升风险就在这 0.45s 里 |
| ADC 输入漏电流 1µA (量级) × 500kΩ | **0.50V 偏移 = 满量程 15.2%** | 读数基本不可信 (SoC 具体 ADC 漏电流 [0数据]) |
| 静态功耗 | 3.3V/2M = **1.65µA** | 功耗不是问题, **精度才是** |
| 分压位置 | 网表: 分压在 MAIN_PCB, 5V 原始轨跨铰链 (pin7); P2 叙述: "跨铰链侧 (充电板测 VBUS, 高阻分压)" | **网表与叙述矛盾** ⇒ 若真按网表 (5V 跨铰链), 铰链上的 ESD/浪涌会直接打到 SoC 的 ADC 脚, 需要钳位 |

**结论**: 模拟链现在的值**不可用**。软件侧要求 (供硬件参考):
1. 分压降到 **100k+100k** (源阻抗 50kΩ, τ=5ms, 12bit 建立 ~45ms) 或 **47k+47k** (τ=4.7ms, 建立 ~42ms; 静态 35µA, 可接受); 漏电流 1µA 时偏移 50mV/47mV, 可接受。**改电阻不改板** ✅
2. 若必须跨铰链传 5V → 接收端加钳位 (TVS 或串限流 + 肖特基), 并把分压挪到充电板侧 (2.5V 跨铰链) —— 但充电板无 3.3V 轨, 分压源只能是 VBUS_5V, 可行。
3. **无论怎么改, SW 都必须把 VBUS_DET/BAT_DET 当成"秒级慢量"**: 长采样时窗 + 丢弃前 N 次 + 取中位数/均值 + 双阈值迟滞 (避免在阈值附近抖动), 且**掉线/异常时按"未充电"处理但要打告警**。

### 3.4 对 "充电时禁 OD" 门禁的直接含义 (M-CHRG)

- **主判据 = CHG_STAT (数字, µs~ms 级)**, 备判据 = PWR_GOOD, 辅助 = VBUS_DET (慢, 只做确认与趋势)。
- ★**失效安全方向: "状态未知 ⇒ 当作在充电"** (而不是"当作没充电")。理由 (P10 页): BQ25896 的 **CE 被 R_CE 拉低 = 允许充电**, 且 hw-lead 明写"拉低的好处 = **SoC 死机也能充电**" ⇒ **充电的发生不依赖 SoC** ⇒ 当 SoC 读不到状态时, 实际可能正在充电 ⇒ 必须按"在充电"处理 (禁 OD)。这条与 §4.3 的温度失效安全是同一个方向。
- **门禁必须"充电一开始就禁"** ⇒ 只能靠数字链; 模拟链 451ms 的建立时间**不允许**当主判据 (充电 0.8W → 皮肤 75.1°C 的场景下, 0.45s 的空窗是要写进风险的)。
- **禁止**在 SW 里写"读充电 IC 寄存器" (I2C 不过铰链, V1.5 裁决 4)。

## 4. ★TMP117 的物理测点定案 (任务项 3)

> **这是本单里唯一"要我做决定"的项**: 器件已定 (TMP117, I2C_A 0x48, 3.3V), **测点由软件侧定**, 因为它直接决定软件能不能用温度做降载/关机。

### 4.1 候选点取舍

| 候选 | 它测到的是什么 | 能不能做降载/关机依据 | 判定 |
|---|---|---|---|
| **A. SoC die** | TMP117 是**外部**器件, 贴在 SoC 热焊盘/背面测的是**板面温度**, 不是结温 Tj (Tj 还要加上 P_die × R_θ(j-a)) | ❌ 不能代表结温 ⇒ 不能做结温保护 | **不选** (但见 §4.4: 结温保护要另找源) |
| **B. 镜腿 (镜脚) 贴皮肤侧 PCB** | 镜脚 PCB 上、SoC 电源级热源与皮肤之间的板面温度 | ✅ 能: 这正是 ISO 13732-1 43°C 红线对应的部位 | **★定案选这个** |
| **C. 电池** | 电芯温度 | ❌ 已有 NTC → BQ25896 TS 脚 → **硬件直接停充** (不依赖 SoC), TMP117 重复且更慢; 且电池温度不是皮肤红线 | **不选** |

### 4.2 ★定案 (SW 侧需求, 落板由项目总工/hw-lead/mech-lead 执行)

> **测点 = 镜脚主 PCB 的"贴皮肤面"一侧, 位于 SoC/电源级热源与皮肤接触面之间, 投影距 SoC ≤ 10mm, 焊在朝皮肤那一面 (或双面装配时选朝皮肤面)。**

**依据 (4 条)**:
1. **它对应唯一有法律/安全意义的那个点**: ISO 13732-1 的 43°C 红线是**贴皮肤表面**的温度; 光机在镜框正中 (鼻梁上方), SoC/电池在镜脚 —— 镜脚是唯一能同时代表"贴皮肤表面 + 主要发热源"的位置。
2. **方向是保守的**: 皮肤是热沉 ⇒ 稳态下 **T_PCB ≥ T_skin** ⇒ 用 PCB 温度当皮肤代理**只会高估、不会漏判超温**。代价是可能提前降载 (少一点续航), 换来的是**绝不漏判**。
3. **误差由热耦合路径主导, 不是由传感器主导**: TMP117 5µA × 3.3V = **16.5µW** 自热, 可忽略; TI 官方明确 "Mount the TMP117 on the PCB pad to provide the minimum thermal resistance to the measured object surface" ⇒ **贴装方式本身就是需求** (焊在朝皮肤面、靠近测点、周围开散热孔/减铜以降低与热源的耦合, 才能既反映皮肤面又不被 SoC 直烤)。
4. **它是唯一能同时喂"降载"和"合规记录"两个用途的量**: 降载策略要快 (1 帧内切换), 合规记录要准 (±0.1°C)。

**落板要求 (交给 hw-lead / mech-lead)**:
- 位置写在原理图 P2 的 `U_TEMP` note 上 (现在只写了器件, 没写测点) ⇒ **必须补一句物理位置说明**, 否则 PCB 阶段没人知道往哪放。
- 建议在 P7 加一个 `TP_TEMP` 测点 (焊在 TMP117 焊盘旁) 方便 EVT 用热电偶对照标定 (SW 要用它标定 `T_skin = T_TMP117 − K`)。
- **不得**贴到电池座 / 金属骨架 (结构总工已提"骨架/石墨不得延伸进电池段", 热路要分开)。

### 4.3 软件侧配套策略 (本次一并定档, 替换旧档)

**旧档 (SW 侧不再作触发阈值)**: 分片里已登记的 `thermal_control_tiers = 4档 <70/70-85/85-95/>95C` 是 **mech-lead 的 SoC 结温 (Tj) 口径** 表 (其 note 原文: "SoC 结温(Tj)档位, **不是皮肤温度**; 皮肤侧无传感器")。★**TMP117 装到贴皮肤面之后, "皮肤侧无传感器" 这个前提不再成立** ⇒ 两个表不再是同一物理量, 必须分开:
- `thermal_control_tiers` = Tj 口径表 (归 mech-lead, 本单**不改它的值** —— 两个 agent 抢同一个 key 会打架; 合并器已报冲突, 由项目总工统一注记)
- `thermal_tiers_skin` = **SW 新增**, 皮肤口径, 以下为定案

**新档 (TMP117 读数 = 镜脚 PCB 温度, 作为皮肤代理, 偏保守)**:

| 档 | TMP117 读数 | 动作 | 依据 |
|---|---|---|---|
| T0 | < 38°C | 全速 (60fps / NPU 高频档) | MECH 模型 0.05W → 37.5°C |
| T1 | 38 ~ 41°C | NPU 降一档 + OD 降到 30fps (显示同步降档) | 0.10W → 40.0°C, 距红线 3°C |
| T2 | 41 ~ 43°C | OD 只做单帧不连续推理 + 显示亮度降到最低 + 禁充电时运行 | 0.16W → 43.0°C = 红线 |
| T3 | > 43°C | **停 OD + 息屏 + 告警** (不等同于断电, 见 §6-9) | ISO 13732-1 红线 |

- **迟滞**: 每档回退阈值 = 进入阈值 − 2°C (防抖)。
- **滤波**: 3 点中位数 + 1Hz 采样 (与 TMP117 1Hz 转换同步) ⇒ 不会因单次噪声误切档。
- **执行时限**: **切档动作必须在 1 帧周期 (16.67ms) 内完成** (否则 frame age 跳一档 → 端到端 +16.67ms)。⚠️ 注意区分: **检测** 延迟 ~1~3s (TMP117 1Hz + PCB 热惯性), **执行** 延迟必须 ≤16.67ms —— 皮肤热惯性是几十秒量级, 所以 1~3s 的检测延迟对人体暴露无意义。
- **失效安全 (fail-safe)**: TMP117 读失败/总线卡死超过 3 个采样周期 ⇒ **按 T2 档处理** (保守降载) 并打 `temp_sensor_fault`。理由见 §6-12: TMP117 与 camera 同在 I2C_A (跨铰链), camera 拉死 SDA 会一起致盲温度保护。
- **首读丢弃**: 上电后第一次读数 = −256°C [官方] ⇒ 丢弃, 且首次有效读数最坏 ~1s 后才到 ⇒ 启动流程在这 1s 内**不得**判定过温, 也不得用 −256°C 判低温。

### 4.4 这颗 TMP117 覆盖不到的两件事 (必须记在账上)

| 缺口 | 后果 | 建议 | 依赖 |
|---|---|---|---|

| **光机 (镜框正中, 鼻梁上方) 没有温度传感器** | 镜框侧的 43°C 同样适用 (ISS-064 结论: "挪到镜框是换接触点不是消热"), 但**没有任何遥测** | 优先问 JBD 光机是否有内置过温保护/温度遥测; 若要测, 再加一颗 TMP117 (地址 0x49, 走 I2C_A 已有跨铰链能力) —— 但会增加 I2C_A 负载 (见 §6-9), 需权衡 | **JBD + 项目总工** |

## 5. 跨铰链 USB 2.0 差分做烧录口 —— S2 救砖链路可行性 (任务项 4)

### 5.1 链路现状


### 5.4 跨铰链差分的 SI 风险评估 (为什么 FS 比 HS 靠谱)

- 22Ω 源端串阻放在主板侧 (正确: 串阻要在源端) ✅; 差分阻抗 90Ω±10% (USB 2.0 专用模板, 不与 MIPI 的 100Ω 混) ✅; **不装共模扼流圈** (ERC B16 已裁决, 正确) ✅。
- FS (12Mbit/s) 上升时间 ~10ns 量级 ⇒ 跨铰链 30mm FPC 的插损与反射完全不是瓶颈; **HS (480Mbit/s, 上升时间 ~2ns) 才需要认真控阻抗与回流**。
- ⇒ **如果 SoC 的设备控制器只支持 FS, 跨铰链 USB 的 SI 风险其实很低**; 如果支持 HS 且我们想用它, 那 H1 的单地脚就必须先修 (共阻抗是共模→差分转换的主要来源)。
- **EVT 必须测**: 用示波器在 `TP_USB_D_P` / `TP_USB_D_N` 测眼图/摆幅 + 在铰链开合状态下测有无掉线 (ISS-085 已要求"跌落/扭转时 USB 通信不中断", 但那是结构项; **电性能项归 SW**: 枚举成功率 + 掉线率 + 刷写中断率)。

### 5.5 对 S2 救砖 SOP 的三条改动 (ISS-080 §4.5)

1. **BOOT 必须是"静态跳线", 不能是"时序化操作"**。
   理由 (来自 §2.3 F2): RESET 释放时刻 = 轨爬升(未知) + 20ms + 1.32ms, **不可预测**; 网表注记写的 "τ=100ms" 还是错的 (实为 1.1ms)。⇒ SOP-1 的 t1/t2/t3/t4 时序表 **不成立**。
   ⇒ 改成: **BOOT 跳线静态置位 → 上电 → 等枚举**; "按 RESET" 只保留给"已在运行态的设备要重启进下载模式"这一种情况。
   ★**硬件前置**: 现在 `BOOT_N` 只有 10k 上拉 + 按键到地 + `TP_BOOT` 测试点, **没有 0Ω 跳线位**。⇒ **必须加一个"BOOT 强制有效位" (0Ω/焊盘跳线, 接 SoC 自己的 IO 域电平)**。⚠️ **不得**用"把 TP_BOOT 接到 3.3V" 的土办法 —— BOOT_N 的上拉挂在 `VDD_1V8_IO`, 外接 3.3V 会把 5V 灌进这条 1.8V LDO (见 §2.3 F5)。
2. **枚举超时**: `t_enum_timeout` 现写 15s [推算] ⇒ 保留 15s 作为上限, 但**必须新增一条测量项**: "上电 → 首次枚举成功"的实测分布 (min/avg/max, 采样 ≥30 次), 因为它决定产线节拍。
3. **"救砖"的成功判据要加一条硬件项**: 跨铰链 USB 在**铰链被反复开合**的状态下能否完成整包刷写 (与 ISS-085 的可靠性用例对齐)。

### 5.6 ★量产产线要不要改成有线刷写器 —— 建议: **要**

**建议 (交项目总工裁决)**: **量产主刷写口 = 镜脚上的有线刷写器 (pogo 盘), 跨铰链 USB 降级为"工程救援 + 售后自助"路径。**

**依据**:
1. **跨铰链不是量产工位的可控环境**: 产线要求节拍 (每件几十秒级) + 100% 成功率, 而跨铰链意味着每件都要"把眼镜摆成一个特定折叠角度并压住" ⇒ 工装复杂度 + 接触不良率。
2. **返修/售后已经在镜脚上有更好的入口**: `J_DEBUG` (1×4 JTAG) + `J_UART` (1×2) 都在 MAIN_PCB, 且 ISS-092 已提"镜脚末端要开可开启检修口"。⇒ 产线夹具走检修口的 pogo 针, **比跨铰链更可控**。
3. **但有一个前提**: 原厂的下载工具是 USB-only 还是也支持 JTAG/UART, **0数据** (P2 `fw_vendor_toolchain`)。⇒ **若原厂工具只支持 USB, 就必须在镜脚上焊一套 USB pogo 焊盘 (VBUS/GND/D+/D− 4 点)**。
   ★**强烈建议现在就把这 4 个焊盘画上 (可 DNP)**: 第一块板不画, 后面要加就得改板 = 重投 + 重新排产。
4. **Type-C 口仍要留在镜框** (充电 + 售后自助刷机), 这是 ISS-085 已裁的。
