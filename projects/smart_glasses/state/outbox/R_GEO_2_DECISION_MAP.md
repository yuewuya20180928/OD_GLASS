## B1 结论摘要

1. **R-GEO-2 四问的收件方不是一个, 是两个, 必须拆开发。** 问②③④ 是**芯片原厂 (酷芯微/ARS45)** 的事; 问① 是**共同前提** —— 它同时决定"我们该不该裁剪"和"镜头厂该按什么口径交货", 必须**同时**进原厂信与镜头厂 RFQ。四问合并成一份信 = 有一半的人收不到该收的那部分。
2. **四问卡的是三个决策, 但真正的一票否决权只在问③。** 120° 对角是否成立 (问①+②)、宽高比子路线 (问④)、全幅吞吐是否留得住 (问③) —— 三者里, 问③ 的答案是唯一可能把**整条链路推翻**的: 全幅 2688×1520@60 = **245.1 MP/s**, 而公开的两个口径 (250 / 497.7 MP/s) **差 2 倍**, 按 250 算余量只剩 **1.9%**, 按 497.7 算余量 50.7% —— **两个结论完全相反**。
3. **★问① 有一条被现有材料漏掉的连锁: 它不只是"别裁剪", 它还决定 ISP 吞吐余量的分母。** ROI (1920×1080) 只要 **124.4 MP/s**, 全幅要 **245.1 MP/s** —— 问① 的答案直接决定问③ 的余量是 49.8% 还是 98.1%。**所以问① 与问③ 必须成对回答, 单独问③ 没有意义。**
4. **★问② 不答, 我方的板级预留就是错的。** 我们网表 P5 页把 CSI D2/D3 标成 DNP (只按 1080p60 2-lane 设计), 但**全幅 RAW10@60 = 2.451 Gbps → 4-lane**。厂商说"2-lane 就够" ⇒ 那 2-lane 跑的是 ROI, 视场从 120° 掉到 85.61°, 与老板已定的对角 120° 基线直接冲突。**这一条必须在投板前定, 投板后改 = 2-4 周 + 板费。**
5. **★问④ 的真实代价不是"能不能填黑边", 而是"要不要非等比拉伸"。** 若 ISP scaler 既不能 letterbox、也不能输出 640×362 有效帧, 就只能非等比拉伸 → 角分辨率各向异性 **1.326**、目标长宽比**全局失真 32.6%** (比鱼眼自身角落切向 20.9% 还大) → **违反 REQ-GEO-07**。这就是"宽高比子路线"这个决策的真实代价。

### 决策 D1: 120° 对角是否成立

| 项 | 内容 |
|---|---|
| **卡住它的问** | **问①** (边缘畸变区是检测价值最高处 ⇒ 裁剪=目标在被检测到前就出画) + **问②** (全幅 2.451 Gbps → 4-lane) |
| **决策的实质** | 采集端到底是 120.00° (全幅, 立体角 1.768 sr) 还是 85.61° (ROI, 立体角 0.925 sr, 只剩 52.30%) |
| **为什么它一票否决** | 老板 10-25 19:33 拍板"不裁剪" + 19:42 定"对角 120° / 俯角 ≤25°"。ROI ⇒ 垂直半视场 20.98° < 俯角 25° ⇒ **正前方直接掉出画面 (余量 −4.02°)** ⇒ 用户眼前少一半世界, 且走路看前方会没有画面 |
| **答"能"(全幅 + 4-lane) → 走哪条** | ① 采集链锁定 2688×1520@60 RAW10 + 4-lane; ② 网表 P5 的 **D2/D3 从 DNP 改必装** (含 4 颗 AC 耦合电容 + 4 个 100Ω 对地端接 + 8 根差分走线); ③ 镜头按**全画幅口径 120°** 定档; ④ 触发 ISP 动态功耗按 2 倍帧率重估 (影响散热结论) |
| **答"不能"(只能 ROI) → 走哪条** | ① **老板已定的 120° 基线作废**, 必须重开镜头选型 (`HW/LENS_SELECTION.md` §6.3 回退路径 A/B/C: AR0234CS 16:10 原生全幅 / 直行 110° / 直行 100°); ② 或保留 OV04C10 但**放弃对角 120° 改用 ~100-105°**, 代价是"智能眼镜视野"卖点缩水; ③ 俯角必须压到 ≤20° 才能保住正前方 ⇒ 与结构"装镜框上沿、俯角 20-32° 不可回避"冲突 ⇒ **需老板裁决** |
| **如果问① 答"可以裁"** | 那 D1 不是技术问题而是**决策问题** —— 但老板已拍板"不裁剪", 所以我方默认答案是"不裁", 材料里写的是"我们把整幅 scale 写成不可违反的硬约束" |
| **材料对应** | 原厂信 **Q1** (全幅 vs ROI + 模式表) 与 **Q5** (默认模式/寄存器读回, 保证每次开机都是 120°); 镜头厂 RFQ **RFQ-13** (三个 ROI 档位的等效视场表 = 退路量化) |

### 决策 D2: 走哪条宽高比子路线

| 项 | 内容 |
|---|---|
| **卡住它的问** | **问④** (scaler 能否"缩放后指定区域填黑边" = letterbox) |
| **决策的实质** | sensor 16:9.03 (或 AR0234CS 16:10) → 输出 4:3, 必然要在 **拉伸 / 裁剪 / 加黑边** 三者里选一。裁剪已被 C3 禁 ⇒ 只剩**子路线 1 (各向异性拉伸)** 与 **子路线 2 (等比 + letterbox)** |
| **项目总工 10-26 已裁决** | **子路线 2 (等比 scale + letterbox)**: 各向异性 1.000, 反投影公式零改动, f_out = f_px×k (OV04C10 351.05 / AR0234CS 360.35) 单 f_px 在输出系仍成立 |
| **答"能"(支持 padding 或能出 640×362 有效帧) → 走哪条** | 维持子路线 2: 内容区 640×362 + 上下各 59 px 黑边 (24.58% 输出像素是黑边; AR0234CS 640×400 + 40 px = 16.67%); 代价 = 24.58% 的 NPU 算力落在空像素 (纯 NPU 16 ms 估 ≈ 3.9 ms 等效), 但**黑边上不可能有目标 ⇒ 对 mAP 无损** |
| **答"不能" → 走哪条** | 退化到**子路线 1 (各向异性拉伸)**: 各向异性 **1.326**, 目标长宽比**全局失真 32.6%** (比鱼眼角落切向 20.9% 还大) ⇒ **直接违反 REQ-GEO-07 "优先等比"**; 且输出系不再是"等距圆" ⇒ 反投影必须 fx≠fy (f_out_x 351.05 vs f_out_y 465.89), `FISHEYE_GEOMETRY.md` §3.2 的各向同性公式在输出系失效, 框角张角随框在画面里的**朝向**而变 (不再是标量) ⇒ **必须回项目总工重裁, 不能由 hw-lead 自决** |
| **★还有第三条路 (原材料没写, 本轮补上)** | **letterbox 可以在 ISP 之后的软件侧生成** —— 我们已锁定"黑边只生成一次、全链路复用同一组 (ox, oy)" (CR-3 裁决), 所以即使芯片 ISP 不支持 padding, **只要它能输出等比缩放后的有效帧 (640×362 或 640×400), 我们在 OD 侧补黑边即可**, 几何与子路线 2 完全等价。⇒ **所以问④ 的正确问法不是"能不能填黑边", 而是"能不能等比缩放 + 能不能输出非 4:3 的有效帧"** —— 已按此改写材料 (原厂信 Q4 给 A/B 两个可接受答案, 只把"非等比拉伸"列为不可接受) |
| **材料对应** | 原厂信 **Q4** (A/B 两案 + 明确排除第三案); 镜头厂 RFQ **RFQ-15** (畸变曲线要角度口径 + 机器可读, 因为不做 LDC 时曲线就是我们的标定源) |
