## P0 —— 直接卡住原理图/PCB，缺这条我们无法出图

**问题 1（显示输出接口，最优先）**
我们在公开资料中看到"DP1.4RX""1080p@60fps 异屏显示"等表述，但**无法确认 DP1.4 是仅 RX 还是同时有 TX**，也未在产品页看到 MIPI-DSI TX 的芯片级声明。因此我们**不敢默认 ARS45 能直接驱动 MIPI-DSI 光机**（我们用的光机是 MIPI-DSI 输入），如果判断错，会凭空多出一颗桥接芯片和 4–8 周采购周期。

请书面回答（最好直接给 datasheet / HRM 的 Display TX 章节）：

1. ARS45 **是否集成 MIPI-DSI TX**？如有，**几 lane**、每 lane 最高速率、**最高分辨率 @ 帧率**分别是多少？
2. **DP1.4 是只有 RX，还是同时有 TX**？若 TX 与 RX 并存，TX 最高分辨率@帧率是多少？
3. DSI TX 与 DP1.4 RX **能否同时工作**？若能，两者同时工作时的带宽/时钟限制是什么？
4. DSI TX 的 **I2C 通道**是独立的还是与 DSI 共用？DSI DDC 地址可否配置（我们还要接一路 sensor 的 I2C，需要避免地址冲突）？
5. 若**确实没有** DSI TX 也没有 DP TX —— 请直接说明，**我们需改用外接 DP→MIPI-DSI 桥接方案**（这会改变整机 BOM、功耗与结构，请务必明确）。

**问题 2（FCCSP 球间距 —— 我们已升级为 SoC 选型一票否决项）**
8×10mm FCCSP 的 **ball pitch** 是多少？请提供**完整球位图 / 引脚图**。

我们内部按以下门槛评估（这是我们自己的工程判断，不是贵司结论）：

| ball pitch | 对我们的影响 |
|---|---|
| ≥ 0.4mm | 可行，4-6 层板 + 常规逃线 |
| 0.35mm | 极限，逃线/叠层需 HDI 工艺 |
| ≤ 0.3mm | 走线密度不足，需 HDI —— **与我们已锁死的 4-6 层普通工艺冲突** |

也就是说：**若 pitch ≤ 0.3mm，我们会重新评估是否继续用 ARS45**。请给出准确数值（不同 die 型号若不同请分别注明）。

**问题 3（启动存储 / 固件分区）**
我们的整机需要存放：rootfs、YOLOv5 INT8 权重、ISP 固件、NPU 固件。请问：

**问题 4b（EMC 预评估新增, 来自 `HW/EMC_PRECHECK.md` D1/D2/D3）**
画板前我们必须把谐波落频点定死，否则 PCB 的滤波/屏蔽布局没有裁决依据：

1. ARS45 **内部主时钟 / DDR 时钟频率**是多少？**集成 DC-DC 的开关频率**是多少（若有）？——
   这两个数决定所有谐波落在哪，直接决定机壳地/滤波/屏蔽怎么排。
2. **MIPI-CSI 输入侧**的规格（我们此前只问了显示侧，输入侧漏了）：
   - **lane 数**、**每 lane 最高速率**、支持的最高输入分辨率@帧率
   - **输入电压域**（VDD_IO 是多少？1.8V / 1.2V / 可配？）
   - **是否需要外部 AC 耦合电容**？内置了吗？
   - 是否有**参考时钟 MCLK 引出**？
3. **是否提供帧同步（FSIN/VSYNC）信号**？能否从芯片引出到外部引脚？
   —— 我们需要在板外做示波器打点测端到端延迟，没有帧同步就没法同步测。
4. **充电状态能否被读取**？是充电 IC 的状态脚回读到 SoC，还是只有 VBUS 检测？
   —— 我们要求"充电时必须禁 OD"（充电 IC 耗散 0.8W，贴皮肤会到 75°C），
   若硬件读不到充电状态，这个安全门禁就实现不了。

2. ★**官网/演讲提到 ARS45「在 1080p 30fps EIS 录像场景下整芯片功耗（含 DDR）低于 300mW」——
   这个数的测试条件能否书面确认？**

**问题 4d（20:20 补充：出图对齐全量对齐后发现的 2 个漏问）**

我们已把贵司需要回答的问题与自己的原理图待画清单**逐条对了一遍**，发现下面 2 项我们此前没问到，
但它们**直接决定某些电路画不画得出来**（不是"最好有"，是"没有就画不出"）：

1. **ARS45 是否集成 USB PHY / USB 2.0 控制器？**

## P1 —— 决定两个硬指标能不能达标

**问题 5（NPU 耗时口径 + 输出格式）**
我们此前在公开资料中**未找到 ARS45 跑 YOLO 的任何实测数据**（公开案例多为语音/翻译/降噪）。贵司是否跑过 YOLOv5 系列？

1. 若跑过：**yolov5s / yolov5n INT8 的单帧实测延迟**是多少？**输入尺寸**是多少？**是否含前后处理**（pre-process / decode / NMS）？请分别给出**纯 NPU 耗时**与**SDK 总耗时**两个数。
2. **NPU 输出是否强制 FP32**？我们在同系列 A733 上实测 `tensor_to_fp` 反量化占 SDK 总耗时 25%（9.29ms / 36.51ms）。若 ARS45 同样强制 FP32 并原样透出，反量化会多耗约 7.3ms —— 对我们的**框龄**计算是跨档影响（16.67ms 一档，差 2ms 可能等于差 17ms）。请问能否**直接拿量化整数输出**、由我们自己反量化？
3. 连续推理是否需要**散热降频**？首帧预热/权重加载耗时多少？单次推理的**最坏延迟**（P99）大致范围？
4. 是否支持**分阶段 profiling**（只跑 NPU、只跑 decode 等），便于我们定位耗时？
5. 能否提供**分阶段耗时**的实测值（pre-process / NPU / decode / NMS / draw）？
