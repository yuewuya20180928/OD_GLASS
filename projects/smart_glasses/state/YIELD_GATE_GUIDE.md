# ★【预测性让路闸 (窄版) · 使用与验证手册】★ — 2026-11-11

> 适用: `state/gen_pcb_routing.py` 的 `_yield_straight_steps()` + env `PCB_YIELD_STRAIGHT` / `PCB_YIELD_VICTIMS`

## ★1. 它治什么病 ★
**"先布的那个拐弯, 把后布的那个出脚口掐死"** —— 后布的网等它上场时, 走廊已被前一个网的拐弯链占死。

★**实测案例 (`v76mv0` 终板)**: ★
- 受害者 `BOOT_N` (焊盘 `J_SOM_P1.28` @ 63.60, 11.04) 的 A* 起步格 = **(63.70, 12.20)** (★用 `_ci/_cj` 算★)
- 抢路者 `ID_DETECT_0` (焊盘 `J_SOM_P1.32` @ 62.80, 11.04) 的**两段**铜进它的 halo:
  · (63.450,12.700)→(63.700,12.700) 中心距 **0.5000**
  · (63.700,12.700)→(63.950,12.950) 中心距 **0.5000**
- 模型半径 halo[1] = CLEAR 0.20 + 对方铜半宽 0.125 + W_CLS[1]/2 0.125 + HALO_MARGIN 0.0625 = **0.5125**
- ⇒ ★**0.5000 < 0.5125 ⇒ 起步格被判死 (★差 0.0125mm★) ⇒ 但真净距 0.2500 完全合法** ⇒ ⇒ **不是物理堵死, 是"余量+调度"问题** ★

## ★2. 它怎么工作 ★
当抢路者出脚后, **先直行 k 步再拐弯**, 使它的阶梯下降路径离受害者的起步格 ≥ halo 半径。

★**k 的计算 (★`state/gen_pcb_routing.py` 的 `_yield_straight_steps()`★)**: ★
1. 受害者起步格 = `_cx(_ci(受害者焊盘x))` / `_cy(_cj(受害者焊盘y + dj·ESC_LEN))`
2. 抢路者直行 k 步后, 新铜 = 【出脚直道】【续直行】【45° 阶梯下降的横道链】(★横道一直延伸到受害者的 x 列★)
3. 逐段算**点到线距**到受害者起步格 ⇒ 全部 ≥ `_need` 才算过

★★**`_need` 必须用 `W_CLS[1]/2` (0.125), 不能用 `W_MIN/2` (0.075)** ★★
⇒ ★**因为真正封死受害者起步格的是【受害者将来落的 0.25 铜】⇒ 它的 halo 半径是 0.5125** ★★

## ★8. ★★【三个被它咬过的坑】★★
