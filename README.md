## 0. 这不是一个人的项目 —— 是 4 个 Agent 的协同产物

```
                      ┌─────────────────────────┐
                      │  main = 项目总工 (moli) │
                      │  方案/选型/拆解/计划/   │
                      │  收口/质量与进度把控     │
                      └───────────┬─────────────┘
        ┌─────────────────────────┼─────────────────────────┐
        │                         │                         │
┌───────▼────────┐      ┌─────────▼────────┐      ┌─────────▼────────┐
│  hw-lead       │      │  sw-lead         │      │  mech-lead      │
│  硬件总工      │      │  软件总工        │      │  结构总工(散热) │
│  原理图/PCB    │      │  需求拆解/方案   │      │  空间预算/散热  │
│  拆解/审核     │      │  开发与验证      │      │  打印件实现     │
└────────────────┘      └──────────────────┘      └──────────────────┘
        ↑                        ↑                        ↑
        └──────── 走共享状态源 STATE.yaml + HANDOFF 交接单 ────┘
              ★ 三个子总工之间【不做直接沟通】(星型拓扑, 硬规则)
```

**为什么这么设计**: 项目总工的核心职责是"需求对接 + 跨模块串联", 而它已经持有全部项目上下文; 另建一个总工等于把上下文切一半出去还多一跳中转。三个子总工之间**横向信息流走文件, 不走对话** —— 堵死的是"对话"不是"信息", 否则结构总工看不到硬件的 PCB 尺寸, 各写各的。

→ 完整说明: **[`docs/AGENT_SYSTEM.md`](docs/AGENT_SYSTEM.md)**

## 4. 三条最该记住的教训

**① 数字不能自己估** — 我给决策表写"0.23W → 皮肤 38-40°C ✅", 结构总工重算是 **46.5°C ❌ 仍超 43°C 红线**, 还漏了整个充电场景 (0.8W → 75.1°C)。
→ *给用户的数必须引子总工的核算原文。*

**② 验收分离: 自己修的必须别人验** — 问题的 `verify_by ≠ owner` 是硬门禁, 自己修自己验等于没验。三个子总工因此抓到总工的三处错 (温度数 / Q17 切换判据 / 验证人填自己)。

**③ 阶段性结论要标证据等级** — `[实测] / [官方] / [推算] / [0数据]`。本项目**至今零实测**, 所有数字都是推算; 推算值不能冒充实测, 阶段门只认 `kind == "实测"`。
