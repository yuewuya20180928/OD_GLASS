## 关键事实清单(必须 resume)

### 1. IMX415 I²C 地址
- `cubie-a7a-radxa-camera-4k-415.dtso` 写 `sensor0_twi_addr = <0x34>` (Linux 7-bit)
- sensor ID register 0x3008 读出 8-bit raw = `0x1a` = `0x34 >> 1`,**两者一致不是矛盾**
- twi3 bus (CCI 3), GPIO PE3=SCL, PE4=SDA, PE9=RESET, PE8=PWDN, **BLDO1 (1.8V) 给 sensor 供电**

### 2. 真正 overlay 源仓库(之前漏看的)
- `radxa-pkg/radxa-overlays` (87⭐, last push 2026-07-24)
- `arch/arm64/boot/dts/allwinner/overlays/cubie-a7a-radxa-camera-4k-415.dtso` ← **A7S 复用此 dtso**(metadata.compatible 字符串包含 radxa,cubie-a7s)
- `cubie-a7z-radxa-camera-4k-415-cam2.dtso` 是 A7Z 第二个 MIPI 端口专用
- Makefile 注释:`dtso can only build on kernel >= 6.2`(2024 git commit 363547d2191c)
- trixie 6.6 满足,R6 5.15 不满足预编译

### 3. A7S 是 2026-01-16 才加进 allwinner-device
- v1.4.6 (2025-06-16) **没有 A7S**
- 2026-01-16 commit `configs: add radxa-cubie-a7s support`(copy from cubie-aiot-v1.4.6)
- 2026-11-19 v1.4.8 release, last push 2026-07-23
- `linux-6.6: merge bsp_defconfig from linux-5.15 based on intuition` ← **凭直觉 merge**,可能漏配

### 4. radxa-build Issue #3 — Radxa 用户公开警告(2025-12-11, 4👍, open)
> "**stay away from the A733 if you want any Video support**"
- ISP: "artifacts and unusable color tuning (only 4k 30fps 2 frame linear hdr)"
- H.264 Encoder: "**never outputs an SPS NAL unit**"
- Last update mid 2024 (官方 2 年没修)

### 5. libisp.so (Dec 2024) HDR stitch bug(论坛 Imran_ahmed 2026-07-23 完整报告)
- kernel sensor driver 是 **single-exposure mode** (reg 0x302C=0x00,DOL disable)
- 但 `/usr/lib/aarch64-linux-gnu/libisp.so` (commit 665dc2e9613716c25abb6b64af145a73b989271e) **hard-coded 走 2-frame DOL-HDR stitch 路径**
- 结果:`[ISP_WARN]can not use sync mode.(buffer0=0xffff8c0418c0, buffer1=(nil))` → 输出分裂/异色/AWB 失败
- IMX415 配置文件只 baked 在 libisp.so 内,不再 kernel `drivers/vfe/isp_cfg/SENSOR_H/`
- Radxa 团队 Alexander (avaf, ninja) 回:"libisp-dev is kind of unstable and old, need to be fixed. Hopefully."

### 6. kernel panic 会 corrupt SD 卡(关键!)
- 论坛 avaf 2026-06-20 在 A7S + IMX214 + R6 bullseye 上实验:
  - 启 imx214 overlay → "**The kernel crashed and the board turned off**"
  - "**the sd card is now corrupt. It looks like a kernel crash can easily corrupt the sd card**"
- **这跟老板 "烧系统卡一周" 是同一个根因!**
- 跟 7/23 我们撞 `vin_g_volatile_ctrl+0xdc` kernel panic 是同款 VIN driver bug

### 7. radxa-pkg/rsetup 是 JavaScript 不是 Python
- `src/usr/` 目录,配置文件 `config/before.txt` + `config.txt`
- `debian/rsetup-config-*.install` 是 deb post-install hooks
- 流程:`rsetup overlay 选择 → extlinux.conf 加 fdtoverlays → u-boot-update → reboot`
- `Rebuild overlays` 选项存在但文档没说用法

### 8. 镜像说明(R6 vs T4)
- **R6 = bullseye (Debian 11), 5.15.147-21-a733** ← 官方 r2/r6 稳定推荐
- **T3/T4 = trixie (Debian 13), 6.6.98-3-aw2511** ← Pre-release "will not be supported"
- 我们当前烧的还是 T4 trixie beta(7/9 那次)
- 我们硬盘上有 R6 但 R6 bullseye 烧卡从没成功过(7/11 R2 烧失败的 sparse hole 教训)

### 9. rsetup 5.15 跟 6.6 镜像里默认 overlay 不一样
