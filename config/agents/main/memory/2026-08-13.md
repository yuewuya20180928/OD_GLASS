### 根因
1. **parser 错配**: 期望 "label: conf%, [x1,y1,x2,y2], class_name", 实际只有 "detection num: %d"
   → sscanf 永远 != 7 → det_count = 0 → log dets=0
2. **count%3 mod 优化**: `if ((count % 3) == 0)` 在 G++ -O2 下被常量化 → 每帧都跑 OD
   → od=21ms 每帧 (期望 1/3 帧 = 7ms avg)
3. (隐藏问题) **libod_helper.so 内置 post-process** `detection num: 0` 因为 NPU max raw conf 3.1-3.4 低于内部阈值
   → 摄像头前没东西 OR 阈值太高 (单独议题, 不在本次 fix 范围)

### 最小修复 (实际改动)

**1. parser 改 `detection num: %d` 格式**:
```cpp
// 旧 (永远 != 7):
sscanf(line, "%d: %f%%, [%d, %d, %d, %d], %63s", ...)
// 新:
if (sscanf(line, "detection num: %d", &n) == 1 && n > 0) {
    count = n;  // 当前 libod_helper 不输出 bbox/class, 只拿 count
}
```

**2. count%3 改 volatile int counter**:
```cpp
// 旧 (G++ -O2 把 mod 常量化):
if ((count % 3) == 0) { ... }
// 尝试 1: std::atomic<int> counter + fetch_add → 代码生成对 (__aarch64_ldadd4) 但运行时仍 od=21ms 每帧
// 尝试 2: volatile int + 普通 +1 (最终方案, 实测 memcpy 5/sec = 1/3)
static volatile int od_counter = 0;
int od_c = od_counter++;
if ((od_c % 3) == 0) { ... }
```
