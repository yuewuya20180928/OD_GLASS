### ★★★ 本轮修了两个"机制自己骗自己"的真缺陷

**缺陷 1 — GitHub 发布闸门把凭据明文写进了要公开的脚本里**
- `state/publish_github.sh` 里 `EXTRA_LITERALS = ["<WECHAT_OPENID_REDACTED>" + "HDbRTzQ1JS4"]` —— **拆拼**形式骗过"自己扫自己", 但两段明文都在文件里, 而**这脚本本身会被 rsync 进公开仓库** ⇒ grep 一下就能拼回完整凭据。
- ⇒ 修法: **脚本里一个敏感串明文都不写**, 全部从**本地不入库的真值源**现读 (openclaw.json / cron/jobs.json / TOOLS.md / MEMORY.md)。设备口令 `radxa` 原来用 `\bradxa\b` 匹配 ⇒ **误伤 6 个正常文件** (路径 `~/Downloads/radxa/`) ⇒ 改**上下文匹配** + **规则由真值动态生成**。
- 自测: 真实发布树 **0 命中** + 故意造 4 类泄漏 **全部被抓到** (含实盘格式 `**SSH 密码**: \`radxa\``)。

**缺陷 2 — token 守护的"最可靠兜底"在骗自己**
- `state/token_watch.py` 用**文件 mtime** 算"距上次推送多久"; `.last_github_push` 是**内容为时间戳**的记录文件 ⇒ **任何重写它都会刷新 mtime** ⇒ 报"刚推过", 实际可能 2 天没推。
- 血证: 我把内容改回真实推送时间 (10-30 00:21) 后, token_watch 报 **"距上次 GitHub 推送 4.5 分钟"** —— 明明 2 天前, 它说 4.5 分钟。
- ⇒ 修法: **读内容里的 ISO 时间戳**算间隔, 解析失败才回退 mtime。修完如实报 **4115 分钟** ⇒ rc=3 正确触发。
- ★**为什么最要紧**: 老板 10-29 说"超 45 分钟没推送"是**最可靠兜底** (限额数值未公开) ⇒ **它骗自己 = 兜底失效 = 断电时什么都留不下来**。
