## 13:30 — SSD 评估口径修复（2 个 bug）

### Bug 1：MAX_IMGS=200 写死 ✅ 修了
- `evaluate_odapi.py` 原代码写死 `MAX_IMGS = 200`，val.record 共 2476 张，只跑 8%
- 修复：加 `--max-imgs` CLI 参数，默认 2476（全量）
- **效果：mAP 从 0.0288 涨到 0.0611（+2.1 倍）**

### Bug 2：GT letterbox padding 用 float 而 dataset_builder 用 int ✅ 修了
- `evaluate_odapi.py` 用 `new_w = orig_w * scale`（float）算 padding
- `dataset_builder.resize_with_padding` 用 `tf.cast(... * scale, tf.int32)` 算 padding
- 1220/2476 张（49%）有偏差，最大 0.5 像素
- 修复：用 `int(...)` 截断 + `// 2` padding，跟 image 实际像素对齐
- 边界 box IoU 受影响显著

### 已确认**不是** bug 的项（实测验证）
- `INFERENCE_SCORE_THRESH=0.5`：0.5 vs 0.01 mAP 完全一样（compute_map 对低分 FP 鲁棒）
- padding 类未过滤：compute_map 内部已 ignore，mAP 不变
- `compute_map` 算法：跟 sklearn 输出对齐，算法正确

### 仍存在的潜在坑（letterbox 输入对齐）
- 本项目 dataset_builder letterbox vs OD API 训练时的 letterbox 可能不完全一致
- 推测：SSD 320 在我们数据上 mAP=0.0611 vs paper 0.222（差 3.6 倍）就是这个原因
- D1 在同样数据上 mAP=0.0929 vs paper 0.384（差 4.1 倍），比例上跟 SSD 差不多
- **D1 vs SSD 的对比结论仍然成立**（同 bug 同偏移）

### evaluate_odapi.py 关键改动

```python
def parse_args():
    p = argparse.ArgumentParser()
    p.add_argument("--model-path", type=str, default=str(ODAPI_MODEL_DEFAULT), ...)
    p.add_argument("--input-size", type=int, default=None, ...)
    p.add_argument("--max-imgs", type=int, default=2476, ...)
    p.add_argument("--score-thresh", type=float, default=0.01, ...)
    p.add_argument("--no-pad-filter", dest="pad_filter", action="store_false", default=True, ...)
    return p.parse_args()

# GT letterbox 修复
scale = INPUT_SIZE / max(orig_h, orig_w)
new_w = int(orig_w * scale)  # int 截断
new_h = int(orig_h * scale)
pad_x = (INPUT_SIZE - new_w) // 2  # 整除
pad_y = (INPUT_SIZE - new_h) // 2

# score/padding 三层过滤
score_mask = scores[:num] >= args.score_thresh
if args.pad_filter:
    score_mask &= (classes[:num] >= 1) & (classes[:num] <= 80)
```
