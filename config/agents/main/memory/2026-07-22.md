## od_api v0.1 — subprocess + PTY

**文件**: `/work/od_api/od_api/{__init__,model,parse,classes}.py` + `tests/test_basic.py`

**思路**: subprocess 调 SDK yolov5 binary，正则解析 stdout detection 行。

**关键坑**（已加 MEMORY.md）:
- yolov5 binary 完全缓冲 stdout（C runtime 检测到非 TTY → block buffer）
- `subprocess.run(capture_output=True)` 是 pipe → yolov5 print + segfault → buffer 没 flush → detection 全部丢
- **`stdbuf -oL` 不奏效**（pipe 仍 block buf）
- **`grep` pipeline 偶尔能捕到但不可靠**
- **唯一可靠的修法**: `pty.openpty()` + `Popen(stdout=slave_fd, stderr=slave_fd)` → child 看到 TTY → line-buffered → 每 `\n` flush

**结果**:
```

ALL TESTS PASS
```

## od_api v0.2 — ctypes 直绑 shared lib

**文件**: `/work/od_api/od_api/model_ctypes.py` + `tests/test_direct.py`

**思路**: 不调 binary，直接 ctypes CDLL 绑 SDK 源码编出来的 shared lib，跳过 subprocess 开销。

**关键坑**（已加 MEMORY.md）:
- yolov5 binary 是 PIE (ET_DYN)，glibc 2.34+ 拒收: `cannot dynamically load position-independent executable`
- 修法：从 SDK 源码编 shared lib（不要 dlopen 那个 binary）

**Build command**（板端跑过）:
```bash
cd ~/ai-sdk/examples/yolov5
g++ -shared -fPIC -O2 -o ~/od_api/lib/libod_helper.so \
    ../libawnn_viplite/awnn_lib.c ../libawnn_viplite/awnn_quantize.c \
    ../libawutils/image_utils.c yolov5_pre_process.cpp yolov5_post_process.cpp \
    -I../libawnn_viplite -I../libawutils -I../.. -I../../log \
    -I../../viplite-tina/lib/aarch64-none-linux-gnu/v2.0/inc -I/usr/include/opencv4 \
    -lopencv_core -lopencv_imgcodecs -lopencv_imgproc -ljpeg -lNBGlinker -lVIPhal
```
产出 79KB shared lib。

**postprocess stderr 坑**: yolov5_post_process 把 detection lines 写 stderr，cv::imwrite 写 cwd 下的 result.png。
修法: `os.chdir('/tmp')` + `os.dup2(tmpfile, 2)` 重定向 stderr，调用完恢复 + 读 tempfile。

**awnn_init/create 优化**: 第一次 predict init+create，后续复用 ctx，支持 `with A733ODModelDirect() as m:` 语法。

**结果**:
| 指标 | v0.1 subprocess | v0.2 ctypes | 增益 |
|---|---|---|---|
| 总帧时间 | 358.4ms | **100.8ms** | **3.56x** |
| NPU 推理 | ~26ms | ~26ms | (硬件不变) |
| Python 开销 | ~330ms | ~75ms | 4.4x |
| 检测一致性 | dog 82%, truck 69%, bicycle 47% | 完全一致 | OK |

## 00:25 — od_api v0.3 完成 + 性能优化

### Bench 结果（steady state, n=30）
- **v0.1 subprocess: 358ms**
- **v0.2 ctypes (chdir/tmpfile): 100ms**
- **v0.3 ctypes (no-chdir/pipe): 89ms**  ← 当前

### v0.3 优化点
- **取消 `os.chdir('/tmp')`** — 让 cv::imwrite("result.png") 在 read-only /etc/npu/yolov5 上 fail-fast，省 ~30ms
- **改用 `os.pipe()`** 替代 tempfile — 性能基本相同但代码更清晰
- awnn_init/create 已在 v0.2 阶段 amortized

### Phase 分解（n=10, v0.2 baseline）
```
preprocess                  14.70  (imread + letterbox)
set_buffers                  0.40
run                         36.57  (NPU 25ms + tensor fp 8ms)
postprocess_setup            0.06
postprocess_call            52.71  (detect_yolov5: 3×generate_proposals + NMS + imwrite fail)
postprocess_teardown         0.05
parse                        0.07
free                         0.93
TOTAL                      105.50  (≈ v0.2 baseline)
```

### v0.3 取消 chdir 节省在哪里
v0.2 chdir 到 /tmp → cv::imwrite 写入 700KB PNG (~30ms PNG encode + write)
v0.3 不 chdir → imwrite fail-fast (permission denied, ~0ms)

### 进一步优化的瓶颈（v0.4 候选）
- postprocess_call 52ms 里：~10ms std::vector copy of 2.1M floats + 15ms generate_proposals + 5ms NMS + 2ms draw + 1ms imwrite fail
- 要砍到 50ms 需要：自己写 C 函数跳过 std::vector copy（直接读 float* outputs）+ 跳过 draw_objects
- **装 numpy 也行**（apt install python3-numpy 在板端可能 work, 但 apt-hell 风险高）

### 决策
**v0.3 收工**，89ms = ~11 FPS。够用，复杂优化（写 C NMS / 装 numpy）留给 v0.4 看是否真有需求。
