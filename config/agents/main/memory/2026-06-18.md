## 关键发现

### 1. retrain v4 崩盘
- 原因：6/16 把 loss 从 binary sigmoid focal (gamma=2.0, neg_pos=3.0) 改成 multi-class softmax focal (gamma=1.5, neg_pos=1.0)
- 6/16 改 loss 时没跑全流程验证，cls_loss 从 0.41 上升到 0.73 平台
- 修复：改回标准 focal 参数

### 2. mAP 0.0003 真相
- **不是评估 bug，是训练坍缩**
- 50 张图 805 个 det，99.5% 是 person，4 个 dining table，其他 78 类 0 预测
- raw cls argmax 99.75% background，0.25% foreground 中 98.42% 是 person
- **模型完全没学到 80 类，只学会 "person 是个东西"**

### 3. 自训坍缩 root cause：OHEM
- hard neg 多为"model 误以为 person 的 bg"
- OHEM 强化 person 预测 → 迭代 → model collapse 到 person
- 数据本身健康（80 张图覆盖 66/80 fg classes，person GT 占比 30.1% 正常）
- 修复需重训 6-8h+，且不一定成功（架构层 / 容量问题）

### 4. TTA 优化结果
- baseline (single 320): mAP@0.5 = **0.0488**
- TTA NMS-concat (3 尺度 + flip): mAP@0.5 = **0.0528-0.0530** (+8.2-8.6%)
- TTA WBF: mAP@0.5 = **0.0200** (-59%) ❌
- NMS IoU 不敏感 (0.3-0.6 都 0.053)
- 5 尺度无增益 (0.0528 vs 0.0530)

### 5. WBF 为什么反向
- WBF 内部"软合并"多尺度 box，把 320/384/448 三尺度同目标 box 平均成一个位置
- 平均后跟每个真实 box 都不严格对齐 → IoU < 0.5 → 漏匹配
- NMS-concat 不做平均，每个尺度 box 跟真实 box 严格对齐 → 保留为 TP

## 教训

1. **改 loss 函数必须跑全流程验证**：6/16 改 multi-class focal 没跑完 30 epoch，导致 4 天训练投入归零
2. **val_loss 健康 ≠ mAP 健康**：val_loss 0.41 看着好，但 mAP 0.0003 因为模型坍缩到只预测 person
3. **TTA 集成要选对 fusion**：NMS-concat 适合多尺度 WBF 不适合
4. **class balance 不是简单调参**：模型对 80 类投降是根本性问题，调 focal/OHEM 不一定修
5. **沉没成本**：6/13-6/17 五天投入但要承认失败转 OD API 路径
