## 已知问题 / 待优化（老板说 "后继再考虑"）

### 性能
- **9.96 FPS vs baseline 24.4 FPS** — encoder thread + bgr.copy() + udpsink 加了 ~10ms/帧
- **NPU worker 82ms** vs 之前 v0.16 报告的 37ms — taskset 绑 core 2 后慢了一倍，存疑
  - 可能原因：core 2 有别的进程 / NPU 本身共享 core 等
- **x264enc 软件编码** — 板端没硬编 H264，CPU 占大头
  - 可优化：调 x264enc threads=1 / speed-preset=ultrafast threads / bitrate 降
  - 或用 hardware vencoderdemo (需要 /dev/dma_heap/system + /dev/cedar_dev 666 权限)

### 稳定性
- **v24 不是 systemd service** — SSH 断开时可能被 kill
  - 修法：写 systemd unit `~/.config/systemd/user/od-pipeline.service`
- **板端 ssh 有时会卡** — v24 CPU 占用高峰时 sshd 排不上 CPU
  - 修法：降低 worker 优先级 / nice / taskset 留核给系统
- **PC 端 player 启动顺序敏感** — VLC/mpv 必须等板端先推包，否则可能显示"流已停止"
  - 修法：player 加 retry / 等 5 秒再连

### 检测
- **suitcase 误识别** — 纸箱被当 suitcase，置信度 0.41-0.54
  - 根因：yolov5s int8 模型对纸箱/suitcase 区分不强
  - 可优化：TTA / 重新训练 / 接受（demo 用够了）

### RTSP 选项
- **彻底不用 RTSP** — 当前用 udpsink + SDP 兜底
- **想要真 RTSP URL**（如 `rtsp://192.168.2.3:8554/od_stream`）需要：
  - 把 RTSP server 单独进程化（不是跟 encoder 共享）
  - 用 priority 调度保证 GLib MainLoop 迭代
  - 或用 gst-rtsp-server-1.0 的 UDP transport + rtspsink
