## 4. ⚠️ 本轮修的两处真问题 (不是拍板项, 但你会想看到)

### 4.1 ★★ ISS-184 (blocker, 已修待验): `.net` 导出器把 23 个 SoM 脚**静默丢弃**了 3 天

- ★**怎么发现的**: 我跑 `state/gen_netlist_pins.py` 时它**自检报红** —— 「.net 里 SoC 引脚合计只有 29 个 (应 >=50) ⇒ SoC 引脚丢失」。顺着查下去:
- ★**根因**: `state/gen_kicad_net.py` 的器件集合**只从 CSV 的 `ref` 列取**; 而 ★**J_SOM_P2 / J_SOM_P4 从不出现在 `ref` 列** (CSV 是"一行=一根连接"模型, 每行只写它经过的那个脚, `ref` 列写的是**另一个**器件) ⇒ 导出器判定"这不是器件" ⇒ ★**这 23 个脚被静默丢掉**。
- ★**实测口径 (修前 → 修后)**: `.net` 里 `J_SOM_P1`=10 / `J_SOM_P3`=19 / **`J_SOM_P2`=0 / `J_SOM_P4`=0** ⇒ 修后 **10 / 9 / 19 / 14**, 总 node **561 → 584**。
- ★**三个连带后果**: ①★**`HW/netlist_v1_pins.csv` (脚级表, PCB 工程师照着它接线) 从 11-03 00:50 起停更 3 天** ②★**`check_kicad_net.py` 原有 5 条判据全部 rc=0 通过** ⇒ ★**门禁形同虚设** (这已经是"同一个错逃过全部门禁"的又一次复现) ③ 原理图侧 (`gen_kicad_sch.py`) 同一套口径 ⇒ `.kicad_sch` 与投产包 `demo_mainboard-kicad.net` 里**同样缺 J_SOM_P2/P4**。
- ★**修法 (修在产生点, 不在产物上擦)**: ①导出器的器件集合改为 **ref 列 ∪ node 串里带引脚提示的 head** (排除网名与伪 ref) ②为这两个 node-only 器件补 `(comp ...)` 条目 (否则 .net 里有 node 却没有器件 ⇒ KiCad 导入时这 23 个脚无处安放) ③`gen_netlist_pins.py` 的"CSV 出处"判据同步认 node 串出处。
- ★**防复发 (新增第 6 条门禁)**: `check_kicad_net.py` 现在**按 CSV 逐个点名**「带引脚提示的脚 .net 里一个都不能缺」⇒ ★**拿修复前的坏 .net 实测 rc=1 报红, 拿修复后的 rc=0 通过** ⇒ 这类静默丢脚以后当场报红。
- ★**板没被动** (md5 `611b869e…` 修复前后完全一致) —— 板走的是另一条路 (直接正则解析 `J_SOM_(P\d) pin(\d+)`), 实测板上 4 组 BTB 共 400 焊盘、目标脚全部挂网 ⇒ **板↔网表等价性不受影响, 不需要重出板/Gerber**。
- ★**遗留 (我没做, 要你或下一轮定)**: 原理图链 (`gen_kicad_sch.py`) 的同一处口径 ⇒ **要么同样修, 要么明确写清"原理图侧不画 SoM 座"的口径** —— 我这轮只修了 `.net` + 脚级表这两条链。
