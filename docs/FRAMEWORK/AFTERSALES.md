# 售后支持与故障诊断 (1 台样机版) — H8-03 / ISS-036

> 生成 2026-10-25 | 原则: 1 台也要能自己修 —— **故障码 + 诊断步骤 + 返修流程**
> 正式售后体系 (客服/工单/备件) 推迟到量产; 这里只做"这一台坏了怎么办"

---

## 1. 三类故障, 三条路

| 类别 | 现象 | 处理 |
|---|---|---|
| **A 软件问题** | 画面卡/不显示/框乱/发烫/重启 | 客户可自行按 §2 步骤排查; 需固件则 USB 重刷 |
| **B 硬件问题** | 不开机/充不进电/某个模块无响应 | 返修 (§4) |
| **C 结构问题** | 松动/异响/夹皮肤/镜片晃 | 返修 (§4), 或打印件自己重打 (3D 打印件可自制!) |

---

## 2. 客户可自行排查的步骤 (写成用户能照做的语言)

**① 完全不工作**
```
1. 长按侧键 10 秒 → 关机
2. 换一根线 + 换一个充电头试 (最常见是线的问题)
3. 充电 10 分钟后再试
4. 仍不工作 → 报修, 附: 充电时指示灯状态
```

**② 充电时发烫 / 皮肤侧烫**
```
⚠ 这是安全项, 不是故障:
   充电时必须摘下眼镜 (充电 IC 耗散 0.8W, 贴皮肤会到 75°C 设计值)
   充电时软件会禁止 OD 推理 (若仍发热, 说明禁 OD 门禁失效 → 报修, 属安全问题)
```

**③ 画面卡 / 不显示 / 框位置乱**
```
1. 确认镜头没被遮 (镜框上沿的摄像头窗口)
2. 摘下擦一下镜头与波导 (指纹/油污在鱼眼镜头下影响很大)
3. 重启 (长按侧键 10 秒 → 再开机)
4. 仍异常 → 报修, 附一段 10 秒录屏
```

**④ 画面里有弯的框 / 框跟不住**
```
已知现象 (鱼眼 + 不裁剪的必然结果):
  图像是鱼眼形状, 所以框在图上看起来是弯的 —— 这是当前设计的预期行为, 不是 bug
  框的方位角已做反投影修正, 但视觉上仍会看到弯曲
  若要直的框 → 需要开启畸变校正 (LDC), 会吃掉一部分算力与延迟
```

**⑤ 用一会儿就发烫 / 掉电快**
```
1. 确认是不是在连续录制 (连续满载 1.22W → 皮肤 96°C 设计值, 必然发烫)
2. 待机/按需触发才是正常佩戴场景
3. 发热异常 → 报修 (属 NTC/温控问题)
```

## 3. 诊断信息采集 (报修必附, 省一轮来回)

| 项 | 怎么取 |
|---|---|
| 固件版本 | 开机后长按侧键 3 秒, 屏幕显示版本号 (或 `adb shell cat /etc/version`) |
| 故障码 | 崩溃时屏幕左上角显示的短码 (见 §5) |
| 复现步骤 | 什么动作下出现 (转头/走动/充电/开机瞬间) |
| 视频 | 10 秒录屏, 含边缘画面 (能看出畸变与框位置) |
| 温度 | 故障时皮肤侧是否发烫 + 大概多久开始热 |
| 充电状态 | 充电时是否发烫 (验证禁 OD 门禁) |
| 外观 | 外露金属件/充电口/Type-C 口照片 (ESD/进灰最常在这) |

## 4. 返修流程 (1 台版)

```
用户报修
  ↓ 项目总工 triage (软件 / 硬件 / 结构)
  ↓ 软件 → 给固件 + 重刷指导 → 用户自助 (30 分钟内解决)
  ↓ 硬件 → 寄回 → 项目总工 拆解定位 → 三个总工分别出结论 → 修 → 复测
  ↓ 结构 → 3D 打印件可自制重打 (打印包在仓库) → 不必寄回
  ↓ 复测用 QCP.md 的整机测试项全过 → 才算修好
```

**返修前后都要跑一次 `state/measurements.yaml` 的 10 项实测** —— 修完不看数等于没修。

## 5. 故障码表 (预留, 由 sw-lead 在 EVT 阶段补全)

| 码 | 含义 | 用户可做什么 |
|---|---|---|
| E-01 | camera timeout | 重启; 仍报 → 换线/换头试 |
| E-02 | NPU init fail | 报修 (固件或板级) |
| E-03 | thermal throttle (已降频) | 正常保护; 持续出现 → 报修 |
| E-04 | charging gate fault (禁 OD 失效) | ★**安全项** → 立即报修, 停止使用充电功能 |
| E-05 | DSI/显示链路无响应 | 重启; 仍报 → 报修 |
| E-06 | 存储空间不足 (日志写满) | 报修 (需清理/配额策略) |

> ⚠️ 故障码表在 EVT 阶段由软件总工补全; 补全前按现象排查。

## 6. 明确**不做**的 (1 台样机阶段)

- 不做客服/工单系统 (直接找项目总工)
- 不做备件库存 (1 台, 坏了重打/重买)
- 不做远程日志/云端分析 (不上无线)
- 不做用户反馈闭环 (内部样机, 反馈直接进 issue_log)
- 不做召回预案 / EOL 计划 (推迟到量产)

---

## 7. 一条纪律

> **故障必须登记进 `state/issue_log.yaml`**, 哪怕只是"用户觉得别扭"。
> 1 台样机的每个故障都是**免费的用户测试数据** —— 漏登记 = 白白丢掉一次真实工况暴露。
